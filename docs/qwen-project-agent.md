# Qwen 프로젝트 에이전트

실사용 한계: Beta 11 이후 `run_command`를 명시해도 추가 도구 선택 대신 읽기 전용 `sh`를 쓰려는 실패가 실제 14B 새 세션에서 재현됐습니다. 파일 편집 과제 통과를 모든 명령 실행의 안정성으로 일반화하지 않습니다. 이번 패치에서는 프롬프트·권한을 더 완화하지 않았으며 [실패 재현 보고](testing/beta12-followup.md)를 확인하세요.

Discord Qwen 명령은 `/agent`로 통합했다. 기존 클라우드 작업은 `/cloud-agent`, Gemini 직접 작업은 `/sub-agent`를 사용한다. 기존 웹 파일 비서의 제한된 초안 모드는 별도로 유지한다.

## 시작

Discord 최고 관리자 역할이 곧 소유자다(웹 계정 연결은 필수가 아니며, 연결하면 웹에서 등록한 작업 폴더 목록을 추가로 쓴다). 봇에 채널 관리·스레드 생성·첨부 권한을 허용한다. 자연어 채널 요청에는 Discord Developer Portal의 Message Content Intent도 필요하다. 사용할 컴퓨터의 Ollama에 Qwen 모델이 설치되어 있어야 한다.

```text
/agent setting default:14b
/agent project name:demo path:/절대/프로젝트/경로
/agent channel project:demo
/agent run prompt:프로젝트 구조를 조사해줘
/agent setting explicit_permission:false
/agent stop
```

`channel`의 프로젝트는 선택 사항이다. 생략하면 `~/ServerManagerProjects`를 홈으로 사용한다. 생성 채널은 같은 카테고리 아래 비공개 채널이며 요청자와 봇을 허용한다. Discord 관리자는 채널을 볼 수 있다. 초대된 다른 구성원은 결과를 볼 수 있지만 해당 채널 소유자의 도구 승인 권한은 얻지 않는다.

기본 Thinking은 켜져 있으며 `/agent run ... think:false` 또는 `/agent setting think:false`로 끈다. 모델 옵션은 생략할 수 있고 개인 기본값을 우선한다. 매 요청에는 Discord 표시 이름과 ID를 전달한다. 이름은 설명용이며 권한 확인은 ID로 한다. 대화는 채널별로 저장하되 입력 문맥과 도구 출력은 크기를 제한한다.

## 실행과 승인

모델 추론은 웹에서 선택한 Ollama 실행기 또는 관리 컴퓨터에서 수행한다. **파일·셸 도구는 관리 앱 컴퓨터의 OS 사용자 권한으로 실행한다.** 관리자/root 권한을 자동 획득하지 않는다. 실행기 추론에는 새 대화 프로토콜을 지원하는 이 버전의 실행기가 필요하다. 실행기의 로컬 LLM 허용 설정도 유지된다.

파일 목록·읽기·찾기·문자열 검색·쓰기·삭제, 임의 명령, 빌드·테스트·Git, 프로젝트 생성·HTTPS 복제를 제공한다. 매 도구를 실행하기 전에 독립된 새 Qwen 대화가 정확한 요청과 정규화된 경로를 검토한다. 검토 실패나 거부는 실행하지 않는다.

명시적 승인 모드가 기본이다. 자동 모드도 프로젝트 밖 경로나 범위를 증명할 수 없는 작업은 사용자 승인을 요구한다. 셸·Git 및 일반 스크립트 실행은 자동 모드에서도 승인이 필요하다. 예외로 프로젝트별 최초 동의를 받은 `./gradlew build/test/check/assemble`과 그 조합은 자동 모드에서 재사용한다. wrapper·빌드 설정·빌드 로직 지문이 바뀌거나 전역 init script가 있으면 다시 확인한다. 정상적인 Gradle 캐시와 의존성 다운로드도 최초 동의 범위에 포함한다. 배포·게시·셸 조합은 이 예외에 포함하지 않는다. 프로젝트 안의 낮은 위험 작업만 자동 진행한다. 심볼릭 링크·하드링크·경로 변경 검사와 실행 직전 재검사를 추가했지만 **OS 샌드박스나 악성 명령의 완전한 격리는 아니다.**

승인은 사용자·채널·요청·설정 버전에 묶인 일회용이며 만료된다. 권한 철회, 설정 변경, 중단 요청은 대기 중인 작업도 막는다. 이름이나 도구 출력에 쓰인 승인 문구는 권한이 아니다.

메인 모델은 여러 단계로 작업한다. 도구 실행 뒤 실제 결과와 종료 코드를 검토하고 필요하면 수정·재실행·검증을 이어간다. 요청당 최대 턴 수는 서버 설정·역할·개인 설정으로 정한다(기본 30, 상한 100, 아래 "친구 사용" 참고). 도구 실행이나 빌드 성공만으로 전체 요청의 완료를 주장하지 않는다. 중단·한도·막힌 작업은 남은 일을 보고한다.

답변은 마크다운 일반 메시지로, 턴 상태·승인·요약은 임베드로 표시한다. 실제 Thinking만 `‘…’`로 감싼다. 약 750ms 단위로 편집을 합치고 Discord 제한을 따라 대기한다. 긴 답변과 로그는 여러 메시지로 이어 보낸다. 중지 버튼은 요청자·현재 작업에 묶인다. 이미 끝난 파일 변경은 취소해도 되돌리지 않는다.

장시간 명령은 턴 스레드에 실행 중 출력을 전달한다. 일반 명령 기본 시간 제한은 15분, 최대 30분이며 출력은 1MiB까지다. 긴 결과는 별도 도구 없는 Qwen 세션이 의미를 요약하여 임베드와 다음 모델 턴에 전달한다. 짧은 결과는 종료 코드를 포함한 간략 결과를 사용한다. 요청 전체 JSON이나 도구 입력 JSON을 Discord에 첨부하지 않는다.

## 채널 문맥

```text
/agent context action:status
/agent context action:configure limit:2867
/agent context action:configure window:16384 output:2048 limit:8800
/agent context action:compact
/agent context action:reset
```

기본 실행 창은 8192, 입력 예산 3600, 출력 예약 4096, 압축 기준 2867이다. Beta 11부터 `window:16384`로 16K를 선택하고 `output`으로 512~4096 출력 예약을 정할 수 있다. 16K 입력 상한은 11000이며 시스템·계획·원문 결과도 포함한다. 16K는 메모리 압력·스왑 경고가 있으며 자동으로 기본값을 올리지 않는다. 구형 실행기의 16K/출력 설정 변경은 거부한다. 모델 최대치와 실행 창·압축 기준은 별개이며 최대치 조회 실패는 확인 불가로 표시한다. 자세한 구성과 실제 주입 지시문은 [문맥 구조](architecture/agent-context.md), [지시문 원문](architecture/agent-context-prompts.md)을 참고한다.

기준 도달 시 다음 모델 호출 전에 독립 세션으로 목표·완료 조건·결과·현재 단계·남은 일을 요약하고 최근 대화를 유지한다. 압축 실패 시 원본을 보존한다. 압축 뒤에도 입력이 너무 크면 기록을 유지하고 요청을 나누도록 안내한다. 모델 전환은 대화 기록을 초기화하지 않는다. 명시적 `루오노타르`·`루오`·봇 멘션은 판별 모델을 거치지 않고 호출하며 후속 질문 판별에는 최근 대화를 전달한다.

초기화는 대화와 요약만 지운다. 프로젝트 경로·등록 정보·승인 설정과 실제 파일·Discord 메시지는 유지한다. 실행 중 작업을 취소하고 이전 세대의 기록 저장을 차단한다.

턴 임베드 하단의 문맥은 추정치, 입력·출력은 Ollama가 완료 응답으로 제공한 실측치다. 보조 모델 호출 수와 수신한 토큰 합계를 별도 표시한다. 통계가 없는 응답은 메인 입력·출력에 미수신으로 표시하며 별도 Thinking 토큰 수는 추정하지 않는다.

## Discord 파일 도구

현재 프로젝트 채널의 최근 첨부 목록, 첨부 텍스트 범위 읽기, 프로젝트에 새 파일로 저장, 현재 채널로 로컬 파일 업로드를 지원한다. 메시지·첨부 ID를 사용하며 임의 URL이나 다른 채널은 도구 인자로 받지 않는다. 만료된 URL은 메시지를 새로 조회하여 갱신한다.

텍스트·코드는 UTF-8 1MiB 이하만 읽는다. 이미지·PDF 시각 해석과 첨부 자동 실행·압축 해제는 지원하지 않는다. 업로드는 Discord의 실제 한도와 도구 한도 10MiB 중 작은 값을 사용한다. 프로젝트 밖 경로는 명시적 승인을 요구하고 비밀로 보이는 파일명·내용은 차단한다. 이 검사는 모든 민감 정보를 식별하는 보장은 아니므로 승인할 경로를 확인해야 한다.

## 친구 사용 · 모델 · 턴 제한

최고 관리자 역할만 쓰던 `/agent`를 역할 단위로 열 수 있다. 최고 관리자만 아래 명령을 쓴다. 설정은 `security/agent/agent-access.json`에 따로 저장하므로 이전 베타로 되돌려도 기존 파일을 읽는 데 영향이 없다.

```text
/agent access role-set role:@친구 models:14b tier:read max_turns:15
/agent access role-set role:@동료 models:both tier:edit max_turns:40 projects:demo
/agent access project-add name:demo path:/절대/프로젝트/경로
/agent access limits cap:60 default:30
/agent access list
/agent access role-remove role:@친구
```

- 모델: 역할마다 14b, 30b, 둘 다 중에서 고른다. 여러 역할을 가진 사람은 합집합이다. 허용되지 않은 모델을 직접 고르면 거부하고, 저장된 개인 기본값이 허용 밖이면 허용된 모델로 내려간다.
- 권한 단계: `read`는 읽기 전용(파일 목록·읽기·검색·`sh`·첨부 읽기), `edit`는 여기에 승인 후 부분 수정(`edit_file`)과 새 작은 파일 쓰기(`write_file`)를 더한다. 두 단계 모두 임의 명령·빌드·테스트·삭제·Git 쓰기·프로젝트 생성·업로드는 제안조차 못 하고, 프로젝트 폴더 밖 경로와 `.env`·키·자격 증명 파일은 거부한다. 수정은 항상 요청자의 승인이 필요하며 친구는 이 승인을 끌 수 없다.
- 작업 폴더: 친구는 `~/ServerManagerProjects/friends/<서버>-<사용자>`(개인)이거나, 역할에 연결된 공유 프로젝트만 쓴다. 채널은 친구당 3개까지다.
- 권한은 매번 실시간 Discord 역할로 다시 계산한다. 역할을 회수하면 진행 중인 작업도 다음 확인(3초 이내)에서 중단한다.
- 턴 수: `min(요청의 turns, 개인 설정, 서버 기본)`을 역할 상한과 서버 상한으로 다시 제한한다. 개인은 `/agent turns count:20` 또는 `/agent run turns:20`으로 줄이거나 상한 안에서 늘린다. 상한을 낮추면 저장된 역할·개인 값도 같이 낮아진다. 진행 표시는 `턴 3/30`처럼 나온다.
- 사용 가능 여부는 역할이 정하며, 같은 시각에 Qwen 추론은 한 번에 하나만 실행하므로 여러 명이 요청하면 순서를 기다린다.

## Qwen 30B 하네스

작은 모델이 안정적으로 부분 수정·검토를 하도록 도구와 프롬프트를 좁혔다.

- `sh {command}`: 실제 셸이 아닌 읽기 전용 명령줄 해석기다. `pwd ls cat head tail wc grep find sed(-n 'A,Bp') sort uniq echo git(status diff log show branch ls-files rev-parse shortlog)`와 `&&` `||` `;` `|`를 지원한다. 리다이렉션·`$()`·백틱·변수·`&`·서브셸은 실행 전에 거부한다. 모든 경로는 프로젝트 홈 안으로 해석하고 심볼릭 링크는 따라가지 않으며 `.git`·`node_modules`·`build` 같은 폴더와 비밀 파일은 재귀 검색에서 제외한다. 출력 48,000자·시간 20초 제한, 정규식은 시간 제한 안에서만 평가한다. git은 읽기 하위 명령과 허용 목록의 옵션만 받고 `--output`·`--no-index`·`-C`·`..` 경로를 거부하며 외부 diff·textconv를 끈다.
- `edit_file`: `{path,find,replace}`(정확히 한 곳과 일치해야 함, `replace_all` 가능), `{path,start_line,end_line,replace}`, `{path,insert_after_line,replace}`. 일치가 없거나 여러 곳이면 위치 힌트와 함께 실패하고 파일은 바뀌지 않는다. 승인 화면에는 제거·추가될 줄이 그대로 나오며, 승인 뒤 파일이 바뀌었으면 적용하지 않는다. CRLF 파일의 줄바꿈은 유지한다.
- 읽기 전용 sandbox 도구(`sh`, 친구 단계의 읽기 도구)는 백엔드가 직접 범위를 검증하므로 모델 위험 검토와 결과 요약을 건너뛴다. 결과는 앞뒤만 자르고 원문을 그대로 모델에게 돌려줘서 `edit_file`의 `find`에 정확한 줄을 복사할 수 있다. 추론 호출이 턴당 3~4회에서 1회로 줄어든다.
- "홈 디렉토리 파일들을 리스트업해보겠습니다."처럼 행동을 예고만 하고 도구 호출 없이 끝내는 응답은 최종 답변으로 인정하지 않는다. 턴이 남아 있으면 도구 호출을 다시 요청하며(요청당 최대 2회), 결과나 실제 막힌 사유를 담은 보고는 그대로 종료한다.
- 프롬프트는 "찾기(grep) → 구간 읽기(sed -n) → 작게 수정(edit_file) → 확인(git diff)" 순서를 고정하고, 남은 턴 수를 알려서 마지막 턴 전에 보고하게 한다.

## 검증 범위

Mac에서 관련 자동 기능 테스트 32개, 프런트엔드 빌드와 JAR 빌드를 확인했다. 실제 Qwen 14B로 임시 파일 수정·독립 검토·승인 흐름과 Thinking 스트림을 각각 확인했다. 실제 Discord 상호작용, 30B 품질·성능, 다른 운영체제는 검증하지 않았다. 전체 테스트는 사용자 요청으로 생략했다. Aider는 설치하거나 사용하지 않았으며 자체 하네스를 확장했다. Gmail·Calendar는 기존 연결 기능을 유지하며 새 임의 명령 도구의 전용 통합으로 추가하지 않았다.

이번 워크플로 변경 검증은 별도로 `docs/dev-notes/feat-qwen-workflow.md`에 기록한다. TCP 접속 중 실제 앱 교체 보장은 이번 릴리즈에서 추가하지 않는다. 기존 앱 경유 TCP가 제어 프로세스에 남는 경로는 기존 업데이트 대기를 유지하며 다음 업데이트 대상으로 둔다.

## 도구 없는 종료와 대화 대상 판별 보강

모델이 실제 도구 없이 “읽어볼게요/찾아볼게요”처럼 실행을 예고하면 완료로 처리하지 않고 최대 두 번 보정 요청한다. 계속 도구가 없으면 미실행으로 중단을 보고한다. 백엔드가 임의 명령을 만들어 실행하거나 승인을 우회하지 않는다. 설명·대화 기억 질문은 도구 없이 직접 답할 수 있다. 자연어 검사는 모든 허위 완료 표현을 완벽히 검출하는 보장은 아니다.

`read_file`, `read_attachment`, 파일 목록·검색 등 읽기 도구는 기본적으로 원문을 전달하고 독립 요약 모델을 호출하지 않는다. 모델이 도구 인자 `summarize:true`를 명시한 경우에만 기존 요약 경로를 사용한다. 입력 예산을 초과한 원문은 앞부분의 정확한 범위와 이어 읽을 위치를 표시하며 의미를 재작성하지 않는다. 오래된 대화의 자동 문맥 압축은 별도 정책으로 유지된다.

대화 대상 확인을 위해 코딩용 Qwen을 먼저 호출하던 경로를 제거했다. 최근 15분, 채널별 최대 64개 발언의 참여자 ID·이름·짧은 발언·답장 관계를 별도 비공개 파일에 저장한다. 시작 후 첫 소유자 메시지 때 최근 25개 메시지도 조회한다. 봇은 사람 수에서 제외하며 다른 사람의 참여가 도구 실행 권한을 부여하지 않는다. 공개 채널에서는 수집하지 않는다.

봇 멘션·`루오,`·`루오야`·`루오노타르,`·봇 답장은 직접 호출이다. 다른 사람 멘션·답장은 사람 대화로 취급한다. 혼자 참여한 채널의 후속 대화는 즉시 처리하고, 여러 사람이 참여해 대상이 불명확하면 명시적 호출을 안내한다. 요청 인식 완료 상태와 `/agent context action:status`에 관측된 참여자 수를 표시한다. 의미가 애매한 대화를 완벽하게 분류한다고 주장하지 않는다.

실모델 검증에서 나온 추가 보강: 명시적인 최상위 `tool_name`+`arguments` 형태도 정규 도구 요청으로 변환하되 같은 경로 검토·승인 절차를 거친다. `tool` 누락·모순된 형식은 완료 답변으로 받아들이지 않는다. 도구 내역을 잘못된 출력 스키마처럼 모방하지 않도록 이전 실행 내역 표현도 정리했다.

위험 검토는 Ollama의 [구조화 출력](https://docs.ollama.com/capabilities/structured-outputs)으로 action/risk/projectScope/reason을 요구하고 temperature=0을 사용한다. 형식 또는 정책 검토 실패 시 차단하는 동작은 유지한다. 이 보강을 원격 추론에도 적용하려면 관리 앱과 추론 실행기를 함께 업데이트한다.

사용자가 저장 후 재조회를 명시한 파일 작업은 해당 write_file 대상의 read_file 결과가 오기 전에는 완료로 처리하지 않는다. 대화 기록만으로 답하고 파일 도구를 쓰지 말라는 요청은 별도로 구분한다. 실제 파일 변경은 중단해도 자동으로 되돌리지 않는다.

## 실시간 개입 · 긴 명령 출력 (0.7.0-beta.9)

- **실시간 개입**: 에이전트가 작업하는 동안 채널 소유자가 같은 채널에 보낸 메시지는 "작업 중입니다" 거절 대신 진행 중인 작업에 반영된다. 메시지에는 🧭 반응이 붙고, 다음 모델 호출 전에 `mid_task_instruction`으로 대화에 들어가며 최신 지시가 이전 목표를 갱신한다. 모델이 이미 최종 답변을 만들던 중에 도착했고 턴이 남아 있으면 끝내지 않고 이어서 반영한다. 대기 개입은 최대 5개, 개당 2,000자까지다. 개입은 승인이나 권한이 아니다: 대기 중인 도구 승인과 규칙은 그대로이며, 다른 사람의 메시지는 개입으로 받지 않는다. 대화 대상 판정이 `HUMAN`이면 무시하고 `UNCERTAIN`이면 지금처럼 되묻는다.
- **요구사항 장부**: 40자 이상 요청은 시작할 때 최대 6개 항목으로 나뉘어(모델 추출, 실패하면 줄/문장 분리) 매 호출에 고정된다. 모델은 응답 JSON의 `requirements:[{id,status:"done"|"blocked",evidence}]`로 보고하고, 백엔드가 검증한다: 근거는 8자 이상, 수정·생성·실행 같은 행동 항목은 변경 도구가 성공한 뒤에만 닫힌다. 열린 항목이 있으면 `tool:null` 응답을 받아주지 않고 최대 3번 다시 요청한다(`status`가 `clarify`/`blocked`면 끝낼 수 있다). 최종 보고와 턴 한도 보고에 `요구사항 점검` 목록이 붙는다. 작업 중 개입 메시지는 새 항목으로 추가된다.
- **작업 노트**: 요청이 끝나면 직전 요청·결과·바뀐 파일·미완료 항목을 `project-agent-notes.json`에 채널별로 저장하고, 다음 요청에 `previous_task_notes`로 고정 전달한다. 짧은 후속 요청("계속해줘")은 미완료 항목을 장부로 이어받는다. `/agent context reset`이 노트를 지운다.
- **검색**: `sh`의 `rg`와 `search {pattern,path?,glob?,type?,context?,max?,ignore_case?,fixed?}` 도구는 서버 안에서 구현된 ripgrep 호환 검색이다. 재귀·줄 번호가 기본이고 `--files`, `-g`, `-t`, `-e`, `-A/-B/-C`, `-m`, `-i -l -c -v -F -w`만 지원하며 `--hidden`, `--no-ignore`, 제외 glob, `--pre` 등은 거부한다.
- **긴 명령 출력**: `run_command`·`build`·`test` 출력이 2,400자를 넘으면 원문을 채널별로 보관하고(24시간, 채널당 20개) 앞 1,000자와 `out-…` ID만 모델에 준다. 모델 요약은 거치지 않는다. 모델은 `read_result {id,start_line?,lines?}`로 구간을 읽는다(한 번에 약 3,600자). `read_result`는 모든 권한 단계에서 읽기 전용 sandbox 도구이고 다른 채널의 결과는 읽을 수 없다.

## Beta 11 작업 신뢰성

- 사용자 원문·작업 단계는 대화 요약과 별도로 보존한다. 초기화는 대화·노트·계획을 지우며 이전 작업이 다시 저장하지 못한다.
- 파일별 실제 결과 ID와 현재 파일 지문으로 완료를 검증한다. a 생성만으로 미생성 b를 완료하지 못한다.
- 기존 프로젝트 파일은 `read_file`로 먼저 읽고 `edit_file`로 필요한 부분을 바꾸며, 동일 요청의 무진전 반복을 막는다. 병합 결과에 원문이 보존되기 전 원본 삭제를 거부한다.
- 긴 조회 원문은 `read_result`로 이어 읽는다. `summarize:true` 없는 조회는 모델 요약을 하지 않는다.

### 공식 Ollama 도구 호출 (Beta 11 작업 브랜치)

Discord 실행 모델은 공식 `tools` 등록과 `message.tool_calls`를 사용한다. `select_tools`로 추가 기능을 고르고 `report_task`로 실제 근거를 보고한다. 텍스트에 도구 JSON을 적어도 실행되지 않는다. 경로·역할·독립 위험 검토·사람 승인·재조회 검사는 전환 후에도 백엔드가 담당한다. 새 관리 앱과 추론 실행기를 함께 업데이트해야 하며, 구형 실행기에 공식 호출을 조용히 JSON으로 우회하지 않는다. 구성·영구 보존의 한계는 [문맥 구조](architecture/agent-context.md)에 정리했다.

## Pi 엔진으로 전환

이번 버전부터 `/agent`는 공식 Pi SDK를 기본 엔진으로 사용한다. 명령어와 모델 설정은 그대로이며 최초 요청에서 검증된 Node·Pi를 private profile에 자동 준비한다. 관리 앱과 추론 실행기를 함께 업데이트해야 한다. 엔진·설치·권한·세션 이관·압축과 실제 검증 범위는 [Pi 엔진 구조](architecture/pi-agent-runtime.md)를 참고한다. 이 문서의 이전 custom actor JSON/선택 도구/자체 압축 설명은 과거 버전의 동작이다. 임의 셸은 관리 앱의 OS 사용자 권한이며 OS 샌드박스가 아니다.
