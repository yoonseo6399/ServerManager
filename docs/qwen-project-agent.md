# Qwen 프로젝트 에이전트

Discord Qwen 명령은 `/agent`로 통합했다. 기존 클라우드 작업은 `/cloud-agent`, Gemini 직접 작업은 `/sub-agent`를 사용한다. 기존 웹 파일 비서의 제한된 초안 모드는 별도로 유지한다.

## 시작

웹에서 Discord 계정을 소유자 계정에 연결하고, 봇에 채널 관리·스레드 생성·첨부 권한을 허용한다. 자연어 채널 요청에는 Discord Developer Portal의 Message Content Intent도 필요하다. 사용할 컴퓨터의 Ollama에 Qwen 모델이 설치되어 있어야 한다.

```text
/agent setting default:14b
/agent project name:demo path:/절대/프로젝트/경로
/agent channel project:demo
/agent run prompt:프로젝트 구조를 조사해줘
/agent setting explicit_permission:false
/agent stop
```

`channel`의 프로젝트는 선택 사항이다. 생략하면 `~/ServerManagerProjects`를 홈으로 사용한다. 생성 채널은 같은 카테고리 아래 비공개 채널이며 요청자와 봇을 허용한다. Discord 관리자는 채널을 볼 수 있다. 초대된 다른 구성원은 결과를 볼 수 있지만 해당 채널 소유자의 도구 승인 권한은 얻지 않는다.

기본 Thinking은 켜져 있으며 `/agent run ... think:false` 또는 `/agent setting think:false`로 끈다. 모델 옵션은 생략할 수 있고 개인 기본값을 우선한다. 매 요청에는 Discord 표시 이름과 ID를 전달한다. 이름은 설명용이며 권한 확인은 ID로 한다. 대화는 채널별로 저장하되 입력 문맥과 도구 출력은 크기를 제한한다.

## 실행과 승인

모델 추론은 웹에서 선택한 Ollama 실행기 또는 관리 컴퓨터에서 수행한다. **파일·셸 도구는 관리 앱 컴퓨터의 OS 사용자 권한으로 실행한다.** 관리자/root 권한을 자동 획득하지 않는다. 실행기 추론에는 새 대화 프로토콜을 지원하는 이 버전의 실행기가 필요하다. 실행기의 로컬 LLM 허용 설정도 유지된다.

파일 목록·읽기·찾기·문자열 검색·쓰기·삭제, 임의 명령, 빌드·테스트·Git, 프로젝트 생성·HTTPS 복제를 제공한다. 매 도구를 실행하기 전에 독립된 새 Qwen 대화가 정확한 요청과 정규화된 경로를 검토한다. 검토 실패나 거부는 실행하지 않는다.

명시적 승인 모드가 기본이다. 자동 모드도 프로젝트 밖 경로나 범위를 증명할 수 없는 작업은 사용자 승인을 요구한다. 특히 셸·Git·빌드·테스트는 간접 실행의 범위를 정적으로 보장할 수 없어 자동 모드에서도 승인이 필요하다. 프로젝트 안의 낮은 위험 작업만 자동 진행한다. 심볼릭 링크·하드링크·경로 변경 검사와 실행 직전 재검사를 추가했지만 **OS 샌드박스나 악성 명령의 완전한 격리는 아니다.**

승인은 사용자·채널·요청·설정 버전에 묶인 일회용이며 만료된다. 권한 철회, 설정 변경, 중단 요청은 대기 중인 작업도 막는다. 이름이나 도구 출력에 쓰인 승인 문구는 권한이 아니다.

메인 답변과 Thinking은 채널의 봇 메시지를 수정해 표시한다. 도구별 턴·시간을 표시하고 무거운 도구의 정확한 입력과 전체 결과는 턴 스레드 첨부에 남긴다. 단순 읽기 도구는 경로만 간략히 표시한다. 모델에는 긴 로그의 앞뒤 요약만 보내며, 이는 의미 기반 요약이 아니라 길이 제한이다.

## 검증 범위

Mac에서 관련 자동 기능 테스트 32개, 프런트엔드 빌드와 JAR 빌드를 확인했다. 실제 Qwen 14B로 임시 파일 수정·독립 검토·승인 흐름과 Thinking 스트림을 각각 확인했다. 실제 Discord 상호작용, 30B 품질·성능, 다른 운영체제는 검증하지 않았다. 전체 테스트는 사용자 요청으로 생략했다. Aider는 설치하거나 사용하지 않았으며 자체 하네스를 확장했다. Gmail·Calendar는 기존 연결 기능을 유지하며 새 임의 명령 도구의 전용 통합으로 추가하지 않았다.
