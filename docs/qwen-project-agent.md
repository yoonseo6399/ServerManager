# Qwen 프로젝트 에이전트

Discord Qwen 명령은 `/agent`로 통합했다. 기존 클라우드 작업은 `/cloud-agent`, Gemini 직접 작업은 `/sub-agent`를 사용한다. 기존 웹 파일 비서의 제한된 초안 모드는 별도로 유지한다.

## 시작

웹에서 Discord 계정을 소유자 계정에 연결하고, 봇에 채널 관리·스레드 생성·첨부 권한을 허용한다. 자연어 채널 요청에는 Discord Developer Portal의 Message Content Intent도 필요하다. 사용할 컴퓨터의 Ollama에 Qwen 모델이 설치되어 있어야 한다.

```text
/agent setting default:14b
/agent project name:demo path:/절대/프로젝트/경로
/agent channel project:demo
/agent run prompt:프로젝트 구조를 조사해줘
/agent setting explicit_permission:false
/agent stop
```

`channel`의 프로젝트는 선택 사항이다. 생략하면 `~/ServerManagerProjects`를 홈으로 사용한다. 생성 채널은 같은 카테고리 아래 비공개 채널이며 요청자와 봇을 허용한다. Discord 관리자는 채널을 볼 수 있다. 초대된 다른 구성원은 결과를 볼 수 있지만 해당 채널 소유자의 도구 승인 권한은 얻지 않는다.

기본 Thinking은 켜져 있으며 `/agent run ... think:false` 또는 `/agent setting think:false`로 끈다. 모델 옵션은 생략할 수 있고 개인 기본값을 우선한다. 매 요청에는 Discord 표시 이름과 ID를 전달한다. 이름은 설명용이며 권한 확인은 ID로 한다. 대화는 채널별로 저장하되 입력 문맥과 도구 출력은 크기를 제한한다.

## 실행과 승인

모델 추론은 웹에서 선택한 Ollama 실행기 또는 관리 컴퓨터에서 수행한다. **파일·셸 도구는 관리 앱 컴퓨터의 OS 사용자 권한으로 실행한다.** 관리자/root 권한을 자동 획득하지 않는다. 실행기 추론에는 새 대화 프로토콜을 지원하는 이 버전의 실행기가 필요하다. 실행기의 로컬 LLM 허용 설정도 유지된다.

파일 목록·읽기·찾기·문자열 검색·쓰기·삭제, 임의 명령, 빌드·테스트·Git, 프로젝트 생성·HTTPS 복제를 제공한다. 매 도구를 실행하기 전에 독립된 새 Qwen 대화가 정확한 요청과 정규화된 경로를 검토한다. 검토 실패나 거부는 실행하지 않는다.

명시적 승인 모드가 기본이다. 자동 모드도 프로젝트 밖 경로나 범위를 증명할 수 없는 작업은 사용자 승인을 요구한다. 셸·Git 및 일반 스크립트 실행은 자동 모드에서도 승인이 필요하다. 예외로 프로젝트별 최초 동의를 받은 `./gradlew build/test/check/assemble`과 그 조합은 자동 모드에서 재사용한다. wrapper·빌드 설정·빌드 로직 지문이 바뀌거나 전역 init script가 있으면 다시 확인한다. 정상적인 Gradle 캐시와 의존성 다운로드도 최초 동의 범위에 포함한다. 배포·게시·셸 조합은 이 예외에 포함하지 않는다. 프로젝트 안의 낮은 위험 작업만 자동 진행한다. 심볼릭 링크·하드링크·경로 변경 검사와 실행 직전 재검사를 추가했지만 **OS 샌드박스나 악성 명령의 완전한 격리는 아니다.**

승인은 사용자·채널·요청·설정 버전에 묶인 일회용이며 만료된다. 권한 철회, 설정 변경, 중단 요청은 대기 중인 작업도 막는다. 이름이나 도구 출력에 쓰인 승인 문구는 권한이 아니다.

메인 모델은 여러 단계로 작업한다. 도구 실행 뒤 실제 결과와 종료 코드를 검토하고 필요하면 수정·재실행·검증을 이어간다. 최대 12턴이며 도구 실행이나 빌드 성공만으로 전체 요청의 완료를 주장하지 않는다. 중단·한도·막힌 작업은 남은 일을 보고한다.

답변은 마크다운 일반 메시지로, 턴 상태·승인·요약은 임베드로 표시한다. 실제 Thinking만 `‘…’`로 감싼다. 약 750ms 단위로 편집을 합치고 Discord 제한을 따라 대기한다. 긴 답변과 로그는 여러 메시지로 이어 보낸다. 중지 버튼은 요청자·현재 작업에 묶인다. 이미 끝난 파일 변경은 취소해도 되돌리지 않는다.

장시간 명령은 턴 스레드에 실행 중 출력을 전달한다. 일반 명령 기본 시간 제한은 15분, 최대 30분이며 출력은 1MiB까지다. 긴 결과는 별도 도구 없는 Qwen 세션이 의미를 요약하여 임베드와 다음 모델 턴에 전달한다. 짧은 결과는 종료 코드를 포함한 간략 결과를 사용한다. 요청 전체 JSON이나 도구 입력 JSON을 Discord에 첨부하지 않는다.

## 채널 문맥

```text
/agent context action:status
/agent context action:configure limit:2867
/agent context action:compact
/agent context action:reset
```

압축 기준은 채널별 1024~3584 입력 토큰 추정치이며 기본 2867이다. 실행 창 8192에서 출력 4096과 안전 여유를 확보한다. 모델이 지원하는 최대치와 현재 실행 창은 별개다. 최대치는 선택된 실행 위치의 Ollama에서 확인하고 조회 실패는 확인 불가로 표시한다. 기준 변경은 실행 창 크기를 확대하지 않는다.

기준 도달 시 다음 모델 호출 전에 독립 세션으로 목표·완료 조건·결과·현재 단계·남은 일을 요약하고 최근 대화를 유지한다. 압축 실패 시 원본을 보존한다. 압축 뒤에도 입력이 너무 크면 기록을 유지하고 요청을 나누도록 안내한다. 모델 전환은 대화 기록을 초기화하지 않는다. 명시적 `루오노타르`·`루오`·봇 멘션은 판별 모델을 거치지 않고 호출하며 후속 질문 판별에는 최근 대화를 전달한다.

초기화는 대화와 요약만 지운다. 프로젝트 경로·등록 정보·승인 설정과 실제 파일·Discord 메시지는 유지한다. 실행 중 작업을 취소하고 이전 세대의 기록 저장을 차단한다.

턴 임베드 하단의 문맥은 추정치, 입력·출력은 Ollama가 완료 응답으로 제공한 실측치다. 보조 모델 호출 수와 수신한 토큰 합계를 별도 표시한다. 통계가 없는 응답은 메인 입력·출력에 미수신으로 표시하며 별도 Thinking 토큰 수는 추정하지 않는다.

## Discord 파일 도구

현재 프로젝트 채널의 최근 첨부 목록, 첨부 텍스트 범위 읽기, 프로젝트에 새 파일로 저장, 현재 채널로 로컬 파일 업로드를 지원한다. 메시지·첨부 ID를 사용하며 임의 URL이나 다른 채널은 도구 인자로 받지 않는다. 만료된 URL은 메시지를 새로 조회하여 갱신한다.

텍스트·코드는 UTF-8 1MiB 이하만 읽는다. 이미지·PDF 시각 해석과 첨부 자동 실행·압축 해제는 지원하지 않는다. 업로드는 Discord의 실제 한도와 도구 한도 10MiB 중 작은 값을 사용한다. 프로젝트 밖 경로는 명시적 승인을 요구하고 비밀로 보이는 파일명·내용은 차단한다. 이 검사는 모든 민감 정보를 식별하는 보장은 아니므로 승인할 경로를 확인해야 한다.

## 검증 범위

Mac에서 관련 자동 기능 테스트 32개, 프런트엔드 빌드와 JAR 빌드를 확인했다. 실제 Qwen 14B로 임시 파일 수정·독립 검토·승인 흐름과 Thinking 스트림을 각각 확인했다. 실제 Discord 상호작용, 30B 품질·성능, 다른 운영체제는 검증하지 않았다. 전체 테스트는 사용자 요청으로 생략했다. Aider는 설치하거나 사용하지 않았으며 자체 하네스를 확장했다. Gmail·Calendar는 기존 연결 기능을 유지하며 새 임의 명령 도구의 전용 통합으로 추가하지 않았다.

이번 워크플로 변경 검증은 별도로 `docs/dev-notes/feat-qwen-workflow.md`에 기록한다. TCP 접속 중 실제 앱 교체 보장은 이번 릴리즈에서 추가하지 않는다. 기존 앱 경유 TCP가 제어 프로세스에 남는 경로는 기존 업데이트 대기를 유지하며 다음 업데이트 대상으로 둔다.

## 도구 없는 종료와 대화 대상 판별 보강

모델이 실제 도구 없이 “읽어볼게요/찾아볼게요”처럼 실행을 예고하면 완료로 처리하지 않고 최대 두 번 보정 요청한다. 계속 도구가 없으면 미실행으로 중단을 보고한다. 백엔드가 임의 명령을 만들어 실행하거나 승인을 우회하지 않는다. 설명·대화 기억 질문은 도구 없이 직접 답할 수 있다. 자연어 검사는 모든 허위 완료 표현을 완벽히 검출하는 보장은 아니다.

`read_file`, `read_attachment`, 파일 목록·검색 등 읽기 도구는 기본적으로 원문을 전달하고 독립 요약 모델을 호출하지 않는다. 모델이 도구 인자 `summarize:true`를 명시한 경우에만 기존 요약 경로를 사용한다. 입력 예산을 초과한 원문은 앞부분의 정확한 범위와 이어 읽을 위치를 표시하며 의미를 재작성하지 않는다. 오래된 대화의 자동 문맥 압축은 별도 정책으로 유지된다.

대화 대상 확인을 위해 코딩용 Qwen을 먼저 호출하던 경로를 제거했다. 최근 15분, 채널별 최대 64개 발언의 참여자 ID·이름·짧은 발언·답장 관계를 별도 비공개 파일에 저장한다. 시작 후 첫 소유자 메시지 때 최근 25개 메시지도 조회한다. 봇은 사람 수에서 제외하며 다른 사람의 참여가 도구 실행 권한을 부여하지 않는다. 공개 채널에서는 수집하지 않는다.

봇 멘션·`루오,`·`루오야`·`루오노타르,`·봇 답장은 직접 호출이다. 다른 사람 멘션·답장은 사람 대화로 취급한다. 혼자 참여한 채널의 후속 대화는 즉시 처리하고, 여러 사람이 참여해 대상이 불명확하면 명시적 호출을 안내한다. 요청 인식 완료 상태와 `/agent context action:status`에 관측된 참여자 수를 표시한다. 의미가 애매한 대화를 완벽하게 분류한다고 주장하지 않는다.

실모델 검증에서 나온 추가 보강: 명시적인 최상위 `tool_name`+`arguments` 형태도 정규 도구 요청으로 변환하되 같은 경로 검토·승인 절차를 거친다. `tool` 누락·모순된 형식은 완료 답변으로 받아들이지 않는다. 도구 내역을 잘못된 출력 스키마처럼 모방하지 않도록 이전 실행 내역 표현도 정리했다.

위험 검토는 Ollama의 [구조화 출력](https://docs.ollama.com/capabilities/structured-outputs)으로 action/risk/projectScope/reason을 요구하고 temperature=0을 사용한다. 형식 또는 정책 검토 실패 시 차단하는 동작은 유지한다. 이 보강을 원격 추론에도 적용하려면 관리 앱과 추론 실행기를 함께 업데이트한다.

사용자가 저장 후 재조회를 명시한 파일 작업은 해당 write_file 대상의 read_file 결과가 오기 전에는 완료로 처리하지 않는다. 대화 기록만으로 답하고 파일 도구를 쓰지 말라는 요청은 별도로 구분한다. 실제 파일 변경은 중단해도 자동으로 되돌리지 않는다.
