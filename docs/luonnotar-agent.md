# 루오노타르 메인·서브에이전트 (실험용)

> 0.7.0 베타에서 `/agent`는 [Qwen 프로젝트 에이전트](qwen-project-agent.md)입니다. 아래 클라우드 예시의 `/agent`는 `/cloud-agent`로 사용하세요. 아래의 `/local-llm`은 `/agent run`과 프로젝트 채널로 대체되었으며, 단발 대화·도구 없음·Thinking 기본 false 설명은 새 모드에 적용되지 않습니다.

`/agent`는 OpenAI Responses API를 사용하는 GPT 메인 작업이다. 메인은 파일을 조사하고 직접 수정하거나 Gemini 서브 작업을 분배한다. `/sub-agent`는 기존 Gemini 작업을 직접 실행하는 명령이다. 기존 Discord 토큰과 최고 관리자 역할 설정을 사용한다.

## 설정과 사용

웹 **계정과 보안 → GPT 메인 에이전트**에서 OpenAI API 키, 기본 모델, 추론 강도, 병렬 수, 호출 한도와 토큰 예산을 설정한다. 기본값은 모델 `gpt-6.1-sol`, 추론 `medium`, 병렬 3개, GPT 호출 12회, 누적 GPT 토큰 120000이다. 토큰 예산은 응답 후 집계하므로 마지막 한 응답만큼 초과할 수 있다. Gemini 토큰과 요청 한도는 별도 관리한다. 키는 암호화 저장하며 조회 응답에 반환하지 않는다. 변경에는 소유자 권한, 최근 패스키 인증과 CSRF 검증이 필요하다. 키 입력을 비워 두면 기존 키를 유지한다. `OPENAI_API_KEY` 환경변수가 저장한 키보다 우선한다.

```text
/agent task:유튜브 검색과 재생 기능의 구현 계획과 파일별 작업 범위를 정리해
/agent task:명시한 완료 조건에 맞춰 기능을 구현하고 테스트해 edit:true build-files:true parallel:3 model:gpt-6.1-sol reasoning:medium
/sub-agent task:파일을 요약하고 다음 개선사항을 제안해 files:docs/DEVELOPMENT.md
/sub-agent task:중복 검사를 공통 함수로 추출해 files:src/main/kotlin/example/A.kt,src/test/kotlin/example/ATest.kt edit:true
```

`edit` 기본값은 false다. `build-files:true`는 Gradle·package.json 등의 빌드 설정 수정을 추가로 허용한다. `/agent`의 `files`를 생략하면 허용된 프로젝트 코드 전체를 다룬다. 지정하면 메인과 모든 서브 작업을 그 파일 범위에 제한한다. `/sub-agent`의 `files`는 필수다. 쉼표로 최대 30개 파일을 지정하며 새 파일 경로도 가능하다. 선행 `/docs/...`는 프로젝트 상대 경로로 처리한다.

`model`, `reasoning`, `parallel` 옵션은 해당 GPT 작업의 웹 기본값을 덮어쓴다. `auto` 추론은 API 기본값을 사용한다. 모델 ID와 추론 강도 조합은 해당 모델이 지원해야 한다. 모델 이름 선택만으로 계정의 접근 권한이 생기지는 않는다. ChatGPT 구독과 API 사용료는 별도다.

GPT 추론은 모델/API가 제공한다. 작업 분배·도구 실행·병합·재시도는 이 프로그램이 구현한다. API가 반환하는 추론 요약만 표시하며 내부 사고 원문은 제공하지 않는다. `store:false` 요청은 암호화된 추론 항목을 후속 요청에 그대로 보존한다.

공식 문서: [추론](https://developers.openai.com/api/docs/guides/reasoning), [함수 호출](https://developers.openai.com/api/docs/guides/function-calling).

## 병렬 실행·병합·검증

메인 작업은 동시에 1개, Gemini 호출은 직접 작업과 공유하여 최대 3개다. 메인 한 작업에서 서브 작업은 최대 8개, 한 번에 최대 3개를 요청할 수 있다. 실제 병렬 수는 설정 및 Gemini RPM·TPM·RPD에 제한된다.

시작 시 현재 소스의 스냅샷을 `build/agent-runs/<작업 ID>`에 만들고 그 안에서 독립 Git 저장소를 구성한다. 현재 미커밋 소스도 포함하지만 원본 `.git`, 숨김 파일, 비밀 설정, 빌드 산출물은 복사하지 않는다. 서브 작업마다 별도 체크아웃을 만들며, 완료한 결과를 통합 체크아웃에 순서대로 병합한다. 충돌 시 병합을 취소하고 각 작업 브랜치를 보관한다. 메인이 diff를 보고 직접 충돌을 해결하거나 설명을 남겨 작업을 제외할 수 있다.

메인의 `publish_changes` 도구는 미처리 서브 작업을 확인한 뒤, 테스트가 활성화되어 있으면 통합 테스트를 직접 실행한다. 성공하면 원본 반영 후 **추가 GPT 호출 없이 종료**한다. 실패한 경우만 진단 로그를 GPT에 반환한다. 서브 작업은 통합 테스트를 실행하지 않는다. 성공 로그를 다시 모델에 해석시키는 토큰은 쓰지 않지만, 계획·명세·diff 검토·실패 수정과 누적 대화 입력 비용은 발생한다. 작은 작업은 `/sub-agent` 하나가 더 효율적일 수 있다.

원본 파일이 작업 시작 이후 사용자가 변경한 내용과 다르면 반영을 거부한다. 중단·충돌·실패 작업은 분리된 작업 폴더에 보관한다. 원본에는 검증 후 명시적인 원본 반영 단계에서만 적용한다. 자동 배포나 원본 저장소 커밋은 하지 않는다. 보관 폴더 자동 정리·작업 재개 UI는 아직 없다.

## 표시

각 작업은 일반 텍스트 채널에 공개 메시지를 만들고 **그 메시지 아래** 공개 스레드를 생성한다. 제목은 `에이전트 이름 · 작업 목표`이며 `agent` 옵션으로 이름을 지정한다. Discord에는 중첩 스레드가 없으므로 서브 작업도 채널에 각각 메시지와 스레드를 만들고 메인 작업에서 링크한다. 예약 시 미리 스레드를 만들지 않고 각 서브 작업이 실제 시작되는 이벤트에서 생성한다. 카드에는 담당 파일과 시작·종료 시각을 표시하고, 병합 완료·충돌·제외 상태로 갱신한다. 메인 스레드에는 분기 링크와 완료 알림을 남긴다. 병합·충돌 처리·최종 테스트·원본 반영은 해당 작업의 통합 스레드로 라우팅하며 첫 통합 도구가 실행될 때 생성한다. 각 활동 메시지에는 Discord 현지 시각 표시를 붙인다. 채널을 볼 수 있는 구성원은 활동을 볼 수 있다.

호출 번호별 시작·종료, 소요 시간·사용 토큰, 모델 출력·추론 요약·도구 요청·실제 실행 결과를 구분해 표시한다. 원본 파일 전체는 활동 메시지로 보내지 않지만 모델 출력과 테스트 로그에는 코드가 포함될 수 있다. 봇에는 채널 보기·메시지 전송·공개 스레드 생성·스레드 메시지 전송 권한이 필요하다. 실행 시 최고 관리자 역할을 Discord에서 새로 조회한다.

## Gemini 키와 한도

웹 **계정과 보안 → 루오노타르 Gemini API 키**에서 키 이름, 실제 Google 프로젝트 ID, RPM, 입력 TPM, RPD를 관리한다. 키는 암호화 저장하며 조회 API에 반환하지 않는다. 같은 프로젝트에서 발급한 키에는 같은 프로젝트 ID를 지정해야 하며 해당 그룹은 한도를 공유한다. 프로젝트 ID를 키에서 자동 검증하거나 Google 한도를 실시간 조회하지는 않는다.

기존 단일 키는 `default`로 유지한다. 프로젝트를 모르는 키의 초기 보호값은 RPM 5, 입력 TPM 250000, RPD 20이며 공식 보장 한도가 아니다. 실제 [AI Studio](https://aistudio.google.com/) 한도를 입력한다. API 무료 티어는 웹 무료 사용과 별개다. [공식 요금](https://ai.google.dev/gemini-api/docs/pricing)과 [한도](https://ai.google.dev/gemini-api/docs/rate-limits)를 확인한다.

남은 한도 비율이 큰 프로젝트부터, 같은 프로젝트 안에서는 오래 사용하지 않은 키부터 선택한다. 입력 토큰을 요청 전에 보수적으로 예약하고 응답의 `promptTokenCount`로 보정한다. 프로젝트·모델별 사용량과 진행 중 예약을 저장하며 파일 잠금으로 프로세스 간 한도를 공유한다. 분당 한도는 60초 이동 창, 일일 한도는 미국 태평양 시간 자정 기준이다.

RPM·TPM은 최대 약 65초 대기하며 모든 RPD 소진이나 단일 요청의 TPM 초과는 호출 전에 중단한다. 429는 제공자의 재시도 시간에 따라 프로젝트를 대기시키고, 일일 소진 오류이면 해당 날짜 그룹을 소진 처리한다. 401·403은 해당 키를 1시간 대기시킨다. 500·502·503·504는 제공자 일시 오류로 구분한다. 키가 다른 프로젝트여도 2·4·8초에 무작위 지연을 더해 대기한 뒤 재시도하고 명시된 Retry-After가 더 길면 그 값을 따른다. 전체 대기 한도를 넘는 제공자 권장 지연은 자동 요청을 중단한다. 4회 모두 제공자 오류이면 키 설정 오류 대신 모델과 마지막 HTTP 상태를 안내한다. 최대 4번의 실제 HTTP 요청마다 사용량을 예약한다. Discord에는 키 값 대신 이름과 프로젝트만 표시한다.

`/agent-keys`는 최고 관리자에게 로컬 집계 사용량을 비공개로 표시한다. Google 전체 사용량이 아니므로 다른 앱이나 적용 전 호출은 포함하지 않는다. 같은 프로젝트의 다른 키로 소진량을 초기화하지 않는다. `GEMINI_API_KEY`가 저장된 `default` 키보다 우선한다. 기본 Gemini 모델은 `gemini-3.8-flash`, 변경은 `LUONNOTAR_AGENT_MODEL` 환경변수를 사용한다.

CLI에서도 숨김 입력으로 키를 관리할 수 있다(버전명은 빌드 결과에 맞춘다).

```sh
java -jar build/libs/server-manager-0.4.11-beta.7.jar --configure-agent-key --key-id=work --project-id=your-google-project --rpm=5 --tpm=250000 --rpd=20
java -jar build/libs/server-manager-0.4.11-beta.7.jar --list-agent-keys
java -jar build/libs/server-manager-0.4.11-beta.7.jar --remove-agent-key=work
```

## 실행 범위와 제한

작업 폴더는 환경변수 `LUONNOTAR_AGENT_WORKSPACE` 또는 데이터 폴더의 `security/agent/workspace.txt`에 절대 경로를 설정한다. 환경변수가 우선한다. 테스트는 `LUONNOTAR_AGENT_TESTS=true` 또는 같은 설정 폴더의 `tests-enabled` 파일 내용 `true`로 활성화한다. 실행 중 프로세스는 설정 변경 후 재시작한다. API 키와 모델의 웹 설정은 다음 작업부터 적용된다.

코드·문서 파일의 목록 조회, 읽기, 유일 문자열 치환과 새 파일 생성을 지원한다. 숨김 경로, 심볼릭 링크, 빌드 산출물과 범위 밖 파일은 거부한다. 읽기 모드 파일당 256KB, 수정 모드 48KB, 초기 파일 내용 전체 512KB, 스냅샷 50MB·5000개 제한이다. 삭제·이동 전용 도구나 임의 셸 명령은 없다.

Gemini는 구조화된 액션 배열로 여러 수정과 마지막 테스트를 한 응답에 묶을 수 있다. 최대 12회 모델 호출, 호출당 출력 최대 4096토큰이다. 직접 `/sub-agent` 작업도 테스트 성공 시 추가 모델 호출 없이 종료하며 원본 반영 전에 필요한 최종 검증을 실행한다.

테스트 도구는 `bash ./gradlew test --console=plain --no-daemon`만 실행한다. 체크아웃당 최대 2회, 회당 3분, 로그 2MB 제한이며 모델에는 마지막 12000자를 반환한다. GPT 메인 도구 응답은 20000자, Discord 활동 출력은 약 1400~1800자로 제한한다. npm/프런트엔드 검사·임의 실행 명령·음성 재생 런타임 도구는 아직 없다.

이 작업 폴더 격리는 OS 샌드박스가 아니다. 테스트 코드는 봇과 같은 OS 사용자 권한으로 실행되므로 신뢰할 수 있는 프로젝트만 사용한다. 자식 테스트 프로세스에서 API 키·운영 프로필 환경변수를 제거하지만 파일시스템·네트워크 접근을 격리하지 않는다. 실제 모델 접근·권한·외부 제공자 응답은 키를 설정한 뒤 확인해야 한다.

## 로컬 Qwen 일반 대화

`/local-llm model:14b prompt:질문` 또는 `/local-llm model:30b prompt:질문`을 사용합니다.
기존 Discord 최고 관리자 역할 검사를 그대로 적용하고, 답변은 요청자에게만 표시합니다.
각 호출은 독립 대화이며 저장소·파일·셸·코딩 도구를 전달하지 않습니다. 기존 `/agent`, `/sub-agent`의 제공자는 바꾸지 않습니다.

### 성능이 좋은 서버 실행기에서 Qwen 실행

관리 앱을 띄운 컴퓨터가 느리면 서버 실행기가 설치된 다른 컴퓨터에서 Qwen을 돌릴 수 있습니다.
그 컴퓨터에 Ollama를 설치하고 모델을 내려받은 뒤, 실행기 실행 환경에 `RUNNER_LLM_ENABLED=true`를 설정하거나 실행기 데이터 폴더에 내용이 `true`인 `llm-enabled` 파일을 만들고 실행기를 재시작합니다. 기본적으로는 꺼져 있습니다.
`/local-llm`은 이렇게 허용한 실행기 중 연결된 것(여럿이면 ID 순서 첫 번째)에 요청을 보내고, 답변 머리말에 `실행기 이름`을 표시합니다. 허용한 실행기가 없거나 오프라인이면 아래의 관리 앱 컴퓨터 실행으로 돌아갑니다.
실행기에서도 같은 제한(요청 1개, 3분, 입력 6,000자, 출력 2,048토큰)이 적용됩니다. 실행기의 Ollama 주소는 그 컴퓨터의 `OLLAMA_URL`(로컬 HTTP만)과 `OLLAMA_MODEL_14B`·`OLLAMA_MODEL_30B`로 정하며 관리 앱이 바꿀 수 없습니다.
질문과 답변은 관리 앱과 해당 실행기 사이의 기존 인증된 연결로만 전달됩니다. 0.5.0 미만 실행기는 이 기능을 광고하지 않으므로 먼저 업데이트하세요.

관리 앱과 같은 컴퓨터에서 Ollama가 실행 중이고 해당 모델을 미리 내려받아야 합니다.
기본 주소는 `http://127.0.0.1:11434`, 기본 태그는 `qwen3:14b`, `qwen3:30b`입니다.
앱 실행 환경변수 `OLLAMA_URL`로 로컬 HTTP 주소를, `OLLAMA_MODEL_14B`·`OLLAMA_MODEL_30B`로 설치된 정확한 태그를 지정할 수 있습니다.
원격 Ollama 주소는 지원하지 않습니다. 모델 자동 다운로드나 클라우드 대체 호출은 하지 않습니다.

`think`는 기본 false이며 명시적으로 API에 전달합니다. `think:true`로 변경할 수 있습니다.
Ollama의 `message.content`만 답변으로 사용합니다. 이 설정은 반복 생성 문제가 해결된다는 보장이 아닙니다.
한 번에 로컬 요청 1개, 요청 3분, 입력 6,000자, 문맥 8,192토큰, 출력 최대 2,048토큰으로 제한합니다.
출력 한도 도달 시 미완성 가능성을 표시하며, 긴 답변은 텍스트 첨부로 전달합니다.
응답 후 `keep_alive:0`을 요청해 해당 모델을 메모리에 유지하지 않습니다. 다른 앱의 Ollama 사용은 통제하지 않습니다.
응답에 표시되는 시간은 로딩을 포함한 요청 경과 시간이며, 토큰 수는 Ollama가 반환한 출력 토큰 수입니다.
실제 14B·30B 품질·메모리 사용량·처리 속도 비교와 Discord 실연동은 별도 검증이 필요합니다.
