# 직접 중계와 Qwen 비서 설정

설정은 설치 화면과 관리 웹에서 진행합니다. 설정 파일을 직접 만들거나 수정할 필요가 없습니다. 실행 중인 Minecraft를 설정 확인 목적으로 종료하지 마세요.

## 직접 TCP 중계

1. 중계할 Mac에 실행기를 설치·등록합니다. 설치 화면의 **관리 웹 소유자의 TCP 중계 사용 허용**을 켭니다. 새 설치에서는 기본으로 꺼져 있습니다. 이 허용은 해당 컴퓨터 사용자가 철회할 수 있습니다.
2. 관리 웹 소유자로 **실행기·네트워크 → 게임 주소·중계**를 엽니다. 첫 화면의 **직접 TCP 중계**를 사용합니다. 로컬 허용·활성·준비 상태는 서로 다릅니다. 허용되지 않았거나 연결되지 않은 실행기는 새 대상으로 선택할 수 없습니다.
3. **게임 실행기가 연결할 중계 주소**에 게임 실행기에서 접근할 주소를, **플레이어용 공개 주소**에 플레이어가 사용할 공개 주소를 입력합니다. **실행기 연결 포트**는 공유 게임 포트와 다른 TCP 포트여야 합니다. 주소와 포트 변경을 저장합니다.
4. 중계 컴퓨터의 공유기에서 화면의 **공유기 포트포워딩 입력값**을 그대로 사용합니다. 게임 접속용과 실행기 연결용 두 행의 외부 TCP 포트·내부 주소·내부 TCP 포트를 각각 입력하고 컴퓨터 방화벽에서도 허용합니다. 게임 실행기에서 중계기로 먼저 연결하므로 게임 컴퓨터에는 별도 공개 포트가 필요하지 않습니다.
5. **새 중계 실행기**를 선택하고 **새 중계 준비**를 누릅니다. 포트·실행기 연결 진단을 확인하고 상태가 `CANDIDATE_READY`일 때 **준비된 중계로 전환**을 누릅니다. 기존 경로는 유예 기간 동안 유지되고 기존 연결은 종료를 기다립니다. 강제 차단은 표시된 연결 손실 영향을 확인한 뒤 **즉시 차단**으로 수행합니다.
6. DNS와 공유기·방화벽은 자동으로 바뀌지 않습니다. 필요한 DNS 변경도 소유자가 적용합니다. **관리 서버 위치에서 연결 검사**는 관리 서버에서 해당 주소·포트로 연결한 결과입니다. 외부 도달 여부가 **미검증**이면 인터넷 플레이어 접속 성공으로 판단하지 마세요. 공유기가 자기 공개 주소 접속을 지원하지 않을 수도 있습니다.

직접 경로는 `플레이어 → 중계 실행기 → 게임 실행기 → Minecraft`이며 관리 Mac은 게임 데이터를 전달하지 않습니다. 접힌 **게임 주소·DNS·기존 관리 Mac 경유 중계**의 기존 방식은 `중계 실행기 → 관리 Mac → 게임 실행기`로 전달하므로 관리 Mac의 지연 영향을 받습니다. 기존 방식 선택기를 직접 중계 선택기로 혼동하지 마세요. 공유 게임 포트와 서버별 이름·DNS는 기존 주소 설정에서 관리합니다. 직접 중계는 TCP 범위이며 기존 Sable UDP 설정과 구분됩니다.

## 게임을 유지하는 앱 업데이트

**시스템 → 앱 업데이트**에서 현재·대상 버전과 실제 단계·대기 사유·로그를 확인합니다. **실행기·네트워크 → 서버 실행기**의 각 컴퓨터에서 **구성요소별 업데이트 상태·로그**를 열면 실행기 기록도 볼 수 있습니다. 오프라인 상태는 재연결 후 기록을 이어 조회합니다. 구버전이 제공하지 않는 상세 기록은 이용 불가로 표시됩니다.

상주 게임 서비스가 Minecraft와 콘솔·중계 연결을 소유하면 관리 앱·실행기 제어 계층은 게임 프로세스를 유지하면서 교체할 수 있습니다. 상주 서비스 자체를 바꾸거나 호환되지 않는 변경은 안전한 유휴 시점을 기다립니다. 기존 방식으로 이미 실행 중인 게임의 최초 전환은 **다음 정상 종료 이후**입니다. 업데이트를 끝내려고 강제 종료하지 마세요. 전송·미완료 파일 인계·사용 중인 중계 연결도 대기 사유가 될 수 있습니다. 모든 구성요소가 항상 무중단 교체된다는 뜻은 아닙니다.

관리 앱의 현재 실행 로그는 **시스템 → 관리 앱 로그**에서 조회·필터·일시정지·내보내기를 합니다. 앱 재시작 이전 로그는 이 화면에 포함하지 않습니다.

## Qwen 파일 비서

관리 웹 소유자의 **AI 비서·에이전트**에서 Qwen 실행 컴퓨터와 모델을 설정하고 **Qwen 비서 · 파일과 개인 정보 조회**를 사용합니다. 로컬 모델 작업은 한 번에 하나만 실행합니다.

**파일 접근 권한과 편집 엔진**을 열어 허용할 폴더를 등록하고 **접근 권한 저장**을 누릅니다. 폴더 안의 기존 텍스트 파일 1~5개, 파일당 48KB까지 작은 수정에 사용합니다. 새 파일·삭제·이동·비밀 정보·관리 앱 데이터 접근은 지원하지 않습니다. 현재 파일 반영은 안전한 폴더 핸들이 가능한 Mac 환경을 대상으로 합니다. 다른 운영체제 파일 수정은 검증·지원 범위에 포함하지 않습니다.

**간단한 파일 수정**에서 폴더와 기존 파일의 상대 경로, 요청·완료 조건을 입력하고 **파일 확인·요청 준비**를 누릅니다. 원본 내용과 외부 모델 전송 설명을 검토한 뒤 **위 내용을 모델에 전송하고 초안 만들기**로 전송에 동의합니다. 메인 모델의 계획·변경 검토와 변경 전후 내용을 확인한 다음 **표시한 변경과 명령 최종 승인**을 눌러야 반영됩니다. 두 승인은 별도 단계이며 요청·파일·명령에 묶인 일회용 승인입니다. 외부에서 원본을 바꾸면 재검토가 필요합니다. 필요하면 **거절·취소**하고 완료 뒤 **기록·임시 복사본 삭제**로 정리합니다. 위험 평가는 안전 보증이 아닙니다.

기본 편집 엔진은 구조화된 구문 교체입니다. **Aider는 설치하거나 실행하지 않습니다.** 명령도 기본 금지입니다. 실행 파일 허용 목록은 OS 샌드박스가 아니므로 등록한 프로그램은 관리 앱 사용자 권한으로 폴더 밖 파일과 네트워크에 접근할 수 있습니다. 필요한 신뢰된 진단 도구만 허용하고 최종 승인에 표시되는 정확한 프로그램·인자·작업 폴더를 확인하세요.

Discord에서 사용하려면 **Discord 소유자 계정 연결 → 5분 연결 코드 발급**으로 코드를 만들고 비공개 `/assistant-link`에 입력합니다. 소유자 연결과 Discord 최고 관리자 역할을 모두 확인합니다. 연결 코드는 한 번만 사용하며 앱 재시작 때 연결이 해제됩니다. 승인 요청은 요청 내용·변경·위험·명령을 확인한 뒤 처리합니다.

## 개인 Gmail·캘린더 연결

**내 계정**의 Google 연결 화면에서 연결합니다. 소유자는 **Google 앱 설정 · 소유자 전용**에서 Google Cloud OAuth 클라이언트 ID와 보안 비밀번호를 저장합니다. 화면에 표시되는 리디렉션 URI를 Google Cloud에 그대로 등록하고 Gmail API·Calendar API, 동의 화면·테스트 사용자와 필요한 배포 검증을 준비합니다.

각 사용자는 자신의 Google 계정을 직접 연결합니다. Gmail 검색·읽기와 일정 조회만 제공하며 발송·삭제·일정 변경은 제공하지 않습니다. Qwen 요약은 소유자 비서 화면의 **Gmail·캘린더를 Qwen으로 요약**에서 조건을 정하고 조회 결과를 Qwen 컴퓨터로 보내는 데 별도 동의한 뒤 실행합니다. 이 요약 결과는 메인 클라우드 검토에 보내지 않습니다. 메일·일정에 쓰인 지시는 파일·명령 권한을 부여하지 않습니다. 사용이 끝나면 내 계정에서 Google 연결을 해제할 수 있습니다.

## 검증 범위

개발 검증은 격리된 Mac 프로세스와 모의 API·브라우저를 중심으로 수행했습니다. 실제 여러 컴퓨터·공개 인터넷 중계, 실제 Qwen 추론과 개인 Google OAuth 연결은 아직 확인하지 않은 항목입니다. 운영 서버·공유기·DNS·개인 계정에 이 문서의 예제를 자동 적용하지 않았습니다. 다른 운영체제 추가 검증은 이번 요청 범위에서 진행하지 않습니다.
