# 로컬 모델 선택

관리 웹의 **AI 비서·에이전트 → 로컬 LLM (Ollama)** 또는 Discord `/agent setting default:`에서 선택한다. 기존 사용자 기본 모델은 자동으로 바뀌지 않는다. 일회성 선택은 `/agent run model:`을 사용한다.

| 선택지 | 저장/실행기 ID | 기본 Ollama 태그 | Thinking |
|---|---|---|---|
| Qwen3 14B | `14b` | `qwen3:14b` | 지원 |
| Qwen3 30B | `30b` | `qwen3:30b` | 지원 |
| Qwen3-Coder 30B | `qwen3-coder-30b` | `qwen3-coder:30b` | 미지원, 자동 꺼짐 |
| Gemma 4 12B | `gemma4-12b` | `gemma4:12b` | 지원 |
| Gemma 4 31B | `gemma4-31b` | `gemma4:31b` | 지원 |

관리 앱과 **실제 추론 실행기 모두** 새 버전으로 업데이트해야 한다. 실행기의 `llm-enabled` 동의는 기존대로 필요하다. 해당 실행기 컴퓨터에서 사용할 모델만 설치한다:

```sh
ollama pull qwen3-coder:30b
ollama pull gemma4:12b
ollama pull gemma4:31b
```

선택/저장만으로 모델을 다운로드하지 않는다. 설치 상태는 환경 확인에서 볼 수 있다. 단일 추론 제한과 독립 위험 검토·명시적 승인·중지·문맥 제한을 그대로 적용한다. 추론은 선택한 실행기에서, 파일 도구는 기존 관리 앱 컴퓨터에서 실행된다. 다른 지원 모델이 메모리에 있으면 먼저 내리고, 관련 없는 Ollama 모델은 건드리지 않는다. 따라서 다른 앱이 적재한 모델까지 포함한 전체 메모리 여유를 보장하지 않는다.

Coder는 별도 Thinking 블록을 생성하지 않는다. 기존 개인 Thinking 설정값은 보존하고 Coder 요청에서만 실제 옵션을 false로 제한한다. 다른 지원 모델로 전환하면 기존 설정을 다시 사용한다. 실행 창8192·출력4096은 유지하며, 모델 최대 문맥은 Ollama 메타데이터를 조회한다. 모델의 큰 최대 한도가 모두 RAM에 들어간다는 뜻은 아니다.

31B는 24GB 컴퓨터에서 다른 앱·문맥 캐시를 포함하면 메모리 여유가 작을 수 있다. 실행 여부·속도·스왑은 실제 시험 결과를 참고한다. 파일 수정 성능은 출력 문구가 아니라 최종 실제 파일 전체 바이트와 요청 위치를 검증해야 한다.

내부 `/api/admin/qwen` 경로와 설정 파일 이름은 이전 버전 호환을 위해 유지한다. API GET의 `models`가 UI/Discord 공통 모델 카탈로그이며 기존 `14b/30b` 저장 ID와 기본14b는 유지된다.
