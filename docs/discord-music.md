# Discord 음악 명령

관리 앱에서 Discord 봇 연동을 켜고 Bot 토큰을 저장한 뒤, 표시되는 초대 링크로 봇을 서버에 초대합니다. 음악 기능은 같은 Discord 연동을 사용합니다. 별도의 YouTube API 키는 필요하지 않습니다. 봇이 실행되는 Mac과 관리 앱이 켜져 있고 Discord에 연결되어 있어야 명령을 처리할 수 있습니다.

Discord 서버의 음성 채널에 들어간 뒤 다음 슬래시 명령을 사용합니다.

| 명령 | 동작 |
| --- | --- |
| `/music join` | 사용자가 있는 음성 채널에 봇을 연결합니다. |
| `/music play` | YouTube 주소 또는 검색어로 곡을 찾아 대기열에 넣고 재생합니다. |
| `/music queue` | 현재 곡과 대기열을 확인합니다. |
| `/music pause` | 재생을 일시 정지합니다. |
| `/music resume` | 일시 정지한 곡을 다시 재생합니다. |
| `/music skip` | 현재 곡을 건너뛰고 다음 곡으로 넘어갑니다. |
| `/music stop` | 재생을 멈추고 대기열을 비웁니다. |
| `/music leave` | 재생을 멈추고 음성 채널에서 나갑니다. |

Discord 연동 설정에 등록된 서버의 멤버만 명령을 사용할 수 있습니다. `queue`는 음성 채널에 들어가지 않아도 확인할 수 있습니다. 재생과 제어 명령은 요청자가 음성 채널에 있어야 하며, 봇이 이미 연결되어 있으면 같은 채널에 있는 사용자만 제어할 수 있습니다. 대기열과 재생 상태는 Discord 서버마다 독립적이며 최대 100곡입니다. 앱 재시작 시 대기열은 초기화됩니다. 음악 명령 응답은 요청자에게 비공개로 표시됩니다. Minecraft 서버 제어용 역할 권한은 음악 명령에 적용되지 않습니다.

봇에게 슬래시 명령 사용, 음성 채널 **연결** 및 **말하기** 권한을 부여하세요. 채널별 권한 덮어쓰기도 확인합니다. 검색 및 스트리밍은 YouTube의 가용성과 네트워크 상태에 영향을 받습니다. 일부 영상은 지역·연령·라이브·저작권 제한 때문에 검색되더라도 재생되지 않을 수 있습니다. 재생 중 실패한 곡은 다음 대기 곡으로 넘어가며 `/music queue`에 최근 재생 오류를 표시합니다. 이 기능은 YouTube Premium이나 개인 계정 로그인으로 제한을 우회하지 않습니다.

실제 음성 검증은 본인이 관리하는 Discord 테스트 서버에서 진행합니다. 봇을 초대한 뒤 `join` → `play`(검색어와 영상 URL 각각) → `queue` → `pause` → `resume` → `skip` → `stop` → `leave` 순으로 확인하세요. 다른 음성 채널의 사용자가 제어할 수 없는지, 다른 Discord 서버의 대기열과 섞이지 않는지도 확인합니다. 자동 테스트는 외부 Discord 연결이나 메시지 전송 없이 정책과 재생 상태를 검사합니다.

현재 빌드의 라이브러리 버전은 JDA `6.7.0`, LavaPlayer `2.2.7`, YouTube 소스 플러그인 `1.18.2`, Java 21 호환 DAVE 구현체 `libdave-jvm 0.1.2`입니다. YouTube 소스의 릴리스 이후 [iOS 호환성 수정 6579cdf](https://github.com/lavalink-devs/youtube-source/commit/6579cdf)을 국소 적용하며 Web 검색과 iOS 스트림 경로를 분리합니다. 배포 환경에서 해당 라이브러리와 YouTube 측 변경으로 재생 가능 여부가 달라질 수 있습니다.

외부 Discord 접속 없이 자동 검증하려면 일반 `test`를 실행합니다. 공개 YouTube 검색·영상 URL에서 실제 Opus 프레임 로드와 DAVE 네이티브 초기화까지 확인하려면 `DISCORD_MUSIC_LIVE_TEST=true ./gradlew test --tests '*DiscordMusicLiveTest'`를 실행합니다. 이 추가 검사는 YouTube에 읽기 요청을 보내지만 Discord 토큰을 읽거나 메시지·음성을 전송하지 않습니다. 외부 서비스와 네트워크 상태에 따라 실패할 수 있습니다.

## 음악 전용 채널과 공개 패널

관리자는 `/music channel channel:#노래`로 길드당 하나의 음악 전용 텍스트 채널을 등록합니다. 옵션을 생략하면 현재 채널을 사용합니다. Discord 채널 관리 권한 또는 관리 앱에 등록된 최고 관리자 역할이 필요합니다. `/music unchannel`은 등록을 해제합니다. 채널과 패널의 ID는 비공개 데이터 폴더에 저장되어 앱 재시작 후 복구됩니다.

등록한 채널에 검색어나 YouTube URL을 일반 메시지로 보내면, 같은 음성 채널 조건을 확인한 뒤 자동으로 음악을 추가합니다. 다른 채널의 일반 대화는 처리하거나 삭제하지 않습니다. 사용자가 보낸 검색 메시지는 도착 후 3초 뒤, 봇의 등록·실패 안내는 표시 후 3초 뒤 삭제합니다. 슬래시 명령과 버튼의 비공개 안내도 3초 뒤 정리합니다. 등록 전에 있던 메시지는 일괄 삭제하지 않습니다.

공개 고정 임베드에 현재 곡·YouTube 링크·썸네일·상태·대기열을 표시하고, 현재 곡 등록자의 서버 닉네임과 프로필 사진 및 대기 곡별 등록자 이름을 함께 표시합니다. 등록자 정보는 이전 곡 복귀 시에도 유지되며 현재 메모리의 재생·히스토리 데이터에만 보관합니다. 재생 및 대기열 변경 시 약 1초 뒤 갱신합니다. 재생·일시정지·정지·이전·다음 버튼은 현재 등록된 패널에서만 작동합니다. 이전 곡 기록은 길드별 최근 20곡이며, 이전으로 돌아갈 때 현재 곡은 대기열 앞에 보존합니다. 기록이 없으면 현재 곡을 처음부터 다시 재생합니다. 정지는 재생·대기열·이전 기록을 모두 비웁니다.

Discord는 기존 메시지를 임의로 맨 위로 이동할 수 없으므로 패널을 고정(pin)하고 새 검색·안내 메시지를 정리합니다. 봇이 서버 관리자라면 개별 채널 권한을 따로 부여할 필요는 없습니다. 일반 채팅 내용 접근에 필요한 **Message Content Intent**는 별도 애플리케이션 설정입니다. 앱은 Discord의 승인된 플래그를 조회한 뒤에만 이 intent로 접속해, 권한 미설정 때문에 기존 관리 봇 연결이 끊기는 것을 방지합니다. 수동 설정이 필요한 환경에서는 Developer Portal → Bot → Privileged Gateway Intents → Message Content Intent를 켜고 봇을 재연결합니다. 관리자 권한이 없는 봇에는 메시지 관리·메시지 고정·임베드·기록 보기 권한도 필요합니다.
