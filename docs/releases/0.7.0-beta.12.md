# 0.7.0-beta.12 — 음악 자동 퇴장·모듈 관리, LLM 한계 보고

**Qwen의 도구 선택 실패를 해결했다고 주장하는 릴리즈는 아닙니다.** 실제 봇 기록과 새 LLM 시험에서 확인한 구현 문제를 분리하고, 파인튜닝·하네스 연구 수준의 추가 작업은 사용자 지시대로 보류했습니다.

## 해결한 것

- 음악봇이 연결된 음성 채널에 사람이 **연속 60초 없으면** 재생·대기열을 정리하고 퇴장합니다. 다른 봇은 사람으로 세지 않으며, 사람 복귀·채널 변경·연결 끊김에 시간을 초기화합니다. 늦게 끝난 로드가 음악을 다시 시작하지 못하도록 기존 세션/세대 검사를 유지합니다.
- 짧은 명령 실행 요청을 중복 요구사항 6개로 늘리던 부분을 수정했습니다. 500자 이하 비목록 요청은 파일 이름 유무와 관계없이 원문 한 항목으로 보존합니다.
- Minecraft 명령·패널·알림·중복 방지의 실제 코드를 `DiscordMinecraftModule`로 옮겼습니다. 기존 서버 제어 포트·역할 제한을 유지하며 실행 직전 최신 역할·권한 거부·모듈 활성 여부를 다시 확인합니다.
- 관리 웹 **연동 서비스 → Discord 봇 → 봇 기능 모듈**에서 기능별로 켜고 끌 수 있습니다. 음악 비활성화 시 재생/연결을 정리하고, 에이전트 작업을 취소합니다. 별도 비공개 설정·revision·소유자 재인증·저장 충돌·미저장 이동 보호를 적용했습니다.

## 직접 확인한 LLM 미해결

- 운영 기록: `run_command` 사용 요청에도 모델이 이를 선택하지 않고 읽기 전용 `sh`로 Python 실행을 시도하거나 조회를 반복했습니다. 요약의 수정 완료 주장과 이후 읽은 파일 내용도 일치하지 않는 사례가 있었습니다.
- 실제 Qwen3 14B/8K 새 프로젝트: 같은 도구 선택 실패를 재현했습니다. 메모리 압력 정상에서 실제 실행 0회, 합친 파일 미생성, 두 원본은 보존됐습니다. JUnit 98.6초 후 완료로 처리하지 않고 중단했습니다.
- Qwen3 30B/8K: 현재 Mac에서 로딩 중 압력 임계 4로 약 15초에 시험을 중단했습니다. 답변 전이므로 추론 능력 실패로 계산하지 않습니다. 모델 해제와 별도 정상 압력 회복을 확인했고 Metal 한도는 변경하지 않았습니다.

2단계 도구 선택 설계와 모델 능력을 추가 비교해야 하며, 모델 자체의 한계 또는 파인튜닝 필요로 확정할 수 없습니다. 이 부분에 프롬프트·권한 완화·강제 실행을 더하지 않았습니다. 공식 Ollama 호출은 유지하지만 이전 파일 편집 시험의 성공을 모든 작업의 안정성으로 일반화하지 않습니다.

## 검증과 범위

음악·모듈·요구사항 관련 기능 회귀, 추가 관리자 API 재인증/차단 검사, React 빌드와 모듈 화면 Playwright 1개를 통과했습니다. 전체 스위트·다른 OS·실제 Discord 음성은 미실행입니다. 기존 서명 CI로 JAR·Mac 관리자 PKG·Mac/Windows 실행기 ZIP·서명/해시 파일 9개를 배포합니다.

사용자 선택대로 현재 프로세스의 모듈 구조까지만 보완했습니다. 별도 봇 프로세스·인증 HTTP API·설치 분리는 다음 범위입니다. 제가 운영 앱·실행기·게임호스트 교체나 재시작 명령을 실행하지 않았습니다.
