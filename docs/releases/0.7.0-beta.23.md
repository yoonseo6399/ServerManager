# 0.7.0-beta.23 — 실험 KV 압축·64K 문맥·승인 검토·단일 파일 diff

관리 앱과 **추론에 사용하는 실행기를 모두 Beta23으로 업데이트**해야 새 문맥/압축 설정을 전달할 수 있습니다. 기본8K와 실험 옵션 꺼짐은 유지하며 stable/latest는 바꾸지 않습니다. 운영 앱/실행기를 자동 설치·재시작하지 않습니다.

## 설정 방법

관리웹 로컬 LLM 설정에서 실제 추론 컴퓨터를 선택합니다. 27B는 **TurboQuant 엔진 준비** 후 **실험 KV 캐시 압축**을 켜고 저장합니다. 준비 버튼은 고정 native 엔진과 격리 OpenSSL만 설치하며 모델을 로드하지 않습니다. 파일 직접 편집이나 OS 메모리 한도 변경은 필요 없습니다. Apple Silicon macOS15 이상을 지원합니다.

- 27B 채널: `/agent context action:configure window:65536` (필요하면 `limit`으로 압축 시작점 지정).
- 해당 요청만 변경: `/agent run prompt:... window:65536`.
- Flash-Next: `window:16384`. Strata는8K/16K만 지원하며32K/64K를 조용히 축소하지 않습니다.
- Discord 선택지는8K/16K/32K/64K로 확장했습니다. **실험 KV 토글은27B와 Flash-Next에만 적용**됩니다. 구버전 실행기는 명확히 거절하며 다른 컴퓨터/캐시로 대체하지 않습니다.

27B는 별도 고정 TurboQuant fork의 **Q8 K + Turbo4 V**이며 Ollama에 설치된 GGUF를 재사용합니다. GQA 품질 보호를 유지한 구성입니다. Flash-Next는 기존 Strata의 **회전 Q4 KV**이며 Google TurboQuant와 동일 구현이 아닙니다. 토글을 끄면 기존 Ollama/Strata 경로를 사용합니다. 모델 전환은 관리 대상 모델/본인 서비스만 종료하며 OS wired 한도는 건드리지 않습니다. 상태에 실제 실행 창과 native RSS(공유 페이지 포함)를 표시합니다.

## 실모델 시험

24GiB Mac에서 정상 메모리 압력으로 시작했습니다. 디자인 앱 등 기존 앱은 종료하지 않았습니다.

| 모델 | 확인한 실행 창 | 실제 긴 입력 | 표식 회수 | 총 요청 시간 | 생성 속도 |
|---|---:|---:|---|---:|---:|
| 27B Q4_K_M · Q8 K/Turbo4 V |65,536|56,464토큰|일치|약14분|6.57tok/s|
| Flash-Next Q2_0 · 회전Q4 KV |16,384|8,607토큰|일치|약20분53초|8.8tok/s|

실행 창 전체를 입력으로 채운 시험은 아닙니다. 표식 한 건의 성공을 일반 코딩/도구 품질 보장으로 확대하지 않습니다. 27B는 정상/주의 압력을 관측했고 위험 중단은 없었습니다. Flash는 정상 압력이었습니다. 기존 스왑을 포함한 전후 수치·중단한 첫 시험도 보존했습니다. Flash 긴 입력은 입력 처리 자체가 느려 **기본20분 타임아웃을 넘을 수 있으므로 관리웹의 요청 제한 시간을 늘려야** 합니다. 기본 타임아웃을 임의로 바꾸지는 않았습니다.

## 승인과 diff

- 독립 검토에 공개 API 읽기를 네트워크 사용만으로MEDIUM/ASK로 올리지 않도록 명시했습니다. 정확히 요청한 다운로드는 실행/설치와 구분하며 사전 동의를 인정합니다. 명시 모드·독립 검토·HIGH/DENY·외부 작업과 push/PR 동의 정책은 유지합니다. 백엔드 강제 허용 목록은 추가하지 않았습니다.
- 실제27B 검토4사례는 공개GET 허용/LOW, 승인 다운로드 허용/MEDIUM/동의true, 미승인 스크립트 실행과 비밀키 전송 거부/HIGH로 통과했습니다. 첫44초, 이후약8~10초이며 실제 명령은 실행하지 않았습니다.
- **미해결:** 14B는 같은 공개조회/승인다운로드를 보완 지시 후에도ASK로 오판했습니다. 이번 수정이 모든 모델에서 불필요한 승인 요청을 해결했다고 주장하지 않습니다. 원문을 보존했습니다. 배우 모델의 결과 검증·자가복구는 변경하지 않았습니다.
- 자동 diff는 관측 가능한 변경이 **단일 파일일 때만** 표시합니다. clone/프로젝트 생성/다중 파일 변경으로 채팅이 diff로 도배되지 않으며, 단일 파일 수정의 diff/자세히 보기는 유지합니다. 관측 상한 때문에 전체 변경을 확인하지 못한 경우도 diff를 생략합니다. clone 대상 프로젝트 해석 자체는 바꾸지 않았습니다.

## 검증

기능 브랜치 로컬 전체회귀 **655통과/29조건부 미실행/실패0**(총684보고), 관련24개·격리 native 설치/지원 검사1개 및 프런트 빌드 통과. 통합 소스도 **655통과/29조건부 미실행/실패0**, 프런트/JAR 빌드와 KV 설정 브라우저1개를 통과했습니다. 태그 CI에서 전체 테스트·프런트/JAR·runner-setup·패키징·격리 bootstrap·서명·게시를 다시 검증합니다. 코드와 시험 계획을 먼저 커밋한 후 검증했습니다.

첫 CI에서 TCP 연결 거절 예외의 하위 타입 기대와 Python 별 출력 시험이 실패해 게시 전에 중단했습니다. TCP 시험은 연결 차단을 유지하고 SocketException 계열을 올바르게 검사합니다. Python 검증은 시작 대기와 생성 코드 실행3초 제한을 분리하고 실패 진단을 보강했습니다. Python 최초 실패의 정확한 원인은 미확정입니다. 수정 후 로컬 전체 회귀655통과/29조건부 미실행/실패0, 관련20개 및 TCP 철회3회 반복 통과. 제품의 TCP/모델 실행 로직은 이 CI 보완에서 변경하지 않았습니다.

새 캐시에서 실제 Discord 전체 도구 연쇄·버튼, 전체 창 충전, 기존 캐시와 동등 부하A/B, 다른OS, 디자인 앱 실제 편집 응답성은 미실행입니다. 게시 파일을 다시 다운로드해 해시 비교하지 않습니다. 기존 게시 태그/파일은 변경하지 않습니다.
