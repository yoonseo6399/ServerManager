# 0.7.0-beta.21 — Pi 승인 판정 정리·하단 상태창·선택 답변 기록

관리 앱을 업데이트하세요. 이번 변경은 관리 앱의 Pi 승인·Discord 표시 경로에 적용됩니다. 베타 릴리즈이며 stable/latest는 유지합니다.

- **정적 실행 판정 제거:** OWNER의 Pi read/edit/write/bash를 정적 명령 목록이나 경로·파일명·fingerprint 판정으로 거절하던 백엔드 검사를 제거했습니다. 독립 검토의 ALLOW/LOW가 백엔드 UNKNOWN 때문에 ASK/MEDIUM으로 바뀌지 않습니다. fetch --all --prune, 브랜치 조회·생성, 복합 Bash도 독립 모델이 판단합니다.
- **독립 검토·사용자 승인:** 선택한 모델의 독립 새 세션 검토와 실제 사용자 원문 요청 기록을 사용합니다. 자동 모드에서 ALLOW/LOW 또는 정확한 사전 동의가 확인된 LOW/MEDIUM은 재확인하지 않습니다. 명시 모드는 Bash·변경 작업을 계속 확인하고, 모델 DENY·검토 실패·사용자 거절은 실행하지 않습니다. 프로젝트 밖 일반 파일도 정확한 대상·효과에 대한 명시적 동의가 있으면 검토에서 허용할 수 있습니다. Discord 사용자·채널·역할·정보 제공 ACL과 본인 승인·중지 기능은 유지합니다.
- **선택 답변 기록:** 질문에 어떤 선택지를 골랐는지, 누가 응답했는지 원래 질문 메시지에 남깁니다. 직접 입력한 답변도 같은 방식으로 표시합니다. 긴 답변은 필드로 나눠 표시하고 멘션 알림은 보내지 않습니다. 정보 질문 답변이 실행 승인이 되는 것은 아닙니다.
- **하단 상태창:** 첫 메시지는 요청·모델·진행·토큰/메모리/생성 속도의 요약으로 남습니다. 진행 상태창은 새 응답 메시지 뒤 하단에 표시하고 도구 실행 시 그 메시지를 승인/실행 카드로 바꿉니다. 다음 모델 턴에는 새 상태창을 보냅니다. 완료된 도구 기록은 보존하며 뒤늦은 상태 업데이트가 덮어쓰지 않도록 했습니다. 중지 버튼은 진행 중 유지하고 종료 후 제거합니다.

정적 검사 제거로 위험 판단은 독립 모델과 사용자의 승인에 의존합니다. OS 샌드박스가 아니며 모델 오판과 검토 후 실행 전 파일 변경을 막는 보장은 없습니다. 실행 파일 내용·해시는 검토 참고 자료로 전달하되 내용 변화만으로 백엔드가 실행을 거절하지 않습니다.

검증: 구현·테스트 계획을 먼저 커밋한 뒤 관련 기능54개 통과, 마지막 지표 유지 수정 후 표시7개 재확인 통과. 실제 고정 Pi SDK와 격리한 localhost HTTP Git 원격에서 fetch·조회·pull·beta21 브랜치 생성 연쇄 실행을 확인했습니다. 이 시험의 모델 판정은 재현 가능한 fixture이며 이번에 실제27B 신규 품질 시험은 하지 않았습니다. [검증 계획과 결과](https://github.com/yoonseo6399/ServerManager/blob/v0.7.0-beta.21/docs/testing/pi-reviewer-authority.md).

전체 테스트·다른 OS 실제 실행·운영 Discord 버튼/네트워크 검증은 생략했습니다. 프런트/JAR/설치 패키징·격리 bootstrap·서명은 게시 CI에서 검증합니다. 운영 앱·실행기·게임을 자동 설치·재시작하지 않으며 게시 후 자산 재다운로드·해시 대조는 사용자 요청으로 생략합니다.
