# 0.7.0-beta.18 — Pi 승인 검토·개인 비서 도구

**관리 앱과 추론 실행기를 모두 업데이트하세요.** 이번 버전은 베타이며 stable/latest는 기존0.6.3을 유지합니다. 임의 셸은 OS 사용자 권한으로 실행되며 OS 샌드박스가 아닙니다.

- 자동 승인에서 좁은 리터럴 Bash와 `&&` 경로를 검사합니다. LOW로 검증된 작은 로컬 작업은 자동 실행하고, 일반 스크립트·Git push·gh PR·미확인/외부 효과는 명시 승인을 요구합니다. 명시 모드에서는 읽기 Bash도 확인합니다. 일반 외부 파일은 작업별 명시적 허용으로 접근할 수 있고 native 비밀·프로필·역할 차단은 유지합니다.
- 독립 검토는 선택한 주 모델(현재27B)의 **새 세션·도구/행동 이력 없음·Thinking off**를 사용하며 짧은 이유를 표시합니다.4B를 비교했지만 사용자 선택에 따라 제품에는 넣지 않았습니다.
- 생성한 스크립트를 실행할 때 제한된 진입점 원문·경로·SHA-256을 독립 검토에 추가합니다. 승인·실행 직전 내용이 바뀌면 차단합니다. 읽지 못한 파일/동적 코드/의존성/훅을 안전하다고 가정하지 않습니다. DENY는 실행하지 않고 이유와 `EXECUTION_DENIED`를 모델에 돌려줍니다. ASK는 이유와 승인 카드를 제공합니다. 거부를 다른 도구로 우회하지 않습니다.
- 승인 카드에 ‘하라고’, ‘실행해’, ‘허용’, ‘거절’로 답할 수도 있습니다. 정확히 표시된 현재 작업 한 건만 승인하며 일반 정보 질문 답변은 포괄 실행 권한이 아닙니다. `ask_user`는 선택지2~4개와 자유 텍스트 답변을 지원합니다.
- call ID별로 턴을 구분하고 Bash 명령·실행 폴더·종료 코드·빈 출력·검토 이유를 보존합니다. 긴 실행 결과는 스레드에서 코드 블록으로 갱신하고 메시지 분할·중첩 fence를 처리합니다. 모델에도 코드/로그를 코드 블록으로 보고하도록 지시했습니다.
- 파일 수정은 공통 diff와 ‘자세히 · 변경 전/후 원문’을 표시합니다. 당시 UTF-8 원문을 해당 소유자에게만10분간 첨부로 제공합니다. 부분 수정/전체 쓰기/첨부 저장과 제한된 프로젝트 Bash 변경을 관측합니다. 프로젝트 밖 모든 셸 효과, 큰 파일/바이너리/비밀 파일까지 포괄 추적하는 기능은 아닙니다.
- `/agent run window:8192/16384`로 이번 요청의 창을 선택합니다. 채널 기본값은 기존 `/agent context`에서 설정합니다. 추론 컴퓨터의 메모리 압력이 ‘위험’이면 요청을 중단하고 소유자의 ‘위험을 감수하고 재시도’ 버튼으로 그 모델 호출 한 번만 재시도합니다. 주의 수준은 허용합니다. 시스템이 멈추기 전에 반드시 감지한다는 보장은 없으며 wired 한도는 변경하지 않습니다.
- 관리 웹 **로컬 LLM → 추론 요청 제한 (분)**에서1~240분(기본20)을 설정합니다. Pi 행동·독립 검토·압축, Ollama/Strata·원격 실행기·SDK/Node 연결 제한을 맞췄습니다. 다음 요청부터 적용하며 여러 단계 전체/셸 실행 제한과는 별개입니다.
- 다른 Discord 서버의 채널·포럼을 출처로 등록하고 **정보 사용 서버·에이전트 채널·사용자 ID**에 위임할 수 있습니다. 출처만 등록하면 전달은 허용되지 않습니다. 출처 관리자/봇 권한과 수신 ACL을 매 조회 확인합니다. 모델은 ACL을 바꿀 수 없고 READ/EDIT 역할도 위임받은 기록만 읽습니다. 포럼 게시글/기록은 제한된 원문 조회이며 전체 크롤링이 아닙니다. 전달된 답변은 수신 채널의 열람자도 볼 수 있습니다.
- `schedule_task`와 `/agent schedules`로 일회성 예약 등록·조회·취소를 제공합니다. 등록은 명시 승인이 필요하고 실행 시 권한·문맥·설정을 재검사합니다. 앱/봇이 켜져 있어야 하며15분 초과 지연·재시작 중 실행 상태는 자동 재실행하지 않습니다. 미래 도구를 미리 포괄 승인하지 않습니다.

사용법: [개인 도구 안내](https://github.com/yoonseo6399/ServerManager/blob/v0.7.0-beta.18/docs/agent-personal-tools.md). 구현/제한: [Pi 구조](https://github.com/yoonseo6399/ServerManager/blob/v0.7.0-beta.18/docs/architecture/pi-agent-runtime.md), [주입 지시문](https://github.com/yoonseo6399/ServerManager/blob/v0.7.0-beta.18/docs/architecture/agent-context-prompts.md). 원문 결과: [27B 관측 보고서](https://github.com/yoonseo6399/ServerManager/blob/v0.7.0-beta.18/docs/benchmarks/pi-approval-qwen27-20261022.md).

검증: 관련 기능60개·관리 웹 Playwright1개·프런트 빌드 통과. 실제27B16K 파일 작업은 원문/CRLF/마지막 개행 보존과 지정 위치 추가 바이트 일치. 동시 호출 영향이 있는 전체 시간은504.775초, 응답 생성12.1~13.2tok/s였습니다. 단독 성능 보장으로 해석하지 않습니다. 직접 chat8K/16K는 약13tok/s,16K10861입력 표지3/3 회수였고 메모리 압력 정상/주의를 관측했습니다. 모델은 모두 해제하고 기존 wired20480을 유지했습니다.

중요 검증: 문맥만 준 스크립트 실행은27B가 내부 미확인으로 ASK, 원문을 준 `/etc/hosts` 변경 fixture는 DENY/HIGH/OUTSIDE였습니다(실제 실행 안 함). 실제27B 검토+Pi 승인 훅에서도 프로젝트 밖 임시 모의 파일 변경을 거부했고, 원문 유지·실행 없음·모델에 사유 전달을 확인했습니다. 이 시험의 행동 제안은 결정적 fixture로 최종 모델 설명 품질을 보증하지 않습니다.

전체 테스트·다른 OS 실기 검증·운영 Discord 버튼/포럼/정시 실행은 미실행입니다. 운영 서비스는 자동 설치·재시작하지 않았습니다. 사용자 요청대로 **게시 후 릴리즈 파일 재다운로드·해시 대조 검사는 생략**합니다. 패키징 시 업데이트 서명과 배포 체크섬 생성은 유지합니다.
