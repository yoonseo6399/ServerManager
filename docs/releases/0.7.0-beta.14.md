# Server Manager 0.7.0-beta.14

직접 중계에서 실행기가 누락되거나 최초 선택을 저장하지 못하던 문제를 고치고, Sable UDP도 선택한 실행기를 통해 관리 Mac을 우회하도록 추가했습니다. 게임 주소·중계 화면을 직접 경로/전송 방식과 공통 포트·DNS로 나누고 기존 Mac 경유 방식은 접힌 고급 설정으로 정리했습니다.

- 등록된 활성 실행기를 첫 상태 보고 전에도 표시합니다. 미확인·오프라인·로컬 미허용 상태를 구분하고, 최초 선택을 저장합니다. 활성 중계의 변경은 준비 후 전환합니다.
- 실행기/상주 서비스 재연결 시 중계 상태 전달과 최신 동의 재확인을 복구했습니다. 늦게 도착한 폴링 응답이 새 저장 결과를 덮지 않습니다.
- **직접 중계에 Sable UDP 추가** 옵션과 지원/대기/왕복 확인/오류 상태를 추가했습니다. UDP 포트 충돌 시 TCP 연결을 유지하며 충돌 해소 후 자동 재시도합니다.
- Sable 등록 helper와 인증 터널은 상주 게임호스트가 소유합니다. 실제 TCP 연결·인스턴스·peer IP·토큰·권한에 UDP를 묶습니다. 제어 계층 재접속으로 기존 경로를 끊지 않습니다.
- 포트 표에 프로토콜을 표시합니다. 중계 컴퓨터로 **공유 게임 포트 TCP + 같은 번호 UDP(Sable 사용 시) + 별도 실행기 연결 포트 TCP**를 포워딩하세요. SRV는 공유 게임 포트를 가리킵니다. 공유기/DNS 설정을 자동 변경하지 않습니다.

## 업데이트·적용 안내

관리 앱, 중계 실행기, 게임 실행기 및 **상주 게임호스트를 모두 Beta14로 업데이트**해야 직접 UDP를 켤 수 있습니다. 제어 계층만 새 버전이고 상주 호스트가 구버전이면 지원 대기로 표시합니다. 호스트 자체 교체에는 기존 유휴 조건이 유지됩니다. 활성 중계 때문에 대기하면 정상 점검 시간에 직접 중계를 끄고 게임·전송이 끝난 뒤 호스트 업데이트를 적용하세요.

공통 포트·주소·DNS를 설정한 뒤 직접 카드에서 최초 실행기를 선택해 저장하세요. 로컬 설치기의 **게임 중계 사용 허용 (TCP / Sable UDP)**이 필요합니다(구버전 표기: TCP 중계 사용 허용). Sable은 추가 옵션이며 기본 꺼짐입니다. 사용자가 설정 파일을 직접 만들 필요가 없습니다.

지원 범위는 **NeoForge1.21.1 / Sable2.0.6**입니다. 보조 모드는 다음 정상 게임 시작 때 준비합니다. 실행 중인 게임에 주입하거나 강제 재시작하지 않습니다. UDP 미연결 시 TCP 대체 통신을 사용합니다.

중계↔게임 실행기 구간은 기존 인증·암호화 **TCP 터널**입니다. 플레이어 구간의 UDP를 관리 Mac 없이 전달하지만 순수 종단 UDP는 아니며 회선 손실 시 지연이 늘 수 있습니다. TCP 연결 검사는 UDP 외부 접속 성공을 증명하지 않습니다.

## 검증

관련 백엔드 고유61개, UI6개, TypeScript/Vite production build, 격리 설치기 검증 통과. 상주 호스트·fake game으로 controller 분리 중 TCP/UDP 왕복과 재연결 후 helper 인증 유지 확인. 최초 기존 TCP 왕복1회 실패는 이후 반복 실행에서 재현되지 않았으나 원인 미확정으로 검증 문서에 남겼습니다.

전체 테스트 및 다른 운영체제 실행은 사용자 요청으로 생략했습니다. 실제 별도 컴퓨터·공유기·외부 인터넷·설치 Minecraft 접속은 미실행입니다. 자세한 범위와 실패 기록은 `docs/testing/beta14-direct-relay.md`를 참고하세요. stable/latest와 기존 게시 파일은 유지됩니다.

릴리즈 통합 JAR 빌드와 격리 서명 업데이트·변조 거부·시작 실패 롤백·프로필 폴더 선택 검사도 통과했습니다.
