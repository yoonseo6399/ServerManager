# Server Manager 0.7.0-beta.29

## 중계 전송 지연 격리

- 플레이어/게임 소켓마다 독립된 쓰기 큐를 사용해 한 접속의 수신 지연이 공유 터널 수신 루프를 막지 않도록 개선했습니다.
- 터널 송신은 접속별 순서를 유지하며 번갈아 처리합니다. 큐 메모리와 대기 시간을 제한하고, 특정 접속의 과적체는 해당 접속만 정리합니다.
- 소켓 쓰기가10초 이상 정체되면 종료 이유를 기록합니다. 공통 물리 터널 자체가 막힌 경우에는 해당 터널을 재연결하며, 회선/공유기 문제까지 해결한다고 보장하지 않습니다.
- 정상 종료 직전 대기 중인 응답을 전달한 뒤 소켓을 닫고, 전달이 끝날 때까지 상주 서비스 유휴 교체를 보류합니다.

## 상세 진단 로그

- 실행기 홈의 `logs/relay-host.jsonl`과 `logs/relay-runner.jsonl`에 UTC 시각, 연결/접속/인스턴스 식별자, 송수신량, 마지막 활동 시각, 큐·쓰기 지연, 종료 이유와 원인 예외 타입을 기록합니다.
- 60초 상태 기록과5MiB 파일 회전(백업4개), 비동기·유한 진단 큐를 적용했습니다. 인증 키·티켓·게임 패킷 내용은 기록하지 않습니다.
- 중앙 연결 실패도 단순 CompletionException 대신 시각과 원인 예외 타입을 남깁니다. 자세한 해석은 `docs/relay-diagnostics.md`를 참고하세요.

## 폴더 업로드 표시

- 폴더 하나를 진행 카드 하나로 표시하며 내부 파일/하위 폴더 목록으로 화면을 채우지 않습니다.
- 폴더 이름, 전체 진행률·완료 파일 수·현재 단계·실패 수를 표시합니다. 새로고침 후에도 같은 폴더로 묶어 복원합니다.
- 폴더 취소 시 취소 가능한 현재 작업과 남은 파일을 중단하며, 이미 반영 중인 파일까지 되돌렸다고 표시하지 않습니다.

## 적용과 검증 범위

관리웹 업데이트로 폴더 UI가 적용됩니다. 중계 개선은 **중계/게임 실행기의 상주 게임호스트도 beta.29로 교체**되어야 적용됩니다. 게임을 정상 종료한 뒤 구성요소 업데이트 상태에서 `GAME_HOST` 버전을 확인하세요. 이번 게시 작업에서 운영 Minecraft나 서비스를 강제 재시작하지 않습니다.

기능 브랜치에서 관련 backend 중계68개·업로드10개, 브라우저12개와 TS/Vite·JAR 빌드를 확인했습니다. 실제 암호화 TCP에서 느린 플레이어/게임 백엔드 격리, 다른 접속 유지,512KiB 응답 직후 EOF 바이트 보존을 검증했습니다. 통합에서도 backend78개·브라우저21개·보안11개, 실행기 설치·TS/Vite·JAR 빌드가 통과했습니다. 중앙 단절100회 반복도 통합 버전에서 통과했습니다.

초기 회귀에서 중앙 단절 시험이 한 번 실패했으나 진단을 보강한 단독100회·관련 suite100회에서는 재현되지 않았습니다. 원인 미확정 기록을 보존하며 해결됐다고 단정하지 않습니다. 기존 실제 동시 끊김의 원인은 여전히 미확정입니다. 전체 suite·다른OS 실기·외부망/공유기 검증은 생략합니다. 게시 자산을 다시 다운로드해 해시 비교하지 않습니다.
