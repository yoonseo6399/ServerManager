# Server Manager 0.7.0-beta.7

Gemma 4 12B·31B와 Qwen3-Coder 30B를 로컬 에이전트 선택지에 추가했습니다. 기존 Qwen3 14B·30B와 사용자 기본값은 유지됩니다.

- Discord `/agent setting default:`와 `/agent run model:`, 관리 웹 **AI 비서·에이전트 → 로컬 LLM (Ollama)**에서 선택합니다.
- Coder의 Thinking 미지원은 요청 시 자동으로 끕니다. 개인 Thinking 설정은 보존하므로 다른 지원 모델로 돌아가면 다시 적용됩니다.
- 지원 모델을 전환하면 이전 지원 모델을 먼저 메모리에서 내립니다. 관련 없는 Ollama 모델은 건드리지 않습니다.
- 기존 독립 위험 검토·명시적 승인·중지·문맥 압축·실행기 동의 정책을 유지합니다.
- 읽기 원문의 줄바꿈 형식·마지막 줄바꿈 개수·표시용 줄 번호·부분 조회 여부를 명시합니다. 모델의 원문 보존을 보장하는 기능은 아닙니다.

**관리 앱과 실제 추론 실행기를 모두 업데이트하세요.** 모델은 사용할 실행기에서 별도로 설치해야 합니다. 이 Mac에는 요청에 따라 세 모델을 다운로드했습니다. 다른 실행기에는 자동 설치하지 않습니다.

```sh
ollama pull qwen3-coder:30b
ollama pull gemma4:12b
ollama pull gemma4:31b
```

31B는24GB 컴퓨터에서 메모리 여유가 작을 수 있습니다. 실행 창8192/출력4096은 유지되며 최대 문맥 전체를 적재하지 않습니다.

관련 기능 회귀62개와 모델 선택 UI1개가 통과했습니다. 실제 임시 파일 중간 삽입과 Python 별 출력 결과:

| 모델 | 파일 전체 보존·지정 위치 삽입·재조회 | Python 별 출력 실제 실행 |
|---|---|---|
| Qwen3 30B | 통과172.7초 | 통과50.2초 |
| Qwen3-Coder 30B | 통과45.5초 | 통과1.9초 |
| Gemma 4 12B | 통과62.1초 | 통과36.2초 |
| Gemma 4 31B | 메모리 한도로 적재 거부 | 적재 거부 |

31B는 이 Mac에서 필요18.0GiB/가능15.5GiB라고 Ollama가 거부했습니다. 이 오류는 이제 필요한 용량과 함께 표시합니다. 메모리 한도를 변경하지 않았습니다. 다른 추론 실행기에서 사용할 수 있도록 선택지는 제공합니다.

파일 수정은 마지막 줄바꿈까지 실제 전체 바이트를 비교했습니다. 각 모델 과제당1회, Qwen GGUF Q4_K_M/Gemma MLX, 지원 모델 Thinking=true/Coder=false이므로 전체 성능 순위가 아닙니다. 기존 앱과 스왑도 비우지 않았습니다. 최초 실패와 생성 코드까지 [실측 보고서](https://github.com/yoonseo6399/ServerManager/blob/v0.7.0-beta.7/docs/benchmarks/local-models-2026-10-17.md)에 보존했습니다. 전체 테스트와 다른 OS 실행 검증은 사용자 요청으로 생략합니다. 실제 Discord 전송 시험은 하지 않았습니다.
