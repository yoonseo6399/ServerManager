# Server Manager 0.7.0-beta.10

beta.9를 기반으로 한 구조 변경 베타입니다. 새 사용자 기능은 `/permission` 하나이고, 나머지는 기존 동작을 유지한 채 코드를 모듈 구조로 바꿨습니다.

## Discord 봇
- **모듈 구조**: 음악, AI 에이전트, AI 모델, 파일 비서가 봇의 모듈로 분리되었습니다. 명령과 버튼은 이름과 접두사로 해당 모듈에만 전달되고, 한 모듈의 오류가 다른 기능으로 퍼지지 않습니다. 새 기능을 추가하는 방법은 `docs/architecture/discord-modules.md`에 있습니다.
- **`/permission`** (최고 관리자 전용): 모듈이 선언한 권한을 역할별로 거부·허용하고, 규칙·변경 기록을 볼 수 있습니다. 지금 연결된 권한은 `music.use`, `agent.use`, `ai.cloud`, `ai.local`, `assistant.use`이며 **모두 기존 동작이 기본값**입니다. 거부 규칙을 만들 때만 새 동작이 생기고, 허용 규칙은 기존 접근 규칙을 우회하지 못합니다.
- **로컬 위험도 상한**: 관리 컴퓨터의 `security/discord/permission-ceiling.json`으로만 정하며(기본 MEDIUM) Discord 명령으로는 올릴 수 없습니다. 상한을 넘는 권한은 최고 관리자도 쓸 수 없습니다.
- **서버 제어 통로**: Discord가 Minecraft 서버를 제어하는 경로가 `ServerControlPort` 하나로 모였습니다. 이후 봇을 별도 프로세스로 분리할 때 같은 인터페이스를 HTTP로 제공합니다(설계: `docs/architecture/server-control-api.md`).

## 내부
- 소스 파일을 기능별 폴더로 정리했습니다(패키지 이름은 그대로). 폴더 구조는 `docs/architecture/source-layout.md`.
- CI의 실행기 설치 검사 경로 필터를 새 폴더에 맞게 고쳤습니다.

## 업데이트 시 참고
- 설정 파일 형식은 바뀌지 않았습니다. `/permission`을 쓰면 `security/discord/`에 `permission-grants.json`, `permission-audit.jsonl`이 새로 생기며, 이전 버전으로 되돌려도 다른 파일에는 영향이 없습니다.

## 검증
- 새 테스트 `PermissionServiceTest` 14, `DiscordModuleRegistryTest` 8, `DiscordPermissionModuleTest` 4가 통과했습니다. 절차는 `docs/testing/beta10-test-guide.md`.
- Windows에서는 `DiscordTest`가 POSIX 권한 문제로 실행되지 않아 macOS CI에서 확인이 필요합니다. 실제 Discord 서버에서의 수동 확인은 아직 하지 않았습니다.
