# Server Manager 0.7.0-beta.13

모드 조회·가져오기의 부분 실패 처리와 의존성 강제 활성화를 개선한 **Beta**입니다.

- 직접 업로드한 모드나 Modrinth 조회 실패가 섞여 있어도 파일 목록을 먼저 표시하고, 성공한 조회 결과는 보존합니다. 불완전한 정보는 경고하며 **모드 목록 다시 불러오기**로 재시도할 수 있습니다. 최초 실패 뒤 로딩 표시가 계속되던 문제를 수정했습니다.
- 모드팩 가져오기에서 의존성을 완전히 확인하지 못하면 JAR 자동 제외를 보류하고 원본을 유지하며 경고합니다. 일부 메타데이터 때문에 전체 가져오기를 중단하지 않습니다.
- 다른 모드 사이의 기존 충돌 때문에 무관한 모드를 다시 켜지 못하던 검사를 수정했습니다. 정확한 필수 버전 자동 복원은 유지합니다.
- 활성화가 의존성·비호환 검사로 막히면 사유 옆 주황색 **의존성 무시하고 그냥 켜기** 버튼을 표시합니다. 경고와 변경할 파일을 확인한 뒤 선택한 모드만 강제로 켭니다. 이 경우 서버 시작 실패나 충돌 가능성이 있습니다.
- 강제 활성화로도 실행 중/파일 인계 제한, 관리 권한, 오래된 목록·파일 변경 검사, 대상 파일 충돌·백업·복구를 우회하지 않습니다.

사용자 동의로 실제 232개 모드 해시를 조회했고, 확인된 224개와 미등록 8개 모두 목록에 유지됐습니다. 최초 운영 오류 당시의 정확한 예외는 확보하지 못해 직접 원인으로 확정하지 않았습니다. 운영 모드를 실제로 변경하거나 재시작하지 않았습니다.

고유 백엔드 기능 회귀54개 중51통과·외부 opt-in3개 생략, 별도 실제 Modrinth 조회1개와 브라우저4개, React production build를 통과했습니다. 전체 테스트와 다른 운영체제 실행은 사용자 요청에 따라 생략했습니다. 기존 서명 방식으로 새 버전 자산을 게시하며 stable 최신 버전은 유지합니다.

[검증 보고](https://github.com/yoonseo6399/ServerManager/blob/v0.7.0-beta.13/docs/testing/beta13-mod-inventory.md)
