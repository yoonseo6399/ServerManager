# Server Manager 0.7.0-beta.26

## 추가

- **서버 ZIP 가져오기**: mrpack 옆에서 기존 서버 폴더를 업로드해 새 서버로 등록합니다. 월드·모드·설정을 보존하며 바깥 폴더 인식, 서버 정보 확인, 업로드·압축 해제 진행률, 취소·같은 화면에서 이어 올리기를 지원합니다. 가져오기만으로 서버를 실행하지 않습니다.
- ZIP 업로드 한도는20GiB, 해제 한도100GiB이며8MiB씩 전송합니다. 경로 이탈·중복·CRC·실제 해제량·업로드 계정·CSRF를 검사합니다. RAR/7z/tar.gz·Nextcloud 직접 연동은 포함하지 않습니다.
- **Simple Voice Chat 직접 중계**: 직접 중계 화면에서 서버마다 공개/내부 음성 UDP 포트를 지정합니다. 모드 설정은 백업 후 다음 정상 시작에 반영하고 해제 후 다음 시작에는 복원합니다. 모드 설치와 공개 UDP 포트포워딩은 별도로 필요합니다.
- **한 실행기의 여러 서버 포트 분리**: 실행기 배정·다음 원격 시작 때 충돌하는 내부 게임 포트를 자동 분리합니다. 시작 준비 중인 다른 서버의 Query·게임·음성 포트를 예약하며, 이미 실행 중인 다른 서버의 포트·PID는 변경하지 않습니다.

## Java 보안 런타임

새 설치 패키지의 Java21 보안 하한을21.0.13으로 올리고, 관련 인증서 보완을 패키징 단계에서 적용·검증합니다. Mac은 Eclipse Temurin, Windows는 공식 Temurin API에 보안 버전이 없어 고정 SHA-256으로 확인한 **Azul Zulu CA JRE21.0.13+9**를 사용합니다. [Azul 공식 패키지 메타데이터](https://api.azul.com/metadata/v1/zulu/packages/1953be22-1404-4175-8257-0dcb1ac0dffb), [보안 공지](https://www.oracle.com/security-alerts/alert-cve-2026-91403.html).

**관리 웹의 JAR 자동 업데이트는 기존 내장 Java를 교체하지 않습니다.** 기존 설치의 Java까지 갱신하려면 관련 게임·상주 서비스·실행기를 정상 종료한 뒤 새 설치 패키지로 갱신해야 합니다. 실행 중인 상주 호스트의 새 기능은 해당 호스트가 갱신된 뒤 사용할 수 있습니다. 이 릴리즈 게시 과정에서 운영 서비스를 자동 재시작하지 않습니다.

## 검증과 한계

통합 Kotlin/bootJar·프런트 빌드, 관련 백엔드122개·웹11개·Java 보안11개 검사를 통과했습니다. 패키징·bootstrap·서명은 게시 CI에서 추가 확인합니다. 사용자 요청으로 전체 백엔드 테스트는 생략합니다.

기능 브랜치에서는 실제257MiB ZIP33청크 업로드, 원문·한글 MOTD·EULA 보존, 테스트용 Java JAR의 명시적 시작/정상 종료, 한 상주 호스트의 게임 대역 JVM2개 및 동시 음성40패킷 왕복·한쪽 종료 후 다른 연결 유지를 검증했습니다. 실제 Minecraft 다중 서버·마이크 음질·공유기/외부 인터넷·20GiB/100GiB 실용량·Windows 실행 시험은 미실행입니다. Windows 패키지 구조·Java 버전·인증서 검증은 실제 Windows 실행과 구분합니다.
