# Server Manager 0.7.0-beta.24

관리웹과 실행기를 함께 업데이트하세요. 기존 게임은 종료하지 않고 제어 계층 업데이트 후 PID를 확인해 새로운 종료 인계 경로에 연결할 수 있습니다. 게임호스트 자체 교체와 구형 비상주 게임은 기존 대기 조건을 유지합니다.

- 파일 관리자·모드 화면·로그 조회/다운로드가 배정된 실행기의 실제 원본을 사용합니다. 원격 실패 시 중앙 복사본을 대신 수정하지 않습니다. 실행·전송 중에도 파일 저장/업로드/이동/삭제와 모드 켜기·끄기를 허용하며, 원본 백업·revision 충돌·서버 루트/링크 검사를 유지합니다. 모드 변경은 다음 서버 시작부터 적용됩니다.
- 종료 후 변경되지 않는 복사본을 확보하고 관리 서버가 접수하면 같은 실행기에서 다시 시작할 수 있습니다. APFS에서는 copy-on-write를 시도하고 다른 환경은 일반 복사를 사용합니다. 원본이 다시 실행되는 동안 복사본 전송을 진행하고, 재접속·이어받기·여러 종료 순서를 보존합니다. 이전 전송 완료가 새 게임의 상태/PID/연결 표식을 지우지 않습니다. 다른 실행기로 이동하려면 최신 전송 완료를 기다립니다.
- 전송 서버의 파일별 잠금을 분리해 병렬 업로드가 실제 병렬로 처리되도록 하고, 파일·로그 요청이 전체 전송 잠금을 기다리지 않게 했습니다.
- 모드 목록 해시를 파일 식별 정보로 재사용하고, 토글 후 외부 Modrinth 재조회를 제거했습니다. 미등록/조회 실패 모드는 계속 표시하며 의존성 무시 버튼도 유지합니다. 격리 문제 모드 검사는 정지·동기화 완료와 원본/복구본 모드 일치를 확인합니다.
- 시스템 메뉴에 관리 앱 재시작, 실행기 목록에 지원 여부와 요청/재연결/완료/실패 상태를 추가했습니다. 소유자/기기 등록자 권한·최근 패스키·CSRF 및 실행 중 작업의 거부 조건을 유지합니다. 새 boot ID를 확인한 뒤 완료로 표시합니다.
- 로그는 기본 펼침으로 StackTrace와 이어지는 원인을 묶고 시간 구간별로 logger를 분류합니다. 프레임별 Mixin 상세와 주변 스택 확장, 모바일 가로 스크롤, 기존 전체 원문 검색 모드를 지원합니다. 50ms 시간 구간은 실제 Minecraft tick 번호가 아닙니다.
- 크래시 리포트를 주기적으로 다시 탐색해 최신 보고서 열기/파일 다운로드를 안내합니다. 실행기 원본 로그와 Discord 크래시 첨부 경로를 수정했습니다.

## 검증

관련 backend 고유79건 중78통과·조건부1미실행, 브라우저19건 통과. Kotlin/TypeScript/Vite/bootJar 및 실제 로컬 HTTP500 전송 복구·새 게임 유지·실파일 원문/백업·권한/경로/충돌을 검증했습니다. 실제 모드234개 읽기 전용 스캔: 첫986ms, 재조회3ms(804MB 재읽기0). 전체 테스트는 사용자 요청으로 생략했습니다. 여러 실제 컴퓨터의 새 전송 경로, 다른 OS 실행, 실제 Discord 첨부 및 전원 차단 시험은 미실행입니다.

Java 프로세스 조사에서 과거 임시 테스트 호스트 잔여물을 확인했습니다. 현재 호스트 시작·정리 시험 뒤 새로 남은 JVM은0개였으며 운영 프로세스를 종료하지 않았습니다. 자세한 범위·중간 실패 수정은 docs/testing/operations-controls.md에 기록했습니다.

관리 앱/실행기 설치 패키지·서명된 자동 업데이트를 제공합니다. 게시 후 파일 재다운로드 해시 시험은 수행하지 않습니다.
