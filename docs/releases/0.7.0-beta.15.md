# Server Manager 0.7.0-beta.15

Mac 실행기에서 상주 게임호스트 업데이트가 “새 상주 서비스를 시작하지 못했습니다: 이전 버전”으로 실패하거나, 실제 새 호스트가 실행된 뒤에도 실패 표시가 남는 문제를 수정했습니다.

- launchd 자동 재실행 작업을 남긴 채 PID만 종료해 구버전이 부활하던 원인을 수정했습니다. 기존과 같이 게임·중계 유휴를 인증 확인하고, 해당 홈의 launchd 작업과 실제 PID를 대조한 뒤 작업을 제거합니다. 다른 PID의 작업은 종료하지 않습니다.
- 새 호스트의 실제 PID·시작 시각·목표 버전·수신 포트를 최대30초 기다려 확인합니다. 오래된 endpoint 파일을 새 시작 성공으로 오인하지 않습니다.
- 제한 시간 이후 새 호스트가 연결되면 기존 실패 상태를 정상으로 갱신합니다. 같은 상태의 로그는 반복하지 않으며 다른 버전의 실패를 숨기지 않습니다.

제어 계층은 기존 상주 게임을 유지하며 업데이트할 수 있습니다. 상주 호스트 자체 교체는 게임·파일 전송·중계 접속이 끝날 때까지 기다립니다. 게임 종료나 유휴 제한을 강제로 우회하지 않습니다.

실제 임시 launchd 작업으로 수정 전 실패를 재현했습니다. 관련27개 기능 테스트와 실제 패키징 제어 계층의 게임PID·통신 유지/실패 상태 복구 검증을 통과했습니다. 전체 테스트·다른OS 실행은 사용자 요청으로 생략했습니다. 운영 컴퓨터 적용 결과는 게시 후 별도 확인합니다. 자세한 검증은 `docs/testing/beta15-host-update.md`에 기록했습니다.

릴리즈 통합 Kotlin/React production build, bootJar 및 격리 서명 업데이트·변조 거부·시작 실패 롤백·프로필 선택 검사도 통과했습니다.
