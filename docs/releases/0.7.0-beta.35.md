# 0.7.0-beta.35

- 실행기의 종료 보고를 전체 종료 복사본 준비보다 먼저 처리합니다. 전송이 느리거나 실패해도 Discord에서 종료 코드·사유를 먼저 확인할 수 있고, 재시도·접수 완료에 따른 중복 종료 알림을 막습니다.
- 관리웹 상태가 정지로 잘못 남았어도 미완료 실행의 식별자를 새 시작 요청으로 덮어쓰지 않습니다. 종료 복사본은 기존처럼 현재 실행 세대와 실행기 권한을 검사하며, 오래된 복사본을 무조건 수락하지 않습니다.
- JVM 자체가 종료되는 `hs_err_pid*.log`를 감지하여 네이티브 크래시로 구분하고, 로그 조회·Discord 요약/첨부를 지원합니다. 링크·경로·8MiB 제한은 유지합니다.
- HTTP409 등 전송 실패에서 서버가 보낸 제한된 오류 사유를 표시합니다. 종료 접수 후 응답이 유실돼도 재접수하여 복구할 수 있습니다.
- 새 종료 보고 필드는 기능 협상으로 이전 관리웹과 호환합니다.

관리웹과 실행기 제어 계층을 함께 업데이트하면 전체 개선이 적용됩니다. 게임호스트 교체나 Minecraft 자동 재시작은 포함하지 않습니다. 이미 어긋난 실행 식별자는 무조건 초기화하지 않으며, 정지 상태와 보존 복사본을 확인한 뒤 복구해야 합니다.

## 검증

관련 7클래스 기능 테스트45개 통과. 실제 HTTP 응답 유실·청크500·재시도와 새 게임 실행 중 이전 복사본 반영, 종료 알림 중복 방지, 잘못된 실행 세대 거부, 네이티브 로그 경로·링크 검사를 포함합니다. Kotlin/bootJar·프런트 빌드 및 서명·패키징은 릴리즈 파이프라인에서 확인합니다. 전체 테스트·다른 OS 실기·장시간 Minecraft 운전·공개 자산 재다운로드 해시 비교는 생략합니다.

## 별도 운영 진단: Spark

macOS ARM에서 설치된 Spark1.10.124의 async-profiler3.0이 `ThreadFilter::accept`에서 종료되는 기록을 확인했습니다. 스택과 음수 스레드 ID가 공식 [async-profiler #1143](https://github.com/async-profiler/async-profiler/issues/1143)과 일치합니다. 설치 JAR의 `backgroundProfilerEngine: "java"` 지원은 확인했으나 이 릴리즈는 Spark 모드나 사용자 설정을 자동 교체하지 않습니다. 수정 후 장시간 재발 여부는 검증하지 않았습니다.
