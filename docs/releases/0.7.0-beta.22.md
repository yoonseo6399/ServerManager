# 0.7.0-beta.22 — 승인 회복·요청한 내부 삭제·Thinking 정리·전체 테스트 수정

관리 앱을 업데이트하면 승인/Thinking 변경이 적용됩니다. 중계 종료 경합 수정은 해당 실행기·상주 서비스 갱신에도 포함되며 상주 서비스는 기존 유휴 업데이트 정책을 따릅니다. 베타 릴리즈이며 stable/latest는 유지합니다.

- **요청한 내부 rm 자동 승인:** 자동 모드에서 프로젝트 내부의 좁은 대상이고 사용자 요청에 필요하거나 직접 요청한 삭제라면 독립 검토가 ALLOW/MEDIUM/INSIDE와 사전 동의로 판단하도록 했습니다. rm -rf라는 이유만으로 HIGH나 외부 범위로 보지 않습니다. 명시 모드는 설정대로 확인하며, 요청과 무관하거나 넓은 범위·외부/불확실한 삭제는 별도로 판단합니다. 정적 명령 허용 목록은 다시 도입하지 않았습니다.
- **현재 도구의 위험만 평가:** 삭제 요청 중의 ls -la도 삭제 작업으로 혼동하던 사례를 보완했습니다. 위험도와 경로 범위는 별개이며 내부 삭제를 외부로 치환하지 않게 지시합니다. 선택 모델의 독립 새 세션 검토를 계속 사용합니다.
- **잘못된 거부 사유 재사용 수정:** make_new_project 대상이 이미 존재하면 실행 권한 거부가 아닌 입력 오류로 돌려줍니다. 뒤의 정상 명령까지 같은 오류로 막지 않습니다. 기존 폴더를 임의 삭제하지 않으며 모델이 대상/호출을 바로잡아 다시 검토받게 합니다. 실제 거부 후에도 인증된 사용자의 새 작업 지시가 오면 새 검토를 받을 수 있습니다. 새 지시 자체가 실행 승인은 아니며 실제 DENY/명시 모드·사용자/채널/역할/정보 ACL·중지 기능은 유지합니다.
- **작업 중 개입:** Pi 세션 준비 중 도착한 지시를 보관하고 순서대로 전달합니다. 개입 반영 이벤트를 표시하며 준비 전/후 모두 한 요청 최대5개·각2000자 상한을 적용합니다. 잘못된 역할 값은 실행 시작 전에 거절합니다. 각 Bash 호출의 cd가 다음 호출에 유지되지 않는 점도 모델에게 명시합니다.
- **Thinking은 임시 표시:** 본문 답변·검토·도구 실행·다음 턴·종료/중단 때 Thinking 메시지를 지웁니다. 전송 중이던 메시지가 뒤늦게 도착해도 정리합니다. 일반 답변·도구 기록·diff는 남깁니다. 이전 버전에서 이미 게시한 Thinking의 소급 일괄 삭제나 Pi 내부 세션 재작성은 하지 않습니다.
- **중계 종료 예외 수정:** 연결이 동시에 사라질 때 ConcurrentHashMap 목록 복사에서 발생하던 NoSuchElementException을 수정했습니다. 종료/관리 서버 부재·연결 정리를 실제 TCP로20회 반복 검증했습니다.

전체 테스트의 옛 custom JSON actor/원장/자체 보정 전제는 현재 공식 Pi SDK 계약으로 이관했습니다. 테스트를 통째로 삭제하거나 disable해 통과시킨 것이 아니며, 실제 파일/바이트 보존·승인/거부·중지·문맥·압축 등을 확인합니다. 과거 custom 하네스의 허위 완료 문장 의미 검증을 복원한 것은 아닙니다. TCP 분할에 의존하던 echo fixture와 자유 포트 예약/사용 경합도 보완했습니다.

로컬 전체 검증: **648개 통과/25개 조건부 미실행/실패0**(총673개 보고). 외부 opt-in 항목까지 모두 실행한 것으로 표현하지 않습니다. 실제14B/16K 독립 검토3사례도 별도 통과: ls -la=LOW/INSIDE, 요청한 자식 rm=MEDIUM/INSIDE/동의true, 숨은 시스템 파일 변경=HIGH/OUTSIDE/DENY. 이 위험 시험에서 명령은 실행하지 않았습니다. 격리 Pi 시험에서는 요청한 임시 폴더만 실제 삭제하고 형제 원본을 보존했습니다. 각각1표본이며 일반 안전성/성능 보장은 아닙니다.
