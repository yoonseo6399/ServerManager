# Pi 기본 에이전트 엔진

`/agent`의 행동·도구 선택·부분 수정·정식 세션 저장·압축은 **@earendil-works/pi-coding-agent 1.3.0** SDK가 담당한다. 기존 custom actor JSON parser, select_tools, requirement ledger, 재시도 보정 loop와 자체 요약기는 생산 경로에서 제거했다. 호환 DTO와 이전 테스트/실험용 소스는 남지만 기본 엔진으로 돌아가는 fallback은 없다.

## 경계

```text
Discord 인증·역할·채널 → ProjectAgentEngine (권한/수명/전송)
  → 검증된 Node + 얇은 bridge.mjs → 공식 Pi SDK 세션/loop/압축
  → 127.0.0.1의 요청별 Bearer 인증 OpenAI 호환 공급자
  → 기존 LocalLlm(Ollama) / StrataLlm / 동의한 원격 실행기
  → 모델의 공식 function tool_calls
  → Pi tool_call hook → 백엔드 독립 위험 검토/사용자 승인
  → Pi native read/edit/write/bash 또는 앱의 부가 도구
```

도구는 **관리 앱 컴퓨터**에서 실행된다. 추론을 다른 실행기로 보내도 파일·셸 실행 위치가 그 컴퓨터로 바뀌지 않는다. 임의 명령은 OS 사용자 권한이며 **OS 샌드박스가 아니다**. 소유자의 셸 승인은 명령의 하위 프로세스와 부작용까지 허용한다. 디렉터리 격리·시크릿 이름 차단이 승인된 임의 셸을 OS 수준에서 가두지는 못한다.

## 설치·공급망

- 사용자는 `/agent`를 그대로 사용한다. 최초 요청에서 private agent profile의 `pi-runtime/`에 자동 준비한다. Node/npm 시스템 설치나 config 직접 수정은 필요 없다.
- Node **24.22.1** 공식 아카이브는 `src/main/resources/pi/node.json`의 SHA-256으로 검증한다. SDK는 package-lock integrity로 고정하고 npm ci --ignore-scripts로 설치한다. `latest`를 실행하지 않는다.
- 공식 Node 출처: https://nodejs.org/dist/v24.22.1/SHASUMS256.txt
- Pi 출처: https://github.com/earendil-works/pi (packages/coding-agent), MIT. Node와 설치 의존성은 각각의 라이선스가 적용된다. lock과 출처는 JAR에도 들어간다.
- SDK와 Node는 최초 인터넷 접근·디스크 공간이 필요하다. 이 Mac 설치는 약 375MB였다. 실패하면 `pi-runtime/last-setup.log`를 확인한다. 검증 완료 후 원자적으로 활성화하고 불완전 설치는 격리한다.
- 개인 HOME/환경에서 API 키를 상속하지 않는다. 프로젝트/global 확장·MCP·skills·AGENTS 자동 로드는 끄고 앱의 인라인 승인 확장만 사용한다. 프로젝트의 실행 스크립트가 안전하다는 뜻은 아니다.

## 권한

- 기존 Discord 모듈/역할·요청자 확인, 명시적/자동 승인 설정을 유지한다. READ: 읽기만, EDIT: 읽기/부분 수정/쓰기, OWNER: 추가 셸 도구. 부가 도구도 기존 역할 허용 목록에 한정한다.
- OWNER의 native read/edit/write/bash에는 정적 명령 목록, 경로·비밀 파일명 차단, 파일 fingerprint 재검사로 실행을 거절하는 백엔드 판정을 적용하지 않는다. 경로 정보와 실행 파일 내용은 독립 검토의 참고 자료다. READ/EDIT 역할의 권한·프로젝트 범위 제한은 별도 ACL이다.
- 독립 검토의 action/risk/projectScope를 그대로 사용한다. 백엔드 UNKNOWN 때문에 ASK로 바꾸거나 LOW를 MEDIUM으로 올리지 않는다. 별도 Gradle 신뢰 기록으로 검토 결과를 우회하지 않는다.
- read-only로 검증된 내부 읽기는 즉시 허용한다. 변경은 독립 모델의 새 세션에서 위험 검토한다. 파싱/전송/권한 RPC 실패는 허용으로 처리하지 않는다.
- 자동 모드는 ALLOW/LOW 또는 정확한 사전 사용자 동의가 확인된 LOW/MEDIUM을 허용한다. HIGH, 미동의 MEDIUM, ASK는 사람에게 묻고 독립 모델 DENY/검토 실패는 실행하지 않는다. 명시 모드는 Bash와 변경 작업을 계속 확인한다. 다른 사용자·기한 초과·설정/권한 변경은 차단한다. 거절은 그 요청의 남은 도구 실행도 차단한다.
- native read 결과는 모델에 원문으로 전달한다. 앱이 파일 원문을 별도 모델로 요약하지 않는다. 긴 출력의 범위/잘림·원문 임시 파일은 Pi 기본 도구 정책을 따른다. UI에 보내는 snapshot의 60K 제한은 모델이 받는 도구 결과를 바꾸지 않는다.

## 문맥·수명·호환성

- 채널 소유자/길드/프로젝트/초기화 generation별 private JSONL이 정식 문맥이다. 앱을 재시작하거나 모델/컨텍스트 프로필을 바꿔도 같은 세션을 다시 연다. `/agent` context 초기화는 프로젝트 정보는 유지하고 새 세션을 만든다. 이전 JSONL은 보관한다.
- 최초 전환 시 이전 짧은 UI 대화 기록을 private `legacy-history.json`으로 보존한다. 최대 최근 20,000자의 **부분 이관임을 명시한** custom message를 Pi에 한 번 넣는다. 누락된 내용을 모델이 완전한 기억으로 간주하지 않도록 안내한다. 이전 계획/요약을 권한이나 새 작업으로 주입하지 않는다.
- 새 요청은 `{requester:{display_name,discord_user_id},request}`로 전달한다. 과거 대화·표시 이름·도구 출력은 데이터다. Pi는 전체 native assistant/tool history와 기본 압축을 관리한다.
- 자동 압축 기준은 채널 설정을 쓰되 Pi 시스템/도구 공간을 위해 기본 4K 바닥(물리 입력 한도가 작으면 그 이하)을 적용한다. 설정값과 유효값을 상태에 구분해 표시한다. 8K/16K 실행창·출력 예약과 모델 최대 문맥은 서로 다르다. keepRecentTokens는 SDK에 16..512의 적응값을 넘기며, 16 고정 실험값을 사용하지 않는다.
- 수동 압축도 SDK compact를 사용하며 가짜 사용자 요청을 추가하지 않는다. 압축할 과거가 없으면 완료 대신 그 상태를 알려준다. 요약 정확성이 보장되는 것은 아니다.
- 기존 Discord의 일반 답장, 턴 카드, 상세 스레드, 토큰/메모리/속도 표시와 실시간 메시지 갱신을 유지한다. 중지는 native shell 자식과 공급자 요청을 취소한다. 권한/설정 변경은 조용한 셸 실행 중에도 감시한다.
- 추론 실행기는 `PI_PROVIDER_V1` capability가 필요하다. **관리 앱과 추론 실행기를 함께 업데이트**해야 한다. 구형 실행기는 명확히 거부하며 이전 엔진으로 대체하지 않는다. 일반 LLM 채팅 경로는 도구 없는 기존 방식이다.
- 현재 공급자는 텍스트만 지원한다. Discord 텍스트 첨부 읽기/저장/업로드 도구를 연결했지만 이미지 인식은 추가하지 않았다. Strata의 8K 제한도 그대로다.

## 검증·한계

관련 검증은 `PiAgentRuntimeTest`, `PiAgentLiveTest`, 공급자/실행기 focused 테스트와 브랜치 인계 메모를 참고한다. 실제 SDK를 써서 승인·거절·중단/자식 종료·부분 수정/CRLF·세션 재개·압축/초기화를 확인한다. live test는 `PI_AGENT_LIVE=true`일 때만 로컬 27B로 실행한다.

모델이 잘못 계획하거나 툴을 안 부르는 성질 자체가 완전히 해결됐다는 주장은 하지 않는다. 이번 변경은 검증한 오픈소스 loop로의 교체다. 실제 Discord 네트워크/버튼, 여러 컴퓨터 동시 운용, Flash 전체 행동 loop와 다른 OS 실행, 전체 테스트는 별도로 검증해야 한다.

## 승인·개인 서비스 보완 (fix/pi-approval-audit)

- 독립 위험 검토는 선택한 행동 모델(현재27B)의 **도구·행동 이력 없는 새 세션**, Thinking off로 실행한다. 4B를 내려받아 비교했지만 제품 검토 경로에 넣지 않았다. 모델의 짧은 이유를 카드와 거부 피드백에 표시한다.
- 정적 Bash allowlist와 PiBashAudit/PiReadShell은 제거했다. 복합 명령, git 옵션·브랜치 생성도 같은 독립 검토를 거치며 문법 미지원만으로 승인을 강제하지 않는다.
- 프로젝트 밖의 일반 파일은 정확한 경로·효과의 명시적 동의가 있으면 독립 검토에서 허용할 수 있다. 포괄적인 실행 요청을 시스템·비밀 파일 변경 허용으로 해석하지 않도록 검토 지시문을 유지한다. OWNER에 별도 정적 경로 veto는 없다.
- 현재 표시된 승인 요청 한 건에 소유자가 ‘하라고’, ‘실행해’, ‘허용’ 또는 거절 표현으로 답할 수도 있다. 채널·요청자·기한·설정 버전과 일회성 토큰을 확인한다. 일반 질의 답변은 자동으로 실행 권한이 되지 않는다.
- 거부한 호출은 `EXECUTION_DENIED`와 **실행되지 않았음**, 이유를 모델에 전달하고 해당 요청에서 도구 우회를 막는다. 실제 도구 실행 실패는 `TOOL_FAILED`와 부분 효과 가능성을 구별한다. Bash의 원래 명령, cwd, 종료 코드, 출력 없음, 검토 이유는 call ID별 카드·상세 스레드에 보존한다.
- `ask_user`는2~4개 선택지와 소유자의 자유 텍스트 답변을 받는다. 질문 데이터는 권한이 아니다. 실행 동의는 실제 도구를 제안해 백엔드가 정확한 명령·대상을 표시하게 한다.
- `/agent run prompt:… window:16384`는 이번 요청만16K를 사용한다. `/agent context action:configure window:16384`는 채널 기본값을 저장한다.8K/16K 선택·출력 예약 검증은 양쪽에 적용된다. 일회성 창을 줄이면 Pi의 압축 기준도 입력 예산 이내로 조정한다.
- Ollama/Strata 대화의 모델 로딩·prefill·출력 대기 중 **추론 컴퓨터**의 메모리 압력을 약1초 간격으로 확인한다. macOS 정상/주의는 허용, 위험은 요청 스트림을 취소한다. Discord 소유자에게10분짜리 ‘위험을 감수하고 재시도’ 버튼을 제공하며 **동일 모델 호출 한 번**만 검사 우회를 허용한다. 이전 도구를 재실행하거나 파일·명령 승인을 면제하지 않는다. 다음 호출은 다시 검사한다. 시스템이 응답하지 않기 전에 반드시 감지한다는 보장은 없으며, OS가 압력 값을 제공하지 않으면 판정할 수 없다. 모델 상주 메모리 해제나 앱/서버 재시작을 보장하는 기능도 아니다.
- 추론 실행기의 `llm-capability`에는 기존 `PI_PROVIDER_V1` 외에 `token=AGENT_SAFETY_PROFILE_V1` 확인이 필요하다. 관리 앱과 실행기를 함께 업데이트해야 한다. 구형 실행기에 위험 감시가 있다고 표시하지 않는다.
- `/agent history action:allow source:#채널` 또는 포럼으로 허용하고 `remove`로 철회, `list`로 조회한다. 정보 제공 서버의 최고 관리자만 출처와 위임 ACL을 바꿀 수 있으며 모델 도구는 이를 변경하지 않는다. 출처 등록 후 grant로 정보 사용 서버·에이전트 채널·사용자 ID를 명시적으로 허용해야 한다. DM은 불가하며 다른 길드로의 전달은 이 ACL로만 허용한다. 제공자/봇의 실제 보기·기록 권한과 제공자 관리자 권한, 소비 채널·요청자 ACL을 매 조회 확인한다. 소비자는 제공 서버의 멤버일 필요가 없다. 허용한 포럼의 게시글은 포함하며 직접 허용한 스레드는 그 스레드만 포함한다. private 스레드는 사용자·봇 모두 관리 권한이 필요하다.
- `list_chat_channels`, `list_forum_posts`, `read_chat_history`는 허용 범위의 원문을 한 번에 최대50개·40K자로 반환한다. 포럼 활성 목록은 캐시 일부, 보관된 공개 게시글은 최근 한 페이지이며 전체 수집으로 주장하지 않는다. 첨부는 자동 내려받지 않는다. 철회는 다음 조회에 적용되며 이미 모델이 읽은 기록은 문맥 초기화가 필요하다.
- `schedule_task`의 create/list/cancel은 일회성 예약 도구다. create는 UTC offset 포함 시각·제목·실행 요청을 받으며 반드시 명시적 승인한다. `/agent schedules`로 조회하고 `cancel:<ID>`로 취소할 수도 있다. 예약은 private JSON에 저장하며 현재 시각/시간대를 list 결과에 제공한다. 관리 앱·Discord 연결이 켜져 있어야 하고, 바쁜 채널은 대기하며15분 초과 지연은 MISSED로 남긴다. 실행 때 소유자·역할·문맥 epoch·모델/승인 설정 revision을 다시 확인한다. 미래 도구는 현재 승인 규칙을 따르며 예약 승인은 미래 셸·외부 전송을 포괄 승인하지 않는다.
- 예약은 실행 전에 RUNNING을 기록한다. 앱 재시작 시 RUNNING은 INTERRUPTED로 남기고 자동 재실행하지 않아 중복 효과를 피한다. 정확한 시각/무조건 실행 보장이나 OS를 깨우는 예약은 아니다.

## 파일 변경 표시

모든 도구 종료 이벤트가 같은 파일 변경 표시기를 거친다. native edit/write, 부분 수정·첨부 저장 등은 승인된 대상의 변경 전후 UTF-8 원문을 비교하고, Bash/프로젝트 생성/빌드 등의 셸 효과는 프로젝트 안의 제한된 스냅샷에서 관측한다. Discord에는 기본 `diff` 코드 블록과 ‘자세히 · 변경 전/후 원문’ 버튼이 표시된다. 원문은 별도 파일 첨부로 해당 소유자에게만 ephemeral 응답하며, 당시 스냅샷의 CRLF·마지막 개행을 보존한다. 현재 파일을 다시 열거나 승인 범위를 넓히는 기능이 아니다. 소유자·채널·문맥 epoch를 확인하고10분 후 만료하며, 앱 종료 시 메모리에서 지운다.

관측 범위는 파일당256KiB·프로젝트 텍스트 합계4MiB·최대1000개·탐색5000항목/깊이12·표시20개다. `.git`, 의존성/빌드 폴더, 비밀/관리 프로필, symlink, 큰 파일/바이너리는 제외한다. 임의 셸이 프로젝트 밖에서 한 모든 수정이나 모든 동시 외부 변경을 포괄 추적하지 않는다. 읽을 수 없게 바뀐 파일을 삭제로 오인하지 않는다. diff가 길면 부분 표시임을 명시하고 원문 첨부로 확인한다. 표시에 사용하는 스냅샷 원문을 행동/검토 모델에 자동 추가하지 않는다.

도구 스레드의 stdout/stderr는 코드 블록으로 감싸고, 긴 메시지는 각 구간에 fence를 닫고 다시 열어 전송한다. 출력 안의 코드 fence도 처리한다. 최종 모델 답변에는 코드/로그를 적절한 언어 코드 블록으로 쓰도록 지시한다. UI 설명은 전체 덮어쓰기와 부분 수정을 구별한다.

## 실행 파일 검토와 요청 제한

bash의 일반 스크립트 실행은 독립 검토에 진입점의 실제 UTF-8 내용·경로·SHA-256을 추가한다. python/node/bash 등 리터럴 실행과 빌드 설정 일부를 비실행 방식으로 읽으며 최대4개·파일당64KiB 읽기·4096자 표시/전체6000자다. 프로젝트 밖/비밀/프로필/symlink/큰 파일/바이너리/동적 구문은 읽지 않고 누락 이유를 전달한다. imports/의존성/다운로드 훅과 전체 효과를 증명하지 않으며 누락 사유도 검토 모델에게 제공한다. 내용은 untrusted data다. 내용 해시 변화만으로 백엔드가 실행을 거절하지 않는다. 그 사이 파일이 바뀔 수 있고 OS 수준 격리나 원자적 검토·실행은 제공하지 않는다. OS 수준 원자적 격리는 아니다. DENY는 미실행과 짧은 이유를 모델에 전달하며, ASK는 이유와 명시 승인 카드를 표시한다.

관리 웹 로컬 LLM의 추론 요청 제한 (분):1~240분, 기본20. Pi /agent의 행동·독립 검토·압축의 요청 한 번에 적용하고 다음 요청부터 로컬 Ollama/Strata 및 원격 실행기에 같은 값을 전달한다. 여러 턴 전체와 셸 timeout은 별도다. rollback용 qwen.json은 runner/model만 저장하고 제한은 qwen-execution.json에 별도 저장한다. Pi SDK provider/Node HTTP idle timeout도 맞추고 중복 provider 재시도는 끈다. 메모리 경고 승인·재시도 대기를 위한 내부 transport 여유는 모델 요청 제한을 늘리지 않는다. 관리자와 추론 실행기를 같이 업데이트해야 한다.

## 명령 실행 통합 (fix/pi-bash-unification)

Pi에 제한형 `sh`를 더 이상 등록하지 않는다. OWNER의 명령 실행은 native `bash` 하나로 통일하며 `cd`, 연결 명령, git도 같은 독립 위험 검토·정확한 명시 승인·출력 기록 경로를 거친다. READ/EDIT 역할에 임의 Bash 권한을 추가하지 않는다. 내부 레거시 `ProjectAgentShell`은 다른 제한형 검색/이전 테스트 호환용으로 남지만 Pi의 명령 도구가 아니다. 과거 세션에 남은 sh 호출은 유효한 도구 사용 예시가 아님을 안내한다.

제거된 sh 이름으로 호스트를 직접 호출하면 실행 없이 `TOOL_INPUT_ERROR`를 반환한다. 이 입력 오류는 권한 거절로 영구 잠그지 않는다. 실제 독립 검토 DENY·사용자 거절·승인 만료·권한 검사 실패의 요청 내 우회 방지와 push/PR·외부 효과에 대한 구체적 명시 동의 요구는 독립 검토 지시문에서 유지한다. 일반 입력 검증 실패 전체를 복구 가능으로 바꾸지 않는다.


## 사전 요청·전체 도구 출력 제한 (fix/pi-intent-output-budget)

자동 승인에서 위험 등급과 사용자 동의를 분리한다. 인증된 실제 사용자 요청은 `pi-human-intent.json`에 작업·소유자·epoch·설정 revision 기준으로 보관하며 모델 요약에서 허용을 복원하지 않는다. 독립 새 검토가 `userAuthorized:true`로 현재 정확한 작업/대상/효과를 확인하면 LOW/MEDIUM은 재확인 없이 실행할 수 있다. 백엔드 scope는 이 동의를 거절하거나 위험 등급을 올리는 조건이 아니다. 완료/새 작업/명시 중단/권한·문맥 변경 뒤의 과거 허용은 재사용하지 않는다. 명시 모드는 계속 확인한다.

이전 유한 for/파이프/Git 정적 감사는 사용자 요청으로 폐기했다. 셸 해석 여부로 모델 ALLOW/LOW를 ASK/MEDIUM으로 바꾸던 원인을 제거했다. Git 시스템/글로벌 config를 Pi에 자동 주입하지 않는 기존 환경 격리는 유지한다.

`/agent setting tool_output_limit:2400` (512..8000자, 기본2400)로 모델에 보내는 비정밀 도구 결과의 발췌 상한을 설정한다. 새 설정은 private `project-agent-output.json`에 저장해 구버전 설정 파일의 rollback 호환을 유지한다. 변경은 진행 요청을 취소하고 다음 요청부터 적용한다. Bash뿐 아니라 목록·검색·프로젝트 생성·포럼 목록 등 모든 나머지 도구에 적용한다. read/edit/write/read_file/edit_file/write_file/read_result/read_attachment/read_chat_history/ask_user는 정확성을 위해 제외하며 각 도구의 기존 paging·안전 한도는 유지한다.

Pi tool_result/context 훅에서 전체 원문을 기존 채널별 결과 보관소로 연결하고 일부 원문+read_result ID만 모델에 전달한다. SDK 기본50KB보다 큰 Bash 출력은 Pi 소유 temp 원본을 읽어 보관한다(1.1MB 초과는 부분 보관을 명시하고 원래 Pi 파일 경로를 제공). 비텍스트/바이너리 출력을 바이트 그대로 보관한다고 주장하지 않는다. 보관24시간·채널별20개와 read_result paging은 기존 정책이다. 원문 첨부 실패가 실행 재시도로 이어지지 않으며 보관 실패에도 모델 문맥으로 긴 원문을 그대로 흘리지 않는다.

원문 첨부는 작업 스레드 또는 같은 비공개 채널에 전송한다. read_result는 별도 작업 임베드를 생성하지 않고 원래 작업 카드에 ‘모델이 결과를 읽는 중…’, 보관 ID와 현재/총 줄 수를 갱신한다. 완료 때 마지막 조회 줄을 표시하며 전체 원문을 모두 읽었다고 주장하지 않는다. 카드 연결은 메모리에서24시간/500개까지 유지한다. 앱 재시작 등으로 원래 카드 연결이 없으면 현재 상태 카드만 갱신하며 새로운 페이지별 임베드는 보내지 않는다. 모델의 실제 추론 턴/비용/최대 턴 한도는 합쳐 숨기지 않는다.

실시간 Discord 출력도 같은 글자 한도로 발췌한다. 한 줄짜리 JSON/로그는 read_result의 start_char로 해당 줄 안에서도 이어 읽으며, 마지막 개행을 별도의 빈 줄로 세지 않는다.


## 상태창과 질문 답변 (fix/pi-reviewer-authority)

첫 메시지는 요청 원문 일부·모델·현재 진행·누적 사용량을 담는 고정 요약이다. 진행 상태창은 별도 하단 메시지이며 모델의 새 응답 메시지/청크가 추가되면 현재 placeholder만 삭제·다시 보내 하단으로 옮긴다. Discord는 메시지 위치 이동 API가 없으므로 기존 완료 도구 기록은 이동/삭제하지 않는다. 실제 도구 호출 시 하단 상태창의 동일 메시지를 승인 대기/도구 실행 카드로 바꾸고, 다음 actor 턴에서 새 상태창을 보낸다. 이전 상태 업데이트 대기열은 취소하며 완료 카드에 뒤늦게 상태 텍스트를 덮어쓰지 않는다. 중지 버튼은 하단 상태창·승인/실행 카드에 유지하고 완료 시 제거한다.

질문 선택 버튼 처리 시 원래 질문에 선택한 답변·응답자 ID를 즉시 기록한다. 질문 완료 이벤트도 같은 표시를 사용하므로 자유 입력도 남는다. 2000자 자유 답변은 임베드 필드 두 개로 나눠 보존하며 멘션 알림은 비활성화한다. 질문 응답은 실행 승인으로 취급하지 않는다.


## 전체 테스트 계약과 작업 개입

과거 custom JSON actor/requirement ledger/자동 문장 보정·자체 압축을 전제로 한 engine 시험은 실제 고정 Pi SDK와 native tool_calls fixture로 이관했다. 이는 모델의 허위 완료 문장을 의미적으로 검증해 주는 기능을 복원한 것이 아니다. 순수 레거시 helper/parser 시험은 호환 검증으로 남는다. 전체 수정 계획·대응표는 docs/testing/pi-full-suite.md를 참고한다.

작업 중 개입은 세션 준비 전에 들어와도 보관하고 upstream session.steer에 순서대로 넘긴다. 수락 이벤트를 Discord 상태창에 표시하며 모델의 다음 처리에서 원문을 사용한다. 사용자/설정 확인을 거치고 한 작업 요청에 최대5개·각2000자까지 허용한다. 실행 권한을 자동 부여하지 않으며 실제 후속 도구는 별도 독립 검토를 받는다. 세션 시작 전/후 모두 같은 상한을 적용한다. 역할 문자열은 OWNER/EDIT/READ만 실행 시작 전에 허용한다.


기존 프로젝트 경로 충돌은 권한 거부가 아닌 TOOL_INPUT_ERROR로 모델에 전달한다. 기존 폴더는 삭제하지 않으며 사용 경로를 바로잡거나 새 경로를 골라 독립 검토를 다시 받아야 한다. 실제 독립 검토/사용자 거부 후 모델 혼자의 후속 호출은 계속 막는다. 인증된 소유자의 새로운 작업 중 지시를 받은 경우에만 거부 latch를 해제하고 다음 도구를 새로 검토한다. 이 지시는 포괄 실행 승인이 아니고 사전 동의·명시 승인 모드는 다시 적용한다. 각 Bash는 프로젝트 홈에서 시작하며 앞선 호출의 cd는 다음 호출에 유지되지 않는다.
