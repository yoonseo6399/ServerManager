# 직접 중계와 기존 관리 Mac 경유 중계

신규 설정은 **실행기·네트워크 → 게임 주소·중계 → 직접 중계 · TCP / Sable UDP** 카드에서 한다. 관리 Mac을 데이터 경로에서 빼려면 이 방식을 사용한다. [설정·상태·포트 API](direct-relay-api.md)의 직접 Sable UDP 항목도 참고한다.

1. 중계 컴퓨터 설치기에서 **게임 중계 사용 허용 (TCP / Sable UDP)** 체크. 구버전의 이름은 **TCP 중계 사용 허용**이다. CLI `--runner-relay-consent=allow|revoke|status`도 지원하며 수동 파일 편집은 필요 없다.
2. 공통 카드에서 공유 게임 주소를 켜고 포트·도메인·DNS를 저장한다. SRV는 공유 게임 포트를 가리킨다. 공통 포트 변경은 기존 정상 종료 조건을 따른다.
3. 직접 카드에서 최초 중계 실행기·게임 실행기가 접속할 중계 주소·플레이어 공개 주소·별도 연결 포트를 지정하고 사용을 켜서 저장한다.
4. Sable이 필요하면 중계·게임 실행기 및 상주 게임호스트를 업데이트하고 **직접 중계에 Sable UDP 추가**를 켠다. 다음 정상 게임 시작부터 보조 모드가 준비된다.
5. 중계 컴퓨터로 게임 TCP포트, Sable을 켰다면 같은 번호 UDP포트, 별도 연결 TCP포트를 포워딩한다. UI 표의 내부 주소/포트를 따른다. 게임 실행기는 외부 포트를 열지 않는다.

경로: 플레이어 → 중계 실행기 → 암호화 TCP 터널 → 게임 실행기 → Minecraft. Sable의 플레이어 구간은 UDP, 실행기 사이 구간은 TCP다. 실제 왕복 전에는 UDP 상태를 “대기”로 표시하며 공유기 외부 성공을 가정하지 않는다.

## 기존 관리 Mac 경유 방식

아래는 공통 카드의 **기존 관리 Mac 경유 중계 · 고급 설정**에 남긴 호환 방식이다. 여기서 컴퓨터를 선택해도 직접 중계 대상은 바뀌지 않는다.

## 관리 웹에서 설정하기

1. 모든 게임 서버를 정상 종료하고 전송 완료를 기다립니다.
2. 공유 TCP 중계를 켜고, **TCP 중계 가능**으로 표시되는 실행기를 선택합니다.
3. 중계 컴퓨터의 공유기와 방화벽에서 공유 게임 포트를 해당 컴퓨터로 연결합니다. 공개 IP가 없는 망은 상위 공유기·통신사 환경에서 수신 가능 여부를 확인해야 합니다.
4. DNS only 대상 호스트를 **중계 컴퓨터의 공개 IPv4**로 맞춥니다. Cloudflare 자동 DNS를 쓰지 않으면 게임 주소의 A·SRV도 직접 맞춥니다.
5. 저장 후 게임 서버를 시작하고 중계 상태가 준비 완료인지 확인합니다.

경로는 `플레이어 → 중계 실행기 → 기존 인증 WSS → 관리 Mac → 기존 WSS → 게임 실행기`입니다.
관리 Mac도 트래픽을 계속 처리합니다. 관리 Mac을 우회하는 직결 중계나 독립 중계 서비스가 아닙니다.
공유 TCP의 호스트 이름 검사와 서버별 라우팅은 관리 Mac에 그대로 남습니다.
공유 TCP 리스너는 관리 Mac에서는 루프백에, 중계 실행기에서는 외부 수신 주소에 열립니다.
공유 포트와 같은 컴퓨터에서 실행할 게임의 내부 포트가 충돌하지 않게 설정하세요.

이 기존 실행기 경유 방식은 TCP 전용입니다. 다른 컴퓨터의 중계를 선택하면 Sable UDP는 꺼집니다.
중계 실행기에서 최대 32개 TCP 연결을 처리하며, 제어 연결이 끊기면 연결과 수신 포트를 닫습니다.
재연결 후 현재 선택·권한·실행 경로를 확인해 다시 수신하며, 중계 복구 때문에 Minecraft를 시작하거나 종료하지 않습니다.
현재 TCP 연결이 있으면 실행기의 서명 업데이트 재시작을 기다립니다.
포트 충돌·수신 미허용·오프라인은 관리 웹에 표시됩니다. 중계 실행기가 꺼졌을 때 중앙 Mac으로 공개 접속을 자동 전환하지 않습니다.

## 검증 범위

로컬 TCP 소켓으로 양방향 바이트 보존·포트 충돌·수신 해제와, 인증 세션 모의 연결을 통한 중계→관리 Mac→게임 실행기 경로를 검증합니다.
이는 서로 다른 실제 컴퓨터·공유기·공개 DNS·Windows 방화벽을 통과한 외부 접속 검증을 대신하지 않습니다.
