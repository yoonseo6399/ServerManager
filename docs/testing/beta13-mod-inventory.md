# Beta13 모드 조회·활성화 검증

## 요청과 변경

- 파일 해시 스캔이 끝나면 캐시와 함께 목록을 먼저 게시합니다. 느린 Modrinth 조회가 끝나야 목록을 볼 수 있던 경로를 분리했습니다.
- Modrinth 결과는 100개 단위로 반영하고, 잘못된 메타데이터가 있는 묶음은 제한된 추가 요청으로 분리합니다. HTTP/네트워크 장애는 파일마다 재시도하지 않습니다. 실패를 미등록으로 영구 캐시하지 않으며, 이미 성공한 출처·버전은 보존합니다. 버전 전용 의존성/프로젝트 표시 정보 실패도 나머지 모드를 버리지 않습니다.
- 미등록/직접 업로드 파일은 미확인 경고와 함께 유지합니다. 불완전한 정보는 표시하고 목록 재조회로 다시 확인합니다. 최초 조회 실패 후 무한 로딩 표시와 재시도 불가 UI를 수정했습니다.
- 활성화 시 무관한 기존 중복·비호환 조합까지 검사해 독립된 모드 복원을 막던 범위를 수정했습니다. 변경 대상과 연결되는 충돌과 정확한 필수 버전 검사는 유지합니다.
- 의존성·비호환 검사 실패에만 별도 오류 코드를 보냅니다. 사유 옆 주황색 **의존성 무시하고 그냥 켜기** → 경고/선택 목록 확인 → **위험을 확인하고 그냥 켜기** 순서입니다. 선택한 비활성 파일만 변경하며 의존성 자동 활성화도 생략합니다. 비활성화·검사 후보 선택에는 override를 제공하지 않습니다.
- 강제 옵션으로도 권한/CSRF, 실행 중/인계/진단 작업 제한, inventory revision, 파일 내용 변경 검사, 대상 이름 충돌, 백업·복구를 우회하지 않습니다.
- 모드팩의 클라이언트 전용 제외 검사에서 불완전한 의존성 정보가 있으면 가져오기 전체를 실패시키지 않습니다. JAR 자동 삭제를 보류하고 파일을 유지하며 경고합니다. 다운로드·압축 경로·해시 검증은 유지합니다.

## 실제 데이터 조회

사용자 동의 후 운영 서버의 232개 모드 SHA-512 해시로 공식 Modrinth API를 읽기 전용 조회했습니다. 파일 내용은 외부 전송하지 않았습니다.

- 파일 232개, 알려진 파일 224개, 미등록 8개 모두 최종 inventory에 유지.
- 프로젝트 메타데이터 260개 중 259개 반환. 누락된 표시 정보는 경고하고 버전·파일 목록은 보존.
- ModSourceLiveTest 최종 실행 통과(4.801초). 이 시간은 해당 단일 시험 결과이며 일반 응답 시간 보장이 아닙니다.
- 당시 최초 오류의 정확한 예외는 운영 로그에서 확보하지 못했습니다. 현재 upstream 응답으로 최초 장애를 확정 재현했다고 주장하지 않습니다. 알려진 전체 취소 경로와 UI 무한 로딩은 fixture로 재현·검증했습니다.
- 운영 모드 켜기/끄기·재시작·설치 명령은 실행하지 않았습니다. 운영의 실제 모드팩 전체 재가져오기는 미실행입니다.

## 로컬 기능 테스트

- 모드 관련 5개 클래스: 최종 회귀 53개 중 50통과, 외부 opt-in 3개 생략. 이후 MVC 구분 검사 1개 추가, ModManagementTest 6개 전부 통과(앞선 5개와 중복). 고유 회귀 54개 중 51통과·3생략.
- 별도 실제 해시 조회 1개 통과. 일반 실행에서는 환경 변수가 없으면 생략됩니다.
- Playwright 4개 통과: 오류 옆 주황색 버튼/확인/정확한 override payload, 권한 오류에는 버튼 미노출, 최초 조회 실패 후 재시도, 실행 중 읽기 전용 목록, 1200개 목록 필터·페이징 회귀.
- TypeScript와 React production build 통과.
- 기존 전체 백엔드 스위트·다른 OS 실행은 사용자 요청에 따라 생략.
- 새 MVC 테스트 작성 중 오류 처리기 이름 오타로 컴파일 1회 실패, mock 재설정 방식으로 1회 실패. 테스트 코드를 수정한 뒤 최종 6개 통과. 원문 로그와 XML, 스크린샷, 공개 API 응답은 ignored `build/mod-fix-evidence/`에 보존하며 운영 파일명·해시는 커밋하지 않습니다.
