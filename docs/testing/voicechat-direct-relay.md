# Simple Voice Chat 직접 중계

## 관리 웹에서 설정

1. 관리웹·중계 실행기·게임 실행기와 **상주 게임호스트**를 이 기능이 포함된 버전으로 업데이트합니다. 상주 호스트가 이전 버전이면 음성 기능이 활성화되지 않습니다.
2. **실행기·네트워크 → 게임 주소·중계 → 직접 중계 → Simple Voice Chat · 음성 UDP**에서 서버를 선택합니다. Simple Voice Chat 모드는 서버와 플레이어가 별도로 설치해야 합니다.
3. 공개 음성 UDP 포트는 기본 **24454**입니다. 게임 실행기 내부 포트와 구별합니다. 중계와 게임이 같은 실행기이면 충돌을 피하려고 내부 기본값은 **34454**를 제안합니다. 여러 서버는 서로 다른 공개 포트가 필요하며 같은 게임 실행기에 있는 서버끼리는 내부 포트도 달라야 합니다.
4. 공유기에서 **외부 UDP24454 → 중계 컴퓨터 IP UDP24454**를 포워딩하고 방화벽에서 허용합니다. 게임 실행기에는 추가 외부 포워딩이 필요 없습니다. 게임 TCP/SRV와 기존 실행기 연결 TCP 포트는 유지합니다. Sable UDP를 끄면, 예를 들어 게임 TCP6700과 음성 UDP6700처럼 공개 포트 번호를 공유할 수도 있습니다. UDP6700 포워딩은 별도로 필요합니다.
5. 저장한 뒤 **다음 정상 게임 시작**에 `port`, `bind_address=127.0.0.1`, `voice_host=공개중계주소:공개음성포트`를 앱이 자동 준비합니다. 사용자가 파일을 직접 수정할 필요는 없습니다. 다른 설정·주석은 유지하고 기존 관리 값과 원문을 실행기 프로필의 `voicechat-backups`에 보존합니다. 기능 해제 후 다음 시작에는 기존 관리 키를 복원하며 사용자가 이후 변경한 값은 유지합니다.

## 상태와 제약

- `NEEDS_RESTART`: 변경 사항을 다음 정상 시작에 준비해야 합니다. 자동 서버 재시작이나 모드 설치를 하지 않습니다.
- `CONFIGURED`: 모드 설정 파일을 준비했습니다. 모드 자체의 로딩·오디오 성공을 뜻하지 않습니다.
- `LISTENING`: 중계의 UDP 소켓을 열었습니다. 외부 공유기/인터넷 도달 성공을 뜻하지 않습니다.
- `CONNECTED`: 실제 UDP 왕복 패킷을 확인했습니다. 마이크·오디오 품질은 별도 확인해야 합니다.
- `ERROR`: 포트 충돌 등으로 음성 수신을 준비하지 못했습니다. 기존 게임 TCP는 유지합니다.

경로는 **플레이어 UDP → 중계 실행기 → 기존 암호화 TCP 터널 → 게임 실행기 loopback UDP → 모드**입니다. 관리 Mac으로 음성 데이터를 보내지 않습니다. TCP 구간에서 패킷 손실이 생기면 음성 지연이 증가할 수 있습니다. 새 공개 주소를 모드에 알리는 중계 전환도 다음 게임 시작이 필요하므로 기존 주소·DNS 및 전환 유예를 함께 고려하세요.

중계는 해당 서버의 실제 TCP 접속 소스 IP가 있는 UDP만 전달하고 세션/큐/패킷 크기/속도를 제한합니다. IP 일치는 Minecraft 계정 인증을 대신하지 않으며 Simple Voice Chat 모드의 플레이어 비밀 인증을 그대로 사용합니다. 임의 포워딩 대상은 받지 않고 승인된 서버의 지정 loopback 포트만 사용합니다. 로컬 중계 동의 철회, 경로/epoch 취소와 비활성화는 해당 음성 중계도 차단합니다.

공식 포트포워딩: https://modrepo.de/minecraft/voicechat/wiki/server_setup_self_hosted

## 검증

최종 범위 결과는 기능 브랜치 인계 노트에 기록합니다. 실제 소켓 시험은 격리 UDP echo로 패킷 보존·왕복과 차단 조건을 확인하며, 실제 Minecraft 음성 클라이언트·마이크·외부 공유기 시험과 구별합니다. 전체 테스트/다른 OS/운영 프로세스 재시작은 이번 작업에 포함하지 않습니다.
