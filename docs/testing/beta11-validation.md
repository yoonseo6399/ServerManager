# Beta 11 — 로컬 에이전트 검증 기록

기준은 게시된 `v0.7.0-beta.10` (`84cfa9f`)이다. 단독 구현하며 전체 테스트·다른 OS·운영 서비스 교체는 수행하지 않았다. 수치 원본 요약은 [beta11-results.json](beta11-results.json), 문맥 구성은 [agent-context.md](../architecture/agent-context.md)에 있다.

## 채택 결정과 최종 실행 코드 비교

공식 Ollama 도구 호출을 Discord 에이전트의 기본 경로로 확정했다. 저장 변경 고정 보완 후 같은 Kotlin 소스(`7c0c4f0`, 두 시험의 231개 소스 SHA-256 일치)로 8K 과제를 다시 비교했다. 아래 시간은 JUnit 기준이며 Gradle 시작은 제외한다.

| 방식 | 요청한 수정·전체 나머지 바이트 보존 | 검증·보고 완결성 | 시간 | 완료 메인/보조 호출 | 압력·관측 스왑 증가 |
| --- | --- | --- | ---: | ---: | --- |
| 공식 tools/tool_calls | 성공 | 성공, search → read_file → edit_file → read_file 뒤 근거 보고 | 187.1초 | 6 / 5 | 정상 · 0 MiB |
| 기존 JSON | 성공 | 재조회 뒤에도 완료 근거 누락, 같은 조회 반복 제한으로 중단 | 254.3초 | 10 / 7 | 정상 · 0 MiB |

이 과제에서는 공식 방식이 더 적은 호출과 시간으로 최종 보고까지 마쳤다. JSON이 파일을 잘못 수정했다는 뜻은 아니다. 직렬 시험 각 1회이므로 일반적인 속도 배수·성공률을 추정하지 않는다. 16K의 최종 보완 후 A/B는 재실행하지 않았다. 두 모델 모두 시험 후 해제했고 압력이 정상임을 확인했다.

비교 뒤에는 **종료 표시만** 추가 보완했다. 정상 종료뿐 아니라 반복·턴 제한으로 중단해도 이미 저장된 현재 파일의 이름·영수증을 붙이고, 전체 요구 충족과 구분한다. 이 표시 변경은 별도 기능 회귀로 검증하며 위 A/B 측정 뒤라고 명시한다. 도구 요청·결과·모델 입력 경로의 비교 소스는 동일하다.

## 개발 과정의 8K/16K 비교

Mac M4 Pro 24 GiB, Ollama 0.40.4, `qwen3:14b` Q4_K_M. Thinking 켬, 메인 출력 예약 4096, 보조 1024. 각 창에서 같은 설정으로 비교했다. 각 구성 1회이며 일반 벤치마크·모델 순위가 아니다. 순수 전송 규약만 비교한 학술 실험도 아니다. 공식 함수 등록에 맞는 지시문·`report_task` 및 도구 선택 방식 차이도 포함한다.

임시 프로젝트의 요청은 검색 → 읽기 → 부분 수정 → 재조회다. 원본은 다음 UTF-8 바이트이며 `old` 한 곳만 `new`로 바뀌어야 한다.

```python
b"keep header\r\nPATCH_TARGET_9431=old\r\nkeep footer\r\n"
```

수정 위치뿐 아니라 **전체 파일 바이트**를 기대 결과와 비교한다. 헤더·푸터·CRLF·마지막 개행 보존을 포함한다. 추가로 실제 도구 순서, 한 번의 수정 승인, 재조회, 근거에 기반한 최종 보고를 확인한다. 파일 수정 성공과 보고 완결성은 별개다.

| 방식 | 실행창 | 수정·나머지 원문 보존 | 최종 보고 | JUnit 시간 | 최대 메모리 압력 | 관측 스왑 증가 최대 |
| --- | ---: | --- | --- | ---: | --- | ---: |
| 공식 tools/tool_calls | 8K | 성공 | 성공, 실제 4개 도구 + report_task, 5턴 | 126.3초 | 정상 | 0 MiB |
| 레거시 JSON 도구 규약 | 8K | 성공 | 반복 조회 후 5분 시험 한도 중단 | 300.5초 | 정상 | 0 MiB |
| 공식 tools/tool_calls | 16K | 성공 | 잘못된 인자 교정 후 재조회까지 실행, 보고 도중 5분 한도 중단 | 309.9초 | 경고 | 360.6 MiB |
| 레거시 JSON 도구 규약 | 16K | 성공 | 실제 수정·재조회 후에도 요구사항별 완료 근거를 제출하지 못해 백엔드 종료 | 273.7초 | 정상 | 0 MiB |

시간은 Gradle 시작·컴파일을 제외하고 정리를 포함한다. 5분은 시험 작업 한도이며 중단 뒤 모델 해제에 시간이 더 걸릴 수 있다. 스왑은 모델만의 사용량이 아닌 시스템 관측값이다. 임계 압력은 관측하지 않았다. 각 시험 후 모델 해제와 정상 압력을 확인했다. Metal 한도·운영 실행기의 설정은 변경하지 않았다.

16K에서는 Ollama `/api/ps`의 실제 `context_length=16384`를 확인했다. 보고된 모델 GPU 할당은 약 11.3~11.4 GiB였다. 완료된 메인 호출의 최대 실제 입력은 공식 방식 4515, JSON 3436토큰으로, **16K 전체 길이의 입력 정확성·보존 시험은 아니다.** 과거 Qwen 30B 16K/32K 메모리 시험과 구분한다.

JSON 방식의 보고 실패를 파일 수정 실패라고 해석하면 안 된다. 새로운 요구사항별 영수증 형식을 지키지 못한 것이 주요 종료 원인이었다. 공식 8K에서는 `report_task`가 이 보고에 성공했다. 공식 16K에서도 줄 번호 0과 원문 일부만 쓰려는 요청이 나왔으며 실행 전 차단됐다. 공식 등록만으로 정확한 인자가 보장되지는 않았다. 16K 공식 시험의 잘못된 인자는 메모리 압력이 정상일 때도 나왔으므로 메모리가 원인이라고 단정하지 않는다.

이 A/B 자료는 마지막 동일 조회 결과 감지와 실제 교체 내용 고정 보완 전의 자료다. 이후 같은 조회 결과의 변형 반복을 중단하고, 실제 저장한 교체 전후 값을 요약 밖에 고정하도록 추가했다. 따라서 표의 반복 종료 시간은 최종 보완 후의 성능 측정값이 아니다.

변경 내용 고정 전 공식 8K 재시험에서는 실제 수정을 했음에도 old를 다시 검색하고 잘못 blocked 보고를 했다. 이 실패도 보존했으며, 이후 재실측 결과는 위 표에 별도로 기록했다.

## 개발 중 실패도 보존

- 최초 14B 실측은 실제 검색·읽기·수정·재조회와 전체 바이트 검사를 통과했지만 추출기가 단일 파일 과제를 12개 중복 항목으로 늘려 보고를 마치지 못했다. 단일 파일 요청은 원문 제약을 한 항목으로 보존하도록 수정했다.
- Thinking을 끈 JSON 시험에서는 읽지 않고 수정하려다가 차단된 뒤 사용자에게 읽기를 떠넘겨 종료했다. 결과를 성공으로 계산하지 않는다.
- 최초 공식 호출 시험에서는 다음 호출이 빈 응답으로 끝났다. 빈 완료 응답을 성공으로 취급하지 않고 제한된 교정을 요청하도록 보완했다.
- 테스트 기록 파일 생성·테스트 컴파일 오류도 진단 파일에 남긴다. 모델 품질 실패와 구분한다.
- 공식 API의 단일 읽기 smoke도 별도로 통과했지만, 제품의 다단계 완료를 입증하는 결과로 대체하지 않았다.

## 기능 회귀·보호 범위

최초 최종 회귀는 168개 중 160개 통과, 실제 모델 opt-in 8개 건너뜀, 실패 0이다. 이후 중단 결과 표시를 보완하고 관련 엔진·하네스·공식 호출 21개를 다시 실행하여 모두 통과했다. 이 개수에 실제 모델 A/B의 실패를 섞어 숨기지 않으며, 전체 스위트를 통과했다는 뜻도 아니다.

기능별 Gradle 테스트는 실행 프로필·실제 HTTP 옵션, 공식 함수 등록/스트림/도구 결과 역할, 권한별 도구 제한, 등록 전 실행 차단, 독립 위험 검토·사람 승인 유지, 내용 검색·부분 수정·CRLF, 다른 파일의 영수증 오용 거부, 확장자 없는 a/b 파일, 병합 후 삭제, 반복·미호출·미완료 종료, 재설정·롤백 호환, 실행기 capability와 Beta 10 모듈·권한 경계를 포함한다. 세부 개수와 최종 실제 8K 회귀 결과는 아래 완료 기록을 따른다.

원문이 있는 기존 파일의 부분 변경은 `read_file` 이후 `edit_file`을 사용한다. 읽기 도구가 요약을 요청하지 않은 경우 원문을 보존한다. 긴 원문은 결과 저장소로 이어 읽는다. 완료 영수증은 실행·대상·현재 파일 지문을 검증하며 임의 요구사항의 의미적 정확성을 완전히 증명하지는 않는다. 소유자 명령은 OS 사용자 권한으로 실행되며 OS 샌드박스라고 주장하지 않는다.

## 원문과 재실행

로컬 원문은 Git에 넣지 않고 `build/beta11-evidence/`에 보존한다.

- `comparison/`: 위 네 구성의 고정 A/B 원문.
- `actor-*.jsonl`: 실제 입력 메시지, 모델 응답, 완료 호출의 토큰·시간.
- `wire-*.jsonl`: 임시 과제의 실제 Ollama 요청과 스트리밍 프레임. 제품은 기본적으로 이 추적을 하지 않는다.
- `fixture-*.before.bin`, `fixture-*.after.bin`: 실제 시험 파일. 최초 공식 8K는 캡처 추가 전이라 JUnit 바이트 단언과 마지막 원문 조회로 입증한다.
- `memory-*.jsonl`: 약 2초 간격 압력·스왑·vm_stat·로드 모델.
- `targeted.log`, `targeted-xml/`: 기능 회귀 원문.
- `SUMMARY.json`, `SHA256.json`: 최신 요약·증거 해시. 중단된 호출의 최종 토큰 통계는 없으므로 완료 호출 누계를 전체 사용량으로 오해하지 않는다.
- `history/`와 별도 진단 접두사 파일: 재실행 전 원문·개발 중 실패. 기존 결과를 덮어쓰지 않는다.

macOS용 보조 스크립트이며 모델이 이미 로드됐거나 시작 시 압력이 정상이 아니면 시험하지 않는다. 임계 압력·시간 watchdog에서는 시험을 중단하고 해당 모델 해제를 요청한다. 5분 작업 한도 안에 모델이 끝나지 않은 결과를 기능적으로 불가능하다는 결론으로 일반화하지 않는다.

```sh
python3 scripts/test-beta11-live.py 8192 14b native
python3 scripts/test-beta11-live.py 8192 14b json
python3 scripts/test-beta11-live.py 16384 14b native
python3 scripts/test-beta11-live.py 16384 14b json
python3 scripts/summarize-beta11-live.py
python3 scripts/export-agent-context.py --check
```

## 발견한 문제·수정·남은 한계

| 발견 | 수정 방법 | 남은 한계 |
| --- | --- | --- |
| 8192 실행창과 약 3500 입력 제한이 따로 보임 | 8K/16K·입력·출력 예약을 한 프로필로 검증하고 명령어·턴 표시·실행기 API에 연결 | 실행창 전체를 입력에 쓸 수는 없고, 정의·Thinking·출력 공간이 필요함 |
| 압축 뒤 원래 목적·실제 수정 사실을 잃음 | 원문 목표·계획·요구사항·실제 저장 지문과 교체 내용·남은 재조회를 압축 밖에 보존 | 보조 모델의 자유 요약은 여전히 틀릴 수 있고, 임의 요구의 의미를 완전히 검증할 수 없음 |
| 도구 예고만 하거나 같은 조회를 반복·거짓 완료 | 공식 함수 호출·완료 보고, 미호출 교정, 동일 결과·변형 반복 제한, 근거별 완료 검사 | 모델의 모든 잘못된 판단을 제거하지는 못함. 제한에 걸리면 정직하게 중단 |
| 검색·부분 수정 회피와 원문/개행 손상 위험 | 검색 옵션 보완, 기본 도구에 edit_file, 기존 파일 사전 읽기·부분 변경 검사, CRLF 바이트 보존 시험 | 거대한 파일·모든 파일 형식·모든 명령 경로를 OS 수준 격리하는 구현은 아님 |
| 중단하면 이미 적용된 변경을 놓칠 수 있음 | 모든 정상 엔진 종료에 현재 지문이 맞는 실제 변경 파일·영수증 표시 | 갑작스러운 프로세스 종료·통신 예외의 Discord 표시까지 보장하지 않음 |
| 새 문맥 설정을 구형 실행기가 무시할 가능성 | capability 확인·명시적 업데이트 안내·별도 저장 형식과 롤백 epoch 검사 | 관리 앱과 추론 실행기를 모두 Beta 11로 업데이트해야 새 경로 사용 가능 |

실제 Discord 메시지 전송·버튼 상호작용, 원격 실행기 앱 설치 후 양단 통신, 다른 OS, 30B/Coder/Gemma의 이번 하네스, 전체 16K 입력 및 장시간·여러 과제 품질은 미검증이다. 운영 앱·실행기·게임호스트는 교체하지 않았다. 릴리즈 통합·서명·게시 결과는 해당 버전의 릴리즈 노트에 기록한다.
