# 서버 폴더 ZIP 가져오기

구현 브랜치: `feat/server-archive-import`. 아직 공개 릴리즈·운영 적용 전이다.

## 사용 방법

1. 기존 서버를 정상 종료한 상태에서 서버 폴더를 ZIP으로 압축한다. 월드·모드·config·server.properties·실행에 필요한 libraries/JAR를 함께 넣는다. 압축 안에 바깥 폴더가 하나 더 있어도 인식한다.
2. 관리 웹에서 소유자 또는 전체 관리자 계정으로 **서버 ZIP 가져오기**를 연다. mrpack 가져오기 옆에 있다.
3. ZIP을 선택하거나 끌어 놓는다. 8 MiB씩 분할 전송하며 완료된 용량을 표시한다. 일시 오류는 같은 화면에서 **업로드 다시 시도 / 이어서 올리기**로 서버가 받은 위치부터 이어 간다. **업로드 취소** 또는 가져오기 전 **닫기**는 임시 업로드를 정리한다.
4. 서버 폴더·파일 수·해제 용량을 확인하고 서버 종류, Minecraft/로더 버전, 실행 JAR, 필요 Java, 메모리와 내부 포트를 확인한다. 이름만으로 알 수 없는 버전은 비워 두므로 직접 입력해야 한다. 기존 지원 종류는 Vanilla/Paper/Fabric/Forge/NeoForge, 정식 Minecraft 1.18 이상이다.
5. **새 서버로 가져오기**를 누른다. 별도 임시 폴더에서 압축 해제·CRC를 검사한 뒤 새 인스턴스에 반영한다. 화면의 **서버 ZIP 가져오기 상태**와 콘솔에 완료·실패를 표시한다.
6. 실행 파일이 있으면 정지 상태, 없으면 설치 준비 상태로 등록한다. 필요한 공식 런처를 설치하고 실행 컴퓨터·주소·포트를 확인한 뒤 직접 시작한다. 업로드만으로 서버나 ZIP 안의 스크립트·설치기를 실행하지 않는다. 원격 실행기는 기존 검증된 파일 전송 경로를 사용한다.

## 보존 및 적용

- 기존 서버를 교체하지 않는다. 새 서버 ID를 생성하며 월드·비공개/비활성 모드·일반 설정 파일의 내용을 보존한다.
- `server.properties`는 선택한 내부 게임 포트·loopback·분리 Query 포트·RCON 해제 설정을 적용한다. 알 수 없는 속성값과 UTF-8 한글 값은 유지하지만 파일의 주석·정렬·인코딩 표기는 Java properties 형식으로 다시 기록될 수 있다.
- `server-manager-runtime.json`은 확인한 서버 종류·버전·Java·JAR로 새로 작성한다. ZIP이 갖고 있던 관리자 런타임 정보를 그대로 신뢰하지 않는다.
- 기존 `eula.txt`가 있으면 false도 보존한다. 없으면 일반 새 서버 생성과 같은 동의 정책을 사용한다.
- `__MACOSX`·`.DS_Store`는 제외한다. 한 서버를 인식한 경우 그 바깥 파일은 제외하며 미리보기에 경고한다. 여러 server.properties가 있으면 한 서버만 압축하도록 안내한다.
- 실행기 배정은 일반 서버와 같다. 같은 실행기에 다른 서버가 있으면 기반 다중 서버 패치가 내부 포트를 분리한다.

## 한도와 검증 범위

- ZIP 최대20 GiB, 해제100 GiB, 개별 파일20 GiB, ZIP 항목10만. 파일명·경로·대소문자/Unicode 중복·파일/폴더 충돌·CRC·실제 해제량을 검사한다. ZIP 속성으로 파일시스템 링크를 만들지 않는다.
- 업로드는 해당 계정에 귀속되며 다른 전체 관리자도 토큰만으로 가져올 수 없다. 기존 인증·CSRF를 사용한다. 미완료 업로드 최대4개, 마지막 갱신24시간 뒤 정리한다. 브라우저를 닫거나 새로고침한 뒤의 파일 재선택 자동 복구는 지원하지 않는다.
- 실물 시험은 **257 MiB ZIP / 269,484,322바이트 / 33청크** 저장·미리보기까지 확인했다. 20 GiB 전체 업로드·100 GiB 해제·외부 프록시/인터넷·실제 Minecraft 월드 이전·다른 OS는 시험하지 않았다.
- 테스트용 Java 서버 JAR를 가져온 뒤 자동 실행되지 않음을 확인하고, 명시적인 시작·정상 종료를 실행했다. 실제 Minecraft 호환성 시험을 대신하지 않는다.
- RAR/7z/tar.gz와 Nextcloud 계정·URL 직접 가져오기는 포함하지 않는다. ZIP 파일 업로드만 추가한다.

원시 JUnit 결과의 집계와 대용량 업로드 증거는 `server-archive-import-results.json`, 커밋 전 계획과 실패/수정 기록은 `../dev-notes/feat-server-archive-import.md`에 있다.
