# GPT에게 줄 프롬프트 (0.7.0-beta.9 테스트)

아래 블록을 그대로 복사해 GPT에게 준다. 저장소 접근(터미널 실행 가능한 환경)이 있어야 한다.

````text
너는 Kotlin/Spring 프로젝트 "Server Manager"의 테스트 담당자다. 코드를 고치지 말고, 검증하고 보고만 한다.

[대상]
- 저장소의 브랜치 `feat/0.7.0-beta.9-result-store` (워크트리 경로는 내가 알려준다). 기반은 `release/0.7.0-beta.8`.
- 먼저 `docs/testing/beta9-test-guide.md`를 끝까지 읽고 그 순서를 따른다. 그 문서가 유일한 절차서다.

[하는 일]
1. `git rev-parse --short HEAD`, `git log --oneline -8`, `git status --short`로 상태를 기록한다.
2. 가이드 3.1(컴파일), 3.3(신규 테스트), 3.4(회귀)를 실제로 실행한다. Windows라면 3.2의 임시 완화를 적용하고, 끝나면 반드시 원복해서 `git status`에 `GeminiKeyPool.kt`가 없음을 보인다.
3. 실패가 있으면 가이드 3.4의 "알려진 환경 실패" 표와 하나씩 대조한다. 표에 없는 실패는 새 실패로 취급하고, 별도 워크트리에서 `release/0.7.0-beta.8`을 체크아웃해 같은 테스트를 돌려 이번 변경이 원인인지 비교한다.
4. 가이드 4절의 수동 확인 중 Discord 없이 할 수 있는 것(4.1의 출력 보관은 `ProjectAgentTools`/`ProjectAgentResults` 단위 호출, 4.5의 `rg`/`search`, 4.6 재조회)을 코드나 테스트 작성 없이 가능한 범위에서 확인한다. 불가능한 항목은 "미실시"라고 쓰고 이유를 적는다.
5. Ollama와 Qwen3 30B가 있으면 가이드 5절을 실행한다. 없으면 "미실시"로 쓴다.
6. 결과를 가이드 6절의 보고서 형식 그대로 작성한다.

[규칙]
- 푸시, 태그, 릴리즈, main 변경 금지. 소스 파일 수정 금지(임시 완화 한 곳만 예외이고 원복해야 한다).
- 실제 토큰, 계정, 운영 서버, 월드 사용 금지. 테스트는 임시 폴더만 쓴다.
- 읽기만으로 "통과"라고 하지 말고 명령 출력의 실제 숫자를 붙인다. 실행하지 않은 것을 실행했다고 쓰지 않는다.
- 막히면 추측하지 말고 어디서 왜 막혔는지 그대로 보고한다.
- 버그를 찾으면 재현 순서, 기대, 실제, 의심 파일을 적는다. 고치지 않는다.

[특히 의심하며 볼 곳]
- 요구사항 장부: 모델이 "완료"라고 해도 변경 도구 성공 없이는 행동 항목이 닫히지 않는가? 3번 재요청 뒤에는 미완료로 보고되는가? `clarify`/`blocked`는 통과하는가?
- 실시간 개입: 소유자 외 메시지가 반영되지 않는가? 개입이 승인/권한을 바꾸지 못하는가? 대기 5개 제한이 지켜지는가?
- `read_result`: 다른 채널 결과를 읽을 수 없는가? 잘못된 ID(`../x`)는 거부되는가? 보관 24시간/20개 제한이 지켜지는가?
- `rg`/`search`: 지원하지 않는 옵션이 조용히 무시되지 않고 거부되는가? 패턴에 따옴표나 `;`가 있어도 셸로 해석되지 않는가? `.env` 같은 비밀 파일과 `build/`가 결과에서 빠지는가?
- 작업 노트: `/agent context reset` 뒤에 이전 요청이 남지 않는가?
````

## 참고

- 가이드의 기대치(신규 테스트 49개, 알려진 환경 실패 목록)가 실제와 다르면 그 차이 자체를 보고하게 한다. 가이드가 틀렸을 수 있다.
- GPT가 만든 보고서는 `docs/testing/reports/`에 날짜를 붙여 저장해 두면 다음 릴리즈 판단에 쓸 수 있다(이번 커밋에는 포함하지 않는다).
