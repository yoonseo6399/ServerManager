# 한 컴퓨터에서 여러 Minecraft 서버 운영

구현 브랜치: `feat/multi-server-ports` (Simple Voice Chat 직접 중계 브랜치 포함). 아직 공개 릴리즈·운영 적용 전이다.

## 설정

1. 서버를 각각 만들고, 각 서버의 **실행 컴퓨터**에서 같은 실행기를 선택한다. 실행기 등록자가 각 서버의 사용을 허용해야 한다.
2. 같은 실행기에 이미 배정된 내부 게임 포트와 중계·음성 예약 포트를 피해서 자동 배정한다. 예: A `25565`, B `25566`. 설정 화면과 배정 완료 안내에서 결과를 확인한다. 다른 실행기끼리는 내부 포트가 같아도 된다.
3. 공통 접속 설정에서 서버마다 다른 하위 도메인을 지정한다. 공유 게임 중계는 예를 들어 `a.example.com`, `b.example.com`을 같은 공개 TCP `6700`으로 받아 서로 다른 서버에 전달한다. IP만으로 접속하면 기본 서버 선택을 따른다.
4. Simple Voice Chat을 사용하면 직접 중계 화면에서 각 서버의 음성 중계를 켠다. 공개 UDP는 A `24454`, B `24455`처럼 구분한다. 중계와 게임을 같은 컴퓨터에서 실행할 때 UI가 제안하는 내부 음성 포트는 A `34454`, B `34455`다. 공개·내부 음성 포트는 각각 수정할 수 있다.
5. 중계 컴퓨터의 공유기·방화벽에 공개 게임 TCP 포트와 서버별 공개 음성 UDP 포트를 연다. 내부 게임·Query·내부 음성 포트는 로컬 전용이며 그대로 외부에 열지 않는다. 별도 컴퓨터의 게임 실행기가 접속할 때는 실행기 연결 TCP 포트도 기존 직접 중계 안내에 따라 준비한다.
6. 서버를 정상 시작한다. 음성 설정 파일은 앱이 백업하고 다음 시작에 반영한다. 여러 서버의 힙 예약 합계가 컴퓨터의 허용 메모리를 넘으면 시작을 거부한다.

직접 Sable UDP를 함께 쓰면 공유 게임 UDP 포트도 사용하므로 음성 공개 UDP와 번호가 달라야 한다. Sable을 끄면 게임 TCP와 음성 UDP는 같은 번호를 사용할 수 있으나 **서버별 음성 공개 UDP끼리는 구분**해야 한다.

## 충돌 처리

- 실행 중인 다른 서버의 포트나 PID는 자동 변경하지 않는다. 배정·다음 시작을 요청한 정지 서버만 조정한다.
- 이전 앱이 저장한 같은 실행기의 중복 내부 게임 포트도 다음 원격 시작 직전에 분리한다.
- 설정 화면에서 명시적으로 기존 내부 포트와 같은 값을 입력하면 거부한다.
- 다른 컴퓨터에서는 재사용 가능했던 음성 내부 포트가 이동할 컴퓨터의 다른 서버와 겹치면, 먼저 직접 중계 설정에서 음성 내부 포트를 바꾸라는 안내를 낸다.
- Query 포트는 아직 게임이 바인딩하지 않았더라도 먼저 시작 준비한 서버의 예약을 피한다. 최신 상주 호스트는 예정 음성·공개 UDP 포트도 제어 계층에 알려준다. 구버전 호스트에는 이 추가 예약 조회 기능이 없으므로 함께 업데이트하는 것이 필요하다.
- 다른 프로그램이 점유하는 포트는 실행 시 실제 소켓 검사로 실패할 수 있다. 관리자 배정만으로 원격 OS의 모든 점유 상태를 확인한 것은 아니다.

## 검증 범위

`docs/dev-notes/feat-multi-server-ports.md`에 커밋 전 테스트 계획과 실행 결과를 기록한다. 테스트 JVM·실제 TCP/UDP 소켓을 사용하며 운영 Minecraft 서버나 실제 마이크·공유기·외부 인터넷 검증으로 간주하지 않는다.
