# fix/agent-session-integrity

- 기준: 게시된 `v0.7.0-beta.16`. 혼자 구현. VERSION·릴리즈 문서·stable main은 수정하지 않는다.
- 운영 iMac 기록에서 도구 JSON으로 대체된 요약, `?`로 바뀐 작업 요청, 잘못된 Luonotar 하위 경로, 초기 Thinking 조각만 남은 봇 대화 기록을 확인했다. 운영 데이터는 변경하지 않았다.
- JSON Schema와 별도 검증을 적용한 압축: goal/constraints/facts/unfinished. 실패 시 원본 유지, 성공 표시 금지. 요약의 사실 정확성을 보장하는 장치는 아니며, 원래 요청·미완료 요구사항·실제 도구 영수증은 별도로 고정한다.
- 기존 메시지 DTO의 native 필드가 JsonIgnore여서 재시작 후 공식 도구 호출/결과가 유실되던 문제: epoch와 대화 SHA-256이 일치할 때만 복원하는 private sidecar 추가. 기존 primary JSON은 이전 버전에서 읽을 수 있다.
- 압축 직전 native 포함 원본을 private transcript에 보관한다. 현재 보관 파일 자동 삭제는 없다. 문맥 reset은 추론 기록·계획을 초기화하며 감사용 압축 전 기록을 삭제하지 않는다.
- 짧은 후속 요청에서 원래 과제·남은 항목·재검증 조건을 유지한다. 삭제 경로가 없을 때 실제 홈의 동명 경로를 오류로 안내하되 자동으로 대상을 바꾸거나 실행하지 않는다. 남은 계획 파일은 완료 처리하지 않는다.
- Discord REST 편집 완료 콜백으로 최종 모델 문장을 참여자 기록에 반영한다. 늦은 최초 메시지 이벤트가 Thinking 조각으로 덮어쓰지 않는다. 편집 이벤트로 모델을 재호출하지 않는다.
- 단위/회귀 검사와 실제 모델 성공은 구분한다. 실제 Qwen3.8 27B 기존 엔진 과제는 531.078초, 압축 8회, 삭제 승인 0회, 네 파일 모두 남음, keep.txt 원문 보존. 실패를 숨기거나 완료로 처리하지 않았다. 이번 수정만으로 도구 수행 품질이 해결됐다고 주장하지 않는다.
- Pi 1.3.0과 OpenCode 1.19.3은 동일 Qwen 27B·8K·Thinking off에서 부분 수정/강제 압축 후 네 파일 삭제를 모두 통과했다. 단일 작은 과제이며 운영 승인 연동은 미검증. 다음 통합 후보는 Kotlin HTTP 구조와 맞는 OpenCode; 이번 기본 엔진 교체는 하지 않는다. Hermes는 일반 비서 후보로 문서만 검토했다. [비교 보고서](../architecture/harness-evaluation-2026-10-21.md) 참조.
- 전체 테스트, 다른 OS, 운영 Discord 전송/재시작은 사용자 지시에 따라 실행하지 않는다.

릴리즈 노트 후보: 압축 원문 보관과 도구 대화 재시작 복원을 추가하고, 짧은 후속 요청에서 미완료 작업을 유지합니다. 잘못된 경로·완료 주장 및 Discord 최종 대화 기록을 보완합니다. 실제 모델의 반복 조회/미실행 문제는 여전히 미해결입니다.
