상태: 해시 재사용·메타데이터 재조회 제거 구현, 선커밋 뒤 검증 예정

# fix/mod-toggle-speed

- 검증된 `fix/mod-start-diagnostics` 기준. MOD 목록 해시는 파일 크기·나노초 mtime·inode·Unix ctime이 모두 같을 때만 메모리에서 재사용한다. ctime/inode 없는 환경은 원래대로 읽고 최근 2초 수정 파일은 저장하지 않는다. 강제 재조회·다이제스트 무결성 API는 제거하지 않는다.
- 토글 트랜잭션 준비는 기존 FileInventory의 강한 stamp 기반 캐시를 사용하며 shape/경로/복구 journal 보호를 유지한다. 토글 뒤 메타데이터는 저장된 출처로만 갱신하고 실패 HTTP 조회를 재시도하지 않는다. 명시적 목록 새로고침은 조회를 유지한다.
- VERIFYING/APPLYING/REFRESHING 진행 메시지를 제공한다.

## 커밋 후 검증 계획

1. 캐시의 변경 없음/동일 크기+mtime 복원/동일 경로 inode 교체/추가·삭제/심볼릭 링크 차단. 최근 수정은 강제로 읽는다.
2. 토글 후 메타데이터 외부 조회 0, 원문 바이트·일반/강제 끄기·재활성화·충돌/실행/진단/stale 보호 회귀.
3. 허용된 로컬 실행기 실제 MOD 폴더에서 읽기 전용 cold/warm 시간과 bytesRead 비교. 운영 MOD 활성 상태는 바꾸지 않는다.
4. 최종 통합 브랜치에서 전체 백엔드·웹 빌드/관련 화면 검증. 배포·릴리즈는 별도 요청 전 미실행.
