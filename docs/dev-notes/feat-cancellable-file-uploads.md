상태: 비동기 업로드·취소·새로고침 복원 구현 중
# feat/cancellable-file-uploads

- 기준 v0.7.0-beta.27. 기존 동기 multipart 업로드가 504 이후에도 파일 예약을 유지해 다음 파일에 409를 내는 문제를 수정한다.
- 브라우저 → 관리웹은 짧은 분할 요청으로 임시 저장. 업로드 완료 접수 후 작업 ID로 실행기 전송·반영 상태 조회. 동일 서버 작업은 순서대로 처리한다.
- 수신 중·대기·실행기 전송 중 취소 가능. 취소는 실행기 임시 쓰기를 중단하고 기존 파일을 보존한다. 원자적 반영 시작 이후에는 취소 불가를 명시하고 실제 결과를 표시한다.
- 인증 계정/인스턴스/업로드 소유권/CSRF/현재 권한 재검사, 크기·디스크·작업 수·경로 제한, 임시 파일 수거, 서버 재시작 후 중단 결과를 유지한다.
- 새로고침: 접수된 백그라운드 작업은 상태 복원. 같은 탭에서 아직 수신 중이던 파일은 취소. 다른 탭 업로드를 임의 취소하지 않는다.
- 파일/모드 공통 업로드에 적용. mrpack 미리보기 같은 별도 기존 업로드는 기존 동작을 유지한다.
- 운영 서버 시작/재시작·릴리즈는 이번 요청에 포함하지 않는다.

## 구현 커밋 후 테스트 계획
1. 실제 RunnerWorkspace를 통한 원격 임시 쓰기·교체·보존과 취소(수신 중/대기/전송/반영 경계).
2. 느린 실행기에도 HTTP 완료 접수는 즉시 반환, 동일 서버 순차 처리·상태·오류 원문 유지.
3. 소유권·다른 서버·뷰어 쓰기·CSRF·권한 회수, 경로 탈출/크기/오프셋/만료, 재기동 중단 상태.
4. 브라우저: 진행률·취소·다중 파일·새로고침 후 서버 작업 복원/수신 중 취소·다른 탭 유지, 모바일 표시.
5. 관련 기존 파일/모드 업로드 회귀와 TS/Vite 빌드. 전체 테스트 생략.

- 실행기 WRITE_COMMIT 응답 전에 전체 서버 복사본을 생성하던 경로를 지연 작업으로 분리했다. 인접 수정은 합치고 재연결 시 로컬 수정 표식으로 미전달 복사본을 재시도한다. 파일 원자적 교체와 보관함은 유지한다.
- 취소는 파일별이며 이미 반영을 시작한 파일은 결과를 기다린다. 원격 응답을 확인할 수 없는 반영 오류에는 실제 파일 확인 필요를 표시한다.

## 1차 검증 및 후속 보완
- TS/Vite 빌드 통과. 브라우저 9개 중 8개 통과(분할 전송/취소·진행 상태 복원·반영 경계·모바일 및 기존 5개). 수신 중 새로고침 시험은 탭 식별자 초기화가 파일 선택 시까지 지연돼 실패하여 페이지 진입 시 준비하도록 수정.
- 새 수신 작업이 이전 페이지 작업으로 잘못 취소되는 경쟁을 막기 위해 문서별 ID도 저장하고, 실제 새로고침으로 복원한 다른 문서의 수신 작업만 취소. 다른 탭·현재 페이지의 새 작업은 유지.
- 백엔드 제품 컴파일/bootJar 통과. 새 테스트의 wildcard import로 JUnit Test가 모호해 컴파일 실패하여 명시 import로 보완.
- 완료 알림을 닫아도 완료 응답을 기다리는 호출자가 결과를 조회할 수 있게 유지(목록만 숨김). 후속 테스트 전 커밋.

- 후속 backend 관련 14개 중 제품·전송·취소 등 13개 통과. 인증 시험의 미로그인 POST에 CSRF가 없어서 정상적인 403이 먼저 반환되는 것을 확인, CSRF를 붙여 순수 로그인 거부(401)를 검증하도록 fixture 보완.
- 브라우저는 앱 초기 비동기 로딩 전에 sessionStorage를 읽던 시험을 초기화 완료까지 기다리도록 보완(로그인/인스턴스 응답이 아직 미완료였음). 후속 실행 전 커밋.
