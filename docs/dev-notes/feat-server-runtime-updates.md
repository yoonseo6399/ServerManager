상태: 기능·공식파일 격리 업데이트·브라우저 검증 완료, 최종 통합 회귀 대기
# feat/server-runtime-updates
- 로그 수정 브랜치에 의존하는 별도 작업 브랜치. 같은 모드로더 종류 안에서 공식 로더 버전 변경과 Minecraft 업그레이드를 제공한다. Minecraft 다운그레이드는 거부한다.
- 서버 설정의 버전 선택/중앙 확인 모달, 종료·전송 완료 게이트, 비동기 단계·설치 로그·백업 위치·실패 표시.
- 설치기는 원본 월드가 없는 별도 폴더에서만 실행한다. 허용한 런타임 파일·라이브러리만 원본에 반영하고 월드·mods·config·KubeJS는 제외한다. 기존 JVM 사용자 인자는 유지한다. 반영 실패 시 기존 실행 파일을 복구하고 트랜잭션 기록을 남긴다.
- 선택된 실행기에서 설치하며 RUNTIME_UPDATE_V1 연결 기능이 필요하다. 진행 중인 실행기 런타임 변경은 시작·다른 파일 수정·제어 계층 자동 업데이트를 차단한다. 사용자 지정 JAR 이름은 새 공식 JAR를 같은 등록 이름으로 반영한다.
- 모드 자동 업데이트/호환성 자동 보장, 실제 월드 데이터 변환·변경 후 자동 월드 롤백은 제공하지 않는다. UI에서 월드 백업과 모드 호환성 확인을 안내한다.
- 선커밋 후 검증 계획: 런타임 파일만 반영/월드·모드·설정·JVM 인자 보존, 중간 반영 실패 복구, Minecraft 다운그레이드·동일 버전 거부, 사용자 지정 JAR, 비동기 설치 실패·상태, 확인 모달·진행 로그·실행 중 비활성화 및 기존 로그 브라우저 회귀. 운영 서버의 실제 버전은 변경하지 않는다.

## 검증 결과
- RuntimeUpdateTest 6개: 사용자 데이터/JVM인자 보존, 중간 반영 실패 복구, 사용자 지정 JAR, 다운그레이드·동일 버전 차단, 비동기 실패, 링크 거부 통과.
- RUN_REAL_RUNTIME_UPDATE=true 격리 검증에서 공식 Mojang Minecraft1.21.2 서버 JAR를 실제 다운로드·공식해시 검증하고 실행기 Workspace 작업을 통해 1.21.1에서 교체했다. 원래 server.jar 백업과 world/level.dat 바이트 보존 통과. Minecraft 프로세스는 띄우지 않았다.
- UI3개: 버전 변경 확인 전 미전송, 진행 로그·백업, MC별 로더 카탈로그/취소, 실행 중 차단 통과. 처음 실패는 실제 메뉴명/메모리 API 필드를 빠뜨린 fixture로 확인하고 수정했다.
- 로그 후속 회귀/조회자별 검색 소유권/실행기 읽기 전용 테스트 통과. TS/Vite 성공.
- 실제 NeoForge/Forge/Fabric/Paper 버전 변경, 실제 월드 로드·모드 호환성, 다른 OS는 미실행. 기존 공식 설치기를 재사용하며 운영 인스턴스·서비스 버전은 변경하지 않았다.
