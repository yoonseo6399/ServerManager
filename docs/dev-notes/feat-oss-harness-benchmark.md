# feat/oss-harness-benchmark

- 사용자 결정: 커스텀 모델 실행 루프·계획/압축 하네스를 폐기하고 오픈소스로 대체한다. 먼저 Hermes까지 실제 비교한다. 기존 인가·파일 경로 검사·명시적 승인 등 backend 보안 경계는 엔진 교체와 별개다.
- 기준 소스: v0.7.0-beta.16. benchmark fixture의 repo/는 해당 커밋의 공개 소스만 git archive한 읽기 전용 스냅샷이다. 운영 파일/봇/서버는 연결하지 않는다.
- 같은 도구와 사용자 과제: 코드 부분 수정, 계획 후 승인/실행, 실제 저장소 조사, Python 중앙 정렬 별, 원문 합치기 후 확인/삭제, 애매한 텍스트 선택, 내용 기준 텍스트 선택, 정정/취소 정보의 압축 후 기억. 결과는 모델의 성공 주장과 분리해 실제 바이트·실행·삭제 범위·사실별로 검사한다.
- 공식 Hermes v0.22.2 d923a5e, 전용 Python3.14.8 소스 설치. 최소 64000 컨텍스트를 강제한다. 8K에서 추론 전 거부됨. floor를 패치하지 않는다.
- Qwen3.8 27B 64K 짧은 로딩/응답은 성공했지만 압력4였다. 해제 후 압력1 회복. 이후 사용자는 27B로 가능한 범위까지 세 엔진을 64K에서 비교하도록 지정했다. 본 과제 비교는 아직 시작하지 않았다. Gemma4 12B 64K 짧은 응답은 압력1이었다.
- 공식 Hermes 도구 등록의 tools.tool_search.enabled=off 지원 설정으로 동일 7개 도구 schema를 직접 제공한다. 엔진 소스/압축/실행 루프는 수정하지 않는다. 초기 설치/설정/시험 sandbox 오류는 과제 성능과 구분해 원시 기록을 남긴다.
- Pi1.3.0 SDK, OpenCode1.19.3 서버를 고정한다. 외부 설정/확장/cloud 인증 없이 임시 디렉터리에서만 실행. 공통 Python 실행 도구는 network 차단, 다른 사용자/임시 작업 읽기 및 프로젝트 밖 쓰기를 macOS sandbox로 거부한다. 원문 CRLF 보존·정상 실행·외부 읽기/쓰기 거부 검사가 통과했다.
- 전체 회귀, 다른 OS, 운영 Discord·설치판 연결, 엔진 교체 구현은 아직 미실행이다. VERSION/릴리즈 문서는 건드리지 않는다.

## 재개 지점

- 사용자 최신 지시: 모델을 로딩하지 않은 상태의 메모리와 디자인 앱 실행 여부를 먼저 확인하고, 디자인 앱 사용 중에는 작업을 미룬다. 조건에 해당해 모델 시험을 대기했다. 자동 재개/예약은 만들지 않았다. 로딩 모델 0 확인.
- 원시 준비 기록은 `/private/tmp/sm-oss-*`에 있다. 27B64K 짧은 응답 51.51초, 실제 window65536, pressure4. 작업 품질 벤치마크 결과가 아니다.
- Hermes 최소64K 거부, tool_search 기본 wrapper로 인해 어댑터의 eager-schema 검사가 실패한 초기 시도는 준비 오류로 구분했다. 공식 `tools.tool_search.enabled: off`로 7개 공통 도구 직접 등록을 확인했다. 소스 루프/압축은 수정하지 않았다.
- Gemma64K 준비 시험에서는 Hermes 파일 합치기의 실제 원문 바이트가 불일치했다. 이 결과는 보존하며 프롬프트로 정답을 유도하지 않는다. 압축 호출도 실행됐다. 기억 평가기에는 취소 작업의 JSON 타입(문자열/배열)을 명세로 명확히 정하거나 의미 채점을 추가해야 한다. 타입 차이를 곧바로 기억 상실로 보고하면 안 된다. 압축 전후 문자 수와 실제 요약/유효 입력 감소도 별도로 확인할 것.
- 다음: adapter 준비를 마무리한 뒤 27B64K 공통 8과제를 실제 실행. 매 과제 시작 전 디자인 앱 상태 확인, 사용자 작업 중에는 중단/대기. 실제 결과·원문·실패·미실행을 분리한다. 선정 뒤 별도 브랜치에서 기존 커스텀 추론/압축 루프를 오픈소스로 교체하며 기존 인가/승인 경계는 유지한다.


## 2026-10-21 재개 및 비교 방법 보완

- Illustrator가 열려 있지만 시험을 진행하라는 사용자 승인을 받았다. 이전 앱 대기 조건은 이번 시험에 적용하지 않는다.
- 기본 캐시 27B64K의 Hermes 코드 수정은 600초 내 미완료. 원문/CRLF는 유지했으나 버그 검증 실패, 실제 Python 검증 실행도 없었다. 원시 자료: `/private/tmp/sm-oss-qwen27-64k-20261021`.
- 운영 Ollama를 바꾸지 않고 별도 localhost11435 Ollama에 같은 GGUF를 재사용했다. Flash Attention과 Q8 KV의 실제 적용을 서버 로그에서 확인했다. 64K 모델 할당 약21.94GB→19.94GB. 3토큰 짧은 준비 응답은 약18tok/s였으나 일반 작업 성능으로 해석하지 않는다. wired_limit_mb20480 유지.
- Q8 공통 도구 코드 과제: Hermes398.81초 실패, Pi600.12초 실패. LF/CRLF exact-find 실패를 반복했으며 실제 파일로 실패를 판정했다. OpenCode 결과는 진행 중이다. 결과/실패를 삭제하거나 정답에 맞춰 프롬프트를 수정하지 않는다.
- 공통 도구 방식은 upstream 편집기 자체의 CRLF 처리 등을 측정하지 못한다. 따라서 별도 upstream-native 트랙을 추가한다. 공통 결과와 합산하지 않고 native 트랙에서 같은 8과제를 비교한다. 세 엔진의 실행 루프·압축 구현은 수정하지 않는다. 도구 이름/개수와 기본 프롬프트는 엔진별로 다르다.
- native SDK/import/OpenCode --version과 격리 검증 통과: 허용 폴더 쓰기, 외부 사용자·임시 파일 읽기 거부, 저장소 쓰기 거부, 외부 인터넷 거부, 로컬 시험 API 접근, 민감 인증 환경변수 비상속. `/private/tmp/sm-native-isolation-probe/results.json`. 첫 SBPL 주소 문법 오류는 준비 오류로 수정 후 재검증했다.
- native 이벤트 연결/구문 검증 완료. shell에서 여러 동작을 한 번에 실행할 수 있으므로 read-before-delete·두 Python 예제 실행·소스 근거는 수동 감사를 별도로 표시한다. 기존 instrument 도구 이벤트를 허위로 만들어 통과시키지 않는다.
- 다음: 공통 코드 과제 세 엔진 완료 경계에서 종료 → native 8과제 직렬 실행 → 실제 바이트/실행/기억 및 압축 토큰을 비교 → 선정 및 런타임 교체. 아직 대체 엔진 선정·제품 교체·릴리즈는 완료하지 않았다.
