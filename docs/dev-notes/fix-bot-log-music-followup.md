# 봇 로그·음악·모듈 후속 점검

- 게시된 Beta 11 `d13d101` 기준 별도 워크트리, 단독 작업. 전체 테스트와 다른 OS 검증 생략.
- 사용자 정정: 단순 구현 버그는 수정하되, 파인튜닝·별도 하네스 연구 수준의 LLM 한계는 무리한 규칙 추가 없이 증거와 함께 보고.
- 음악 종료 조건 확정: 봇의 현재 음성 채널에 **사람이 연속 60초 없으면** 재생·대기열을 정리하고 퇴장. 다른 봇은 사람으로 세지 않으며 사람이 돌아오거나 채널이 바뀌면 시간 초기화.
- 관리 iMac의 Beta 11 앱과 저장된 실제 대화·계획·프로필·앱 로그를 SSH로 확인했다. 운영 원문은 비공개 ignored 폴더에만 보존. 모델이 추가 run_command 도구를 선택하지 않고 sh로 Python 실행을 요청하는 문제와 요구사항 중복 6개를 확인했다.
- 직접 실측: 30B/8K는 로딩 중 압력 임계 4로 약 15초에 중단(모델 해제 뒤 별도 검사에서 정상 1 복귀). 14B/8K는 정상 압력에서 같은 도구 선택 실패 재현, 실행 0회·합친 파일 미생성·두 원본 보존. 도구 선택 설계/모델 능력 구분에 추가 연구가 필요하며 사용자 지시에 따라 규칙·권한 완화·프롬프트 덧붙이기는 하지 않았다. 파인튜닝 필요나 모델 자체 결함으로 단정하지 않는다.
- 짧은 비목록 요청을 파일 이름 유무에 관계없이 원문 하나로 보존하도록 명확한 구현 버그만 수정했다. 관련 회귀에 운영 요청 문구를 추가했다.
- 사용자 선택대로 현재 모듈 구조까지만 보완: Minecraft 실제 기능 소유권 이동, 실행 직전 최신 역할·활성 상태 검사, 모듈별 관리 웹 설정/저장/진입 차단, 에이전트 취소, 음성 이벤트 수명 관리. 별도 프로세스/API/설치/서명 분리는 제외.
- 기능 묶음 108개 중 opt-in 2개 생략 후 통과. 추가 관리자 API·모듈·서버 제어 18개 통과(중복 포함). React 빌드·모듈 설정 Playwright 1개 통과. 전체 스위트·다른 OS·실제 Discord 음성은 미실행.
- 보고: docs/testing/beta12-followup.md, docs/architecture/implementation-status.md. 릴리즈 파일은 통합 브랜치에서만 작성하며 음악·모듈 수정과 LLM 미해결을 분명히 구분할 것.
