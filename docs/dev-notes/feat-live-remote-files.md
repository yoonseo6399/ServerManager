# feat/live-remote-files
온라인 실행기는 파일·모드·로그 원본의 권한 주체이며 중앙 복구본을 편집하지 않는다. 새 기능 지원을 협상하지 않은 구형 실행기는 변경을 거절하고 업데이트를 안내한다. 실행/전송 상태만으로 원격 파일 변경을 막지 않고 서버 루트·링크·revision·복구 보관함을 유지한다. Modrinth 메타데이터 조회는 중앙에서 수행하되 JAR 목록과 rename은 실행기에서 한다. 로컬 격리 진단은 별도의 정지 조건을 유지한다.

종료 복사본: 원본이 멈췄을 때만 APFS COW(실패 시 일반 복사)를 만들고 snapshot-ready를 접수한 뒤 같은 실행기에서 재시작한다. 네트워크 전송은 원본 잠금을 보유하지 않고 사설 복사본만 읽는다. 순서·run token·완료 영수증·별도 상태로 이전 전송 완료가 새 게임 lease/PID를 바꾸지 않게 한다. 새 실행기로 이동/중앙 편집은 최신 복구본 접수까지 대기한다. 파일별 병렬 업로드와 commit 배타 잠금으로 기존 4개 클라이언트 전송이 서버에서 직렬화되던 병목을 제거한다.

## 커밋 후 실행할 테스트
- 실제 파일을 변경해도 종료 복사본 내용이 바뀌지 않음, 큐 재시작 복구, 링크/부분 복사 거절.
- live 파일 READ/EDIT 및 MOD_SCAN/MOD_TOGGLE 실행·전송 상태에서 동작, revision 불일치·경로 탈출·중복 이름 거절, 원문/백업 보존.
- 새 run 시작 후 이전 snapshot commit/ready 재전달이 새 state/PID/lease에 영향 없음, 잘못된 token/다른 실행기/역순 전송 거절, 여러 종료 큐 순서.
- 여러 파일 병렬 전송 및 같은 파일 offset 충돌·commit 경합; 기존 전송/폴더 가져오기 회귀.
- 웹 실행/전송 중 파일·모드 버튼 및 적용 안내, 읽기 전용 계정 차단. frontend build와 최종 통합 전체 backend.
- 실제 운영 서버 시작/종료·파일 변경 및 다른 OS 시험은 수행하지 않음.
